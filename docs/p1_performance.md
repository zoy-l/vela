# P1 性能与验证记录

记录日期：2026-10-25。实现契约见 [P1 语法与契约](p1_syntax_proposal.md)，可运行代码见 [examples](../examples/)。

## 验证结果

最终 Windows x64 代码通过 Debug / Release 各 **507** 项 GoogleTest。28 个示例通过静态检查，26 个包含 main 的示例实际执行成功。全仓库 clang-tidy 扫描后，按变更路径复查修复项；最终诊断为零，未修改规则或添加 NOLINT。编码边界、构造顺序、闭包共享捕获、接口调用、泛型展开边界、错误分支、Unicode 和 GC 压力均包含回归覆盖。

完整基准实际运行 87 个案例、每例三次，共 609 行原始测量及聚合结果，错误数为 0。执行案例逐次核对运行状态和预期返回值。原始文件保存在本工作区：

- `.cache/p1-before.json`：修改前的 63 个案例。
- `.cache/p1-delivery.json`、`.cache/p1-delivery.log`：最终完整结果。
- `.cache/p1-debug-final.log`、`.cache/p1-release-final.log`：最终测试结果。
- `.cache/p1-examples-release.log`：示例检查和执行记录。

## 测量边界

使用仓库固定的 Clang、Release 配置和 Google Benchmark，在同一台 24 逻辑处理器的 Windows x64 机器上测量。下表为每个完整负载的墙钟耗时中位数，单位均为 **微秒（µs）**；1 µs = 1000 ns。

`compile` 包含编译、优化、寄存器分配、校验及 Isolate/程序销毁，不含源文件读取。`first_execute` 每次创建新程序和 VM，编译、设置、销毁暂停计时。`vm` 在相同 Isolate/VM 中反复运行，包含实际分配和自动 GC。计时期间没有并行运行构建、测试或 lint。

```powershell
python -m tools.vl bench -- --benchmark_min_time=0.1s --benchmark_repetitions=3 --benchmark_out=.cache/p1-delivery.json --benchmark_out_format=json
```

短负载仍受调度、频率和代码布局影响。完整运行曾出现字符串组明显变慢，而同一二进制的定向复测恢复到先前区间；因此同时保留完整结果与专项复测，不将某次最快结果当作全局性能保证。基准没有测量峰值 RSS、编译器全部原生分配或 GC 最长暂停时间。

## 内存

| 负载 | 首次执行后 GC 分配字节 | 首次执行后 GC 提交字节 | 最终回收后保留字节 | VM 寄存器字节 |
| --- | ---: | ---: | ---: | ---: |
| `numeric_conversions` | 0 | 0 | 0 | 48 |
| `closure_calls` | 128 | 128 | 0 | 112 |
| `expected_results` | 64000 | 64000 | 0 | 64 |
| `unicode_graphemes` | 57728 | 65536 | 128 | 96 |
| `set_membership` | 32896 | 32896 | 0 | 80 |
| `map_lookup` | 41088 | 41088 | 0 | 80 |
| `interface_calls` | 64 | 64 | 0 | 144 |
| `match_dispatch` | 0 | 0 | 0 | 96 |

首次状态包含编译程序持有的常量，以及执行结束但尚未回收的对象；不是累计分配量或峰值。提交字节包含 GC 分配器缓存，不代表进程 RSS。最终保留量在结束当前增量周期并执行新一轮完整回收后读取；Unicode 的保留量来自程序仍保根的字符串常量。布局、C++ 容器、VM 固定元数据及临时原生缓冲不在 GC 字节计数内。

数值转换不分配 GC 对象。Expected 当前每次构造分配一个带单一有效载荷槽位的对象。闭包、共享可变捕获单元及绑定方法也会分配；不宣称无分配。Set / Map 的外部连续存储计入 GC 分配压力并随对象回收，扩容时短暂同时持有新旧缓冲。

全部原有 VM 负载的寄存器容量与基线相同。全程序的布局表只保存一份并由函数共享，避免把相同元数据复制到每个函数；原生加载入口也复用相同借用表的快照。

## 实测后完成的调整

数组与集合共用类型存储操作，但数组读写不再为了构造视图而每次调用元素大小计算，存储操作与数组访问放在同一编译单元供优化器内联。初始完整运行的数组遍历为 452.976 µs、数组分配为 251.501 µs；五次定向测量分别降至 422.849 µs、228.560 µs。`.cache/p1-arrays-tuned.json` 使用 0.2 秒、五次测量，设置与完整表不同。

内建分派合并为一个生产入口，移除了旧字符串入口与多余的跨文件转发。同样使用 0.2 秒、五次测量的前后专项比较：

| 负载 | 合并前 µs | 合并后 µs |
| --- | ---: | ---: |
| string_builder | 17.42 | 15.17 |
| string_builder_large | 133.54 | 124.36 |
| string_join | 80.50 | 72.83 |
| string_unicode | 221.13 | 198.86 |

专项原始数据为 `.cache/p1-string-confirm.json` 和 `.cache/p1-string-tuned.json`。表中数值按专项结果四舍五入；完整最终表使用上面的三次全量测量，没有用专项数据替换较慢项目。

参数名绑定、字段偏移和 lambda 编号在编译时建立索引。接口分派只给被引用的方法分配 selector，建立类布局时只遍历实际实现的接口。未使用的 300 个接口不会耗尽后续实际调用的 8 位 selector，该行为已有执行测试。显式帧调用、泛型专门化和精确 GC 贯穿这些路径，没有解释 AST 或保留旧实现作为回退。

## 当前限制

泛型函数与类模板按具体类型专门化，最多展开 256 个实例；类型嵌套上限为 128。字节码的寄存器、池索引、直接调用和跳转仍受现有编码限制，超限产生诊断；详见 [VM 契约](vm_execution.md)。数组固定长度，集合快照会分配新数组。match 不支持解构、guard 或 double 常量模式。

GC 对数组、集合等大对象的扫描仍按对象计工作量；单个大对象的扫描不是可按条目抢占的，不能保证硬暂停上限。当前结果仅验证本机 Windows Debug / Release，未声称已经验证其他平台或与 Luau、Dart、JS 完成跨语言性能比较。
