# 细粒度响应式设计

> 状态：待实现。

Vela 在声明上启用响应式读写。字段和变量保留原类型，`Reactive.update` 划定写入与合批范围。
引用值沿用自身的读写契约。发布稳定的集合数据时，调用方显式构造不可变快照。
宿主为每个动态属性单独收集读依赖。共享派生值用 `Computed` 缓存，值变化后的副作用用 `Reactive.watch`。

```vela
[Reactive]
class Vitals {
  hp: int = 100;
  shield: int = 25;
}

class HudModel {

  #vitals: Vitals = Reactive(Vitals());
  #hitCount: int = Reactive(0);


  hpLabel(): string {
    return 'HP: ${this.#vitals.hp}';
  }

  shieldLabel(): string {
    return 'Shield: ${this.#vitals.shield}';
  }

  takeDamage(amount: int): void {
    Reactive.update(() => {
      this.#vitals.hp -= amount;
      this.#hitCount += 1;
    });
  }
}
```

两段文字分别求值时都会订阅 `vitals` 引用槽，各自再订阅当前实例的 `hp` 或 `shield` 字段。
一次伤害改变 `hp` 时，只有生命值文字需要重新求值。替换 `vitals` 会使两段文字重新求值，
并将字段订阅移到新实例。

## 1. 声明和类型

`Reactive` 是标准环境中的 `Attribute` 子类，沿用 `Reflect` 同时提供特性和静态 API 的形式。
前端按解析后的标准类型身份识别特性、初始化标记和静态入口。同名声明沿用现有名称解析规则。
[源码特性契约](reflection.md#14-源码特性与反射登记)

| 写法 | 响应式存储 |
| --- | --- |
| `[Reactive] class Vitals { ... }` | 本类声明的每个可写实例字段分别拥有依赖身份。继承字段沿用其声明处的规则。 |
| `[Reactive] #hp: int = 100;` | 只追踪这个实例字段。 |
| `#hp: int = Reactive(100);` | 与同一字段上的 `[Reactive]` 等价。 |
| `let count = Reactive(0);` | 声明一个类型为 `int` 的响应式局部变量。每次执行声明创建独立的存储身份。 |

首版接纳脚本类的实例字段和函数内的可变 `let`。标准 `Reactive(initial)` 接受单个位置实参，
作为受支持声明的整个初始化器。用于普通实参、返回值、后续赋值、`const`、全局变量或静态字段时给出编译诊断。
特性目标限于脚本类与其实例字段。

初值表达式接受原声明的预期类型，只求值一次。对自动构造的公开字段，命名构造实参仍可替换默认初值。
字段的响应式规则由声明决定，因此 `Vitals(hp: 40)` 中的 `hp` 仍然响应式。类级、字段级与初始化标记
归一为同一份存储语义。首次初始化沿用已有的声明和构造顺序，直接建立初值。
[核心语言的构造模型](core_language.md#按字段生成的类构造模型)

引用槽跟踪引用替换。`model: A = Reactive(A(a: 1, b: 2))` 保留类型 `A` 及原有引用语义。
需要独立追踪 `a` 和 `b` 时，在 `A` 上使用类级标注，或逐个标注字段。
普通脚本对象和宿主句柄也可放入引用槽，订阅者会在引用替换时重新求值。

## 2. 读取、写入与合批

实例字段的依赖键由当前 Isolate 中的对象身份和字段声明身份组成。同一对象的不同引用解析到同一个键，
不同实例的同名字段各有自己的键。局部变量用绑定本次执行的存储身份，闭包共享已有捕获单元。
同一份存储承载读写和 GC 扫描，跟踪元数据只记录身份和订阅关系。

读取发生在收集作用域内时登记依赖。复合赋值与自增先按原语言语义读取旧值，再执行受控写入，
接收者和索引保持原有的求值次数。响应式字段经由普通调用、动态成员、反射或宿主句柄修改时，
统一遵循响应式写入约束。调试器的诊断性读取在非收集作用域执行。

标准 `Reactive` 提供静态入口 `update(work: () => void): void`。回调同步执行，正常写入即时可读。
响应式槽的首次初始化由初始化入口处理。后续写入该槽要求当前 Isolate 内存在活跃的更新作用域。
越过写入边界时，在改变存储之前报告可捕获的 Vela 错误。宿主主动更新也进入同一个作用域。
同步被调函数沿用当前作用域，异步续延恢复后需要自己的 `Reactive.update`。

成功的变更进入当前批次的待通知集合。字符串按内容比较，引用按身份，动态值先区分实际种类。
`double` 按存储位模式比较，以区分可观察的正负零。相同值的槽写入跳过通知。
同一源在批内反复修改时只登记一次，包括改回原值。同一订阅者依赖多个已变源时也只排队一次。
嵌套更新由最外层退出统一发布失效。回调抛错时仍发布已经完成的写入，并原样传播错误。
绑定求值由宿主在同步调用退出后调度。 [异常处理契约](exceptions.md)

## 3. 引用与集合快照

`T[]`、`Set<T>` 和 `Map<K, V>` 保留既有可变语义。通过响应式槽持有它们时，
写入限制和失效通知只作用于槽的重新赋值。原有别名在赋值前、持有期间和替换后都可按原规则修改容器。
列表需要观察这些数据变动时，存储并发布新的不可变快照。

```vela
class Inventory {
  items: FrozenArray<int> = Reactive(FrozenArray<int>.from([]));
}

func publishItems(inventory: Inventory, draft: int[]): void {
  const snapshot = FrozenArray<int>.from(draft);
  Reactive.update(() => {
    inventory.items = snapshot;
  });
}
```

`FrozenArray<T>.from(T[])`、`FrozenSet<T>.from(Set<T>)` 和 `FrozenMap<K, V>.from(Map<K, V>)`
显式创建独立的只读值。构造时复制容器内容一次，复用既有集合的存储、元素顺序及键比较规则。
源容器的所有别名继续引用原容器。快照提供长度或大小、读取、查找和遍历。
动态值、反射和宿主访问也遵循快照的只读类型契约，转回可变集合需要显式复制。
创建失败时，源容器与已发布快照保持有效。

快照的元素、键和值首版只允许基本值、枚举、字符串、符合相同约束的快照及其可空形式。
引用仍可表示不可变数据，例如 `string` 和嵌套快照。普通类实例、响应式类实例、可变集合、
`dynamic`、闭包、Future 和宿主资源都缺少这份静态不可变保证。需要它们参与集合内容时，先投影为 ID、
可发布的字段值或其他不可变数据。类自身的响应式字段仍可通过 `Reactive.update` 独立修改。

快照发布成本随容器长度增长，适合先批量编辑、再一次发布。列表观察槽替换，用业务 key 更新变化的行。
需要频繁原地编辑的大型集合，由业务模型提供对应的增量编辑与订阅入口。
[强类型数组](arrays.md) · [有序 Set 与 Map](core_language.md#有序-set-与-map)

## 4. Computed 与 watch

普通 getter 适合简短的派生表达式。多个绑定复用同一计算，或计算开销值得缓存时，使用
`Computed<T>(compute: () => T): () => T`。调用返回的函数即可读值。

```vela
func watchLowHealth(vitals: Vitals, onChanged: (bool, bool) => void): WatchSubscription {
  const isLowHealth = Computed(() => vitals.hp < 25);
  return Reactive.watch(isLowHealth, onChanged);
}
```

`Computed` 在首次读取时求值、收集自身依赖并缓存结果。读取它的绑定订阅派生结果。
上游写入即时使相关派生缓存过期。有活跃消费者的派生值在通知下游前按依赖顺序求值，
其余派生值在下一次读取时求值。每次求值按实际分支替换读集。
事务内显式读取时取得当前结果。对下游发布时，按第 2 节比较最后一次已发布结果和最终结果。
成功值相等时保留下游已有输出。求值错误通过读取传播，输入变化后可重试。
同步递归读取一个计算中的派生值时，报告循环依赖错误。

`Reactive.watch<T>(read: () => T, onChanged: (T, T) => void): WatchSubscription`
在注册时求值并订阅读集。初次成功读取建立基准，初次失败将错误交给调用者。
后续在 Isolate 调度点读取合批后的值，按第 2 节比较，并在变化时将新值和上一次成功读到的值传给回调。
调度方每轮合并同一监听的通知，更新基准后再调用回调。回调中的读取独立于该订阅，
回调可通过 `Reactive.update` 写入，使后续调度轮次处理新批次。
后续读函数抛错时保留上次成功值和本次读到的依赖，向调度方报告错误。回调抛错沿用同一错误通道。
调用 `dispose()` 解除订阅并取消排队的通知。

文字、进度值和列表等声明绑定自行订阅。持久化、音效等在值变化后执行的操作由 `watch` 承担。
派生函数与监听读函数沿用绑定求值的同步读作用域。

## 5. 绑定求值与生命周期

响应式上下文归属 Isolate，在它的执行线程访问。宿主持有按挂载生命周期管理的订阅者，用已有的类型化入口
调用求值函数。普通方法和 getter 可以表达派生计算，其内部读取归入当前订阅者的读集。
重复读取去重，分支变化后用当次读集替换旧读集。求值抛错时，宿主保留最后成功提交的属性值，并使用
失败前收集到的依赖安排重试。进入 `Reactive.update` 前检查当前是否在收集依赖，收集期尝试更新时报告错误。

失效队列只交付订阅者身份，由宿主决定何时刷新以及如何消费结果。一个文字属性、一个进度值或一个列表
各有自己的求值范围。文字求值后更新挂载节点的对应属性。文字度量变化时，宿主布局处理受影响的区域，
父组件的构建输出可继续复用。列表求值后把变更交给列表自己的结构更新。
Vela 的公共契约停在订阅、求值和失效交付，节点、布局、绘制与视图调度由宿主实现。

卸载时解除绑定和挂载拥有的 `watch`，撤销已排队的更新。独立脚本监听由调用方持有并释放。
派生值的缓存归返回的函数持有。依赖索引按身份关联源与订阅者，GC 回收后解除对应关联，
地址复用时新旧身份保持可区分。求值函数和缓存值沿用既有 GC 保根契约，
关闭 Isolate 时先收回参与执行的订阅与待处理通知。
[GC 与写屏障](garbage_collection.md#写屏障与字段更新契约) · [宿主句柄](cpp_interop.md#5-句柄根与借用期限)

## 6. 编译、优化和热重载

1. 前端在绑定声明时解析 `[Reactive]` 和 `Reactive(initial)`，将有效标记记录在声明及语义模型上。
   局部推导、泛型特化、捕获、初始化分析和源码工具复用同一事实。
2. Typed IR 保留可观测读、受控写入与更新作用域的效果。AOT 和 JIT 基线与优化层共享 lowering。
   优化必须保留依赖记录、成功写入顺序和异常边。优化帧恢复继续执行当前操作，已完成写入的通知只登记一次。
   普通字段保持直接读写，响应式存储复用现有字段布局和写屏障。
3. 原生映像和编译缓存身份覆盖响应式元数据及其执行契约。反射与宿主生成代码使用相同的字段身份和写入入口，
   诊断和源码工具保留原声明位置。 [原生编译缓存](compilation_cache.md)
4. 前端在集合具体化时校验快照元素类型，动态访问和宿主解码按实际快照类型执行。
   JIT 与 AOT 连到同一个 Isolate 运行时，复用快照构造、派生求值状态及订阅调度。

热重载保留兼容的实例、槽值和字段声明身份。现有字段的响应式资格变化要求完整 Reload。
兼容的新增字段按原有规则初始化，新建的局部槽按新代码执行。旧闭包遵循现有函数版本契约。
接受新的发布版本后，宿主通过挂载生命周期换绑受影响的求值入口和监听并重新收集依赖。
跨挂载保留的脚本闭包继续按其捕获版本执行。候选失败时继续消费已发布版本。
发布在既有安全点协调，等待活跃更新作用域退出。 [热重载身份与版本](hot_reload.md#5-身份版本与代码所有权)

## 7. 完成条件

- 同一脚本在开发 JIT 和封闭 AOT 下验证字段级及类级标注、`Reactive(0)` 类型推导、
  命名构造覆盖默认值、局部捕获、不同实例隔离和写入边界。
- 验证两个独立绑定分别读取 `a`、`b`。更新 `a` 时只执行其订阅，替换对象时重新追踪字段，
  并覆盖条件分支换依赖、相同值写入、嵌套更新、异常退出及卸载后的队列清理。
- 验证普通数组、Set、Map 的别名在写入响应式槽前、期间及替换后均保留写入权限。
  快照保留内容和顺序，源容器修改后已发布值保持稳定。验证静态类型约束及动态、反射和宿主的只读边界。
- 验证多个绑定共享同一次派生求值、结果相同抑制下游通知、批内读到最新值、派生分支或链条变化、
  循环依赖诊断，以及 `watch` 的合批、首次注册、抛错和释放行为。
- 用真实嵌入宿主验证状态更新到节点属性的链路，检查相邻绑定和父构建的执行次数。
  热重载保留已有值并重新绑定新求值代码，AOT 宿主从同一 SDK 的运行时完成订阅和通知。
- Release 性能验证分别测量普通字段读写、响应式读写和实际叶节点更新。
  比较使用相同的输入、负载和输出。批次工作随实际变更源与命中订阅增长。
