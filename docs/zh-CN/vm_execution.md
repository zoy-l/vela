# 虚拟机执行契约与测量报告

[English](../en/vm_execution.md) | [**简体中文**](vm_execution.md)

本报告记录了 2026-10-24 在 Windows x64 上使用仓库内置的 Clang Release 工具链测量的编译器与 VM 执行重构结果。该工作承接自[基础语言里程碑](language_basics.md)。

## 调查发现

编码器在截断前检查寄存器、有符号立即数和跳转偏移量。常量池、调用目标、选择器和字段索引超出紧凑操作数时，使用一个索引扩展前缀，得到完整的 uint32 索引，无需限制整个程序只能有 256 个泛型特化。跳转目标、异常处理范围和源码映射统一转换为最终字偏移；程序加载校验拒绝缺失或位置错误的前缀，以及跳入扩展指令内部的控制流。

其余调查项均转化为具体的重构行动：虚拟寄存器无复用持续累积的问题已解决；执行前重复校验所有函数并分配最大尺寸寄存器文件的问题已修复；常量折叠对紧邻生产者的依赖已消除；合并了需要手动维护映射且带有静默 `LoadNull` 回退的双套操作码枚举。

## 编译流程与寄存器分配

当前的生产编译管线为：

```text
受查 AST -> Typed IR -> 基本块局部常量传播
        -> 不可达块与死值消除
        -> CFG 活跃性分析 -> 物理寄存器分配
        -> 受查编码 -> 持有所有权且校验通过的 Program -> 虚拟机执行
```

中间表示（IR）中的虚拟寄存器 ID 为 32 位。反向活跃性分析使用前驱工作表（predecessor worklist）。死值消除在状态传递时剔除无副作用的废弃纯定义，包括跨基本块边界的消除。常量折叠追踪各个基本块内通过定义和 move 传递的整数、布尔值及 null 常量；推导事实不跨越基本块边界。已知分支被就地简化。执行失败的算术运算、索引读取、函数调用、内存分配及字段写入即使其计算结果未被使用，其副作用依然被严格保留。计算生成超出当前立即数范围的整数会保留其算术指令：`20000 + 20000` 依然正确计算并返回 `40000`。

字节码寄存器分配器采用保守活跃区间与线性扫描算法。在每条指令中，读取阶段位于写入阶段之前，允许生命周期在此结束的输入物理槽位与计算结果槽位合并复用。函数参数槽位保持固定。函数调用、内置函数及字符串插值参数保持连续的参数窗口。删除冗余指令时会自动重映射跳转目标；寄存器分配还会消除无意义的自移动（self-move）。

该分配器不包含内存溢出换出（spill）或活跃区间切分。保守区间分析与连续参数窗口碎片可能导致物理槽位超限（即使理论最优分配方案可以容纳）。超出上限时会在对应源码位置精确报告编译诊断。共享 IR 优化器已实现跳转串接、基本块内复制传播与冗余 move 消除；完整的 SSA 传播和最优图着色不在当前字节码实现中。

IR 与 VM 统一复用 `base/opcode.h` 中的单套操作码枚举。旧的操作码转换 switch 及其 `LoadNull` 回退已被彻底移除。IR 操作数与运行时操作数仍具有不同的数据契约；编码器负责完成精确的格式转换。

## 程序所有权与镜像校验

`vm::Program::Create` 接收可变构建器存储的所有权，执行严密校验，随后发布共享的不可变程序存储。构建器在移交所有权时必须放弃其可变别名。`Program::Load` 在校验前深拷贝借用的裸 `vm::Function` 输入。在注册稳定的根区间前先拷贝字符串指针，确保在增量 GC 回收期间注册常量池能够准确观察到所有存活引用。

校验器严密核验函数的寄存器/参数数量、操作码操作数、常量池引用、参数窗口、相对跳转目标以及末尾控制流穿透。即使是不可能被执行的不可达指令，也必须在结构上完全合法。动态值与堆布局依然保留运行时的类型、字段、越界、算术溢出及内存分配检查；结构校验不能取代运行时的安全受查机制。

`FunctionHandle` 保持对程序、字节码、元数据及保根字符串常量池的引用。对程序句柄的拷贝共享同一份底层存储；系统中不存在并行的可变 `functions/views` 表示法，也不存在视图重建的拷贝路径。默认构造或已被 move 移走的句柄属于无效句柄。元数据访问接口强制要求 `IsValid()`；`Execute` 会直接拒绝执行无效入口。它还会拒绝带参数的入口函数以及属于不同 Isolate 的程序，且不再重复扫描字节码。

Isolate 拥有堆对象与类/数组布局，其生命周期必须长于从属于它的程序、句柄与根对象。裸加载器输入必须包含来自该 Isolate 的存活指针。加载、执行、根变更及析构操作均在 Isolate 所属线程中串行运行。返回的对象/字符串值是从堆中借用的，在下一次内存分配或 GC 运行前必须显式保根。共享不可变程序存储并不代表 Isolate 的操作具备并发线程安全性。

## 栈帧与内存管理

虚拟机针对不同的调用深度分别保留独立的寄存器容量。进入一个先前未激活的深度时，仅分配或扩容该函数实际所需的物理槽位。后续的同深度调用在清零为 null 后复用这块内存。每个活跃栈帧仅将其真正使用的槽位切片注册为 GC 根区间。函数返回及异常展开会解绑所有栈帧根；处于非活跃缓存状态的槽位不会被当作根对象扫描。

当前调用深度上限为 1024 层。栈增长时，帧元数据和寄存器文件的地址保持稳定；首帧内联存储，更深的帧按需分配。原生 JIT/AOT 入口还会检查当前线程的物理栈边界，为错误报告和展开预留 64 KiB。宿主线程栈空间不足时，原生后端可能在达到 1024 层逻辑帧之前返回 `StackOverflow`。

这彻底替代了先前每次执行均分配 262,144 字节最大寄存器文件的做法（在该次构建下为 `64 * 256 * sizeof(Value)`，其中 `sizeof(Value) == 16`）。基准测试新增的 `register_bytes` 计数器统计预热后保留的原生槽位容量总和。该数值不包含固定的 VM/栈帧元数据、分配器开销、程序只读存储及 GC 堆内存，它既不是进程物理内存（RSS），也不是 VM 的总内存开销。该次测量的 20 个脚本实际保留 48–224 字节的原生寄存器槽位。保留的容量一直维持到 VM 实例销毁；极端深度的递归负载仍可能触达配置的物理上限。

显式栈帧避免了递归调用 C++ 解释器函数。异步挂起、调度器所有权、Future 完成、取消通知、timer 顺序以及跨挂起点的 GC 保根已接通，具体行为见[异步契约](async_tasks.md)。增量 GC 的工作步长预算不构成硬实时延迟承诺；根遍历、对象图扫描和内存分配开销仍需严格测量。

## 编码上限契约

| 资源项 | 当前编码契约 |
| --- | --- |
| 单函数物理槽位数 | 1–256；寄存器索引 0–255 |
| 单函数参数个数 | 最多 256 个，受物理槽位与窗口分配约束 |
| 直接调用目标函数 | uint32 函数索引；使用紧凑字节操作数或索引扩展前缀 |
| 程序主入口函数 | 32 位索引；已测试并完全支持索引 256 |
| 类、数组布局、集合、类型、选择器、全局及字段索引 | uint32；按需使用索引扩展前缀 |
| 整数、浮点数及字符串常量索引 | uint32；使用紧凑 uint16 操作数或索引扩展前缀 |
| 数组字面量长度与插值片段数 | 单条指令中最多 255 |
| 整数常量字面量 | 有符号 16 位立即数或完整的 int64 常量池 |
| 相对跳转偏移量 | 相对于下一条指令的有符号 16 位偏移 |
| 活跃调用栈深度 | 最多 1024 层栈帧；溢出时返回 `StackOverflow`；原生后端还检查宿主线程的物理栈边界 |

程序可直接调用或构造索引超出 255 的声明。寄存器压力、字面量长度和跳转范围仍各自受检查。当前 P2 阶段的寄存器/常量池表示与设计详见 [VM 存储](vm_storage.md)。

## 验证与正确性契约

执行引擎的正确性验证与回归防护要求覆盖：
- 极限边界条件：单字节操作数索引、立即数与跳转范围、256 个参数上限、寄存器分配边界及底层镜像加载校验。
- 控制流语义：求值顺序、条件分支、循环回跳及末尾控制流穿透。
- 数值正确性：完整 int64 取值范围、算术运算溢出语义及 IEEE binary64 双精度浮点行为。
- 执行安全性：可观察到的失败保持、输入快照所有权、程序与句柄生命周期、跨 Isolate 执行拦截及异常时栈帧根安全清理。

## 值表示法与类型系统设计决策

`Value` 保持为带标签的联合体变体，严格遵循完整的 int64 与 IEEE binary64 双精度浮点语义。NaN-boxing 在不限制取值范围或不引入二次包装大整数的前提下，无法将全部 int64 整数、全部 double 浮点数以及其它所有带标签对象指针塞进单个 64 位机器字中。它不是任何场景下都能无脑提速的银弹。引入强类型或无装箱物理槽位必须在编译器、GC 和基准测试层面确立清晰的系统契约后方可实施。当前的重构在不改变数值语义的前提下大幅减少了物理槽位数量并消除了冗余分配。

P1 阶段引入了结构化的源码类型语法，并为数组元素、函数签名和泛型实参建立了显式的语义关系；已解析的类型身份仍采用 Intern 字符串名称。运行时的 `ArrayLayout` 链接负责描述物理存储排布与 GC 扫描规则，是系统运转不可或缺的核心元数据。未来可考虑将整数型的 `TypeId` Intern 化。关于已落地的对象模型与语法，详见 [P1 契约规范](core_language.md)。
