# 程序入口、结果与生命周期设计

本文定义 CLI、独立 AOT 程序与嵌入调用之间的入口、结果和任务生命周期契约。

Vela 自动执行入口模块的 `main()`，以这次入口调用的完成状态决定主程序何时结束。
同步 `main` 返回后结束；返回 `Future<T>` 时，运行器自动等待该 Future 完成。
成功返回值是程序结果，独立于进程退出状态：正常完成返回 `0`，未处理的执行错误返回 `1`。
命令行将有值结果输出到标准输出；嵌入宿主直接接收类型化结果。

主程序完成后停止调度其后台任务并清理资源。全局 `exit`、死锁检测和隐式超时不属于本设计。

## 使用示例

```vela
func main(): int {
  print('calculating');
  return 6 * 7;
}
```

命令行输出两行 `calculating`、`42`，正常退出码为 `0`。
返回负数、超过 `255` 的整数或其他合法结果类型，均不会因为值本身改变退出状态。

```vela
async func load(): Future<string> {
  await sleep(10);
  return 'ready';
}

async func main(): Future<string> {
  return await load();
}
```

运行器等待 `main` 的 Future 成功完成，随后输出一行 `ready` 并正常结束。

```vela
func main(): void {
  Future.microtask((): void => { print('background'); });
  print('main');
}
```

该程序只输出 `main`。同步入口已经完成，排队的后台微任务不会为了收尾而继续执行。
需要某个任务完成时，应由 `main` 等待它，或返回采用其结果的 Future。

## 入口与完成边界

独立程序从入口模块查找零参数的顶层 `main`，自动调用一次。导入其他模块不会自动调用
那些模块中的 `main`。本设计不扩展入口参数，也不改变模块初始化顺序。

`main` 可以返回任意合法结果类型。若实际返回值是 `Future<T>`，其成功完成的 `T` 是最终结果；
普通函数显式返回 Future 与 `async` 函数使用相同的入口等待规则。Future 的采用、类型检查、
错误传播和 await 续延继续遵循[异步函数与 Future](async_tasks.md)中的值语义。

| 入口状态 | 运行器行为 |
| --- | --- |
| 同步调用尚未返回 | 继续执行当前调用 |
| 同步调用成功返回普通值或 `void` | 进入收尾，不额外推进后台任务 |
| 已返回的根 Future 尚未完成 | 驱动调度器，等待根 Future 完成或显式停止请求 |
| 根 Future 成功完成 | 保存结果并进入收尾 |
| 入口抛出未捕获异常，或根 Future 失败 | 保存错误诊断并进入失败收尾 |

完成边界位于当前执行单元返回运行器之后。运行器不打断已经进入的同步调用栈；其中的
普通异常处理和 `finally` 按语言规则执行完毕。确认入口完成后，不再开始下一个属于
该主程序的脚本回调、微任务、timer 回调或 await 续延。

这个边界也适用于同一批微任务：根 Future 在某个执行单元中完成后，不能先排空整批剩余
微任务，再检查入口是否结束。调度实现必须能在执行单元之间观察完成或停止状态。

### 异步等待

根 Future 未完成时，运行器可以执行推进它所需的微任务、timer 和宿主完成事件。
这一期间其他已就绪任务仍按既有调度顺序执行；运行器不要求静态识别每个任务是否被
`main` 直接或间接 await，也不只调度能够证明属于根 Future 依赖链的任务。

决定主程序生命周期的是根 Future 的完成状态。后台任务数量、timer 数量和事件源数量
不延长一个已经完成的入口。

暂时没有可执行任务不代表根 Future 已完成，也不构成执行错误。入口等待不自动检测死锁、
设置超时或因事件源耗尽而宣告正常结束。根 Future 可以一直未完成；运行器应休眠等待
可接受的唤醒或外部停止，不能反复轮询 idle 形成忙等。用户显式使用的 Future 超时 API
继续按其自身语义工作。

宿主异步操作仍须按现有协议登记生产者、提交完成事件并唤醒所属线程；去除 idle/deadlock
命令错误不改变跨线程投递和资源所有权契约。

## 程序结果与输出

程序结果保留类型信息，不能再限制为 `int`，也不能将其数值转换为退出码。
普通函数调用与宿主导出调用仍通过现有类型化结果接口交付值。

独立命令行入口采用以下展示规则：

| 最终结果 | 标准输出 |
| --- | --- |
| `void` 或 `Future<void>` 完成 | 不追加结果输出 |
| 字符串 | 输出字符串内容，并追加一个换行符 |
| 数值、布尔值、显式 `null` 及其他合法值 | 使用现有 `print` 的值显示规则，并追加一个换行符 |
| 执行失败 | 不输出最终结果；诊断写入标准错误 |

结果展示复用[现有值输出实现](../../runtime/value/value_io.cc)，不在入口增加 JSON 序列化、
对象遍历或用户方法调用。需要特定表示的程序可以返回已格式化的字符串。
既有 `print` 输出按实际执行顺序保留，最终结果只在成功收尾时追加一次。

`void` 与显式空值必须区分：`main(): void` 无结果，非 void 结果为空时显示 `null`。
运行器须消费入口签名及 Future 载荷的规范类型信息，不能仅凭运行时的空值表示推断是否输出。

结果在资源清理和输出期间保持保根；清理后台任务不能提前释放返回的字符串、对象或其元数据。
结果写入失败属于运行失败，不能仍报告成功。已经发生的输出和其他副作用不回滚。

## 退出状态与错误

| 执行结局 | 进程退出码 |
| --- | ---: |
| `main` 正常完成，结果交付和必要收尾成功 | `0` |
| 未捕获的同步异常、根 Future 失败或已报告的未处理异步错误 | `1` |
| 结果输出或必要运行资源收尾失败 | `1` |

被脚本正常捕获并处理的错误不自动改变退出状态。保留错误对象、原始抛出位置、调用栈及
await 边界，统一在运行入口报告，避免 CLI 与 AOT 为同一个错误重复打印诊断。

根 Future 的失败直接作为入口错误处理，不依赖是否还执行下一个未处理错误检查点。
其他 Future 的未处理错误继续按现有检查点契约认定：在入口完成前已经报告的错误使运行失败；
不能为了检查入口完成之后才可能出现的后台错误而额外执行任务或扫描全部 Future。
丢弃尚未执行的后台任务不是新的脚本异常。

本设计规定主程序执行的成功或失败状态。`check`、`build`、测试运行器等工具命令的
参数、源码、文件和测试结果错误分类仍由各自契约负责，不复用脚本的返回值作状态码。
外部中断和调试器显式停止沿用各自的控制协议，不伪造一次成功的 `main` 返回，也不输出结果。

## 后台任务与资源收尾

未 await 的异步函数可能已经执行了首个挂起点之前的代码，也可能在 `main` 等待期间
执行过部分续延。主程序结束后不保证这些任务完成，也不撤销其已发生的副作用。

收尾应按以下责任顺序完成：

1. 封闭本次主程序的调度边界，拒绝继续进入脚本，阻止周期 timer 再次排队。
2. 关闭属于本次运行的跨线程完成端点，使迟到的完成无法投递到结束或后续运行。
3. 取消所属 timer，撤销待执行微任务、回调和挂起续延，释放其根、程序状态和代码引用。
4. 注销宿主事件源并释放本次运行拥有的资源；对可取消的外部操作发出已有协议允许的取消请求。
5. 在结果或错误仍受保护时完成交付，随后释放入口持有的运行资源。

资源清理不继续执行被丢弃任务的脚本代码，不把其挂起位置恢复出来运行 `finally`，
也不等待脚本级异步清理完成。需要执行这些清理逻辑的任务必须在 `main` 完成前被等待。
后台任务清理也不把普通 Future 类型改成可取消类型。

关闭完成端点与停止实际外部 I/O 是不同责任。运行器必须阻止迟到回调访问已释放的
Isolate、堆或代码；不能假设取消请求已经同步停止外部线程或不可取消操作。
继续使用现有端点关闭及 `Closed` 完成结果契约，原生拥有者按其真实生命周期安全释放资源。

## CLI、AOT 与嵌入边界

`vela run`、直接启动 `main` 的 `vela debug` 及 AOT 独立可执行程序使用同一入口契约。
编译方式、优化级别、缓存命中与否不改变结果输出、停止边界和执行错误码。

C++ 普通导出调用保留现有语义：宿主取得类型化结果或错误，Future 返回值交给宿主选择
等待方式；调用完成不自动退出宿主进程、关闭 Isolate 或清空其他调用的任务。
宿主若使用完整的主程序驱动，则由该驱动应用本文的根 Future 和运行作用域清理规则。

生命周期边界属于本次主程序运行。CLI 独占 Isolate 时可以随运行一起释放它；共享 Isolate
的宿主不能为了结束一个入口而丢弃其他运行拥有的任务。持久开发会话、REPL 与源码测试
运行器仍由各自会话契约决定生命周期；测试中的 `main` 注册完测试树后，测试运行器继续执行。

本设计不增加全局 `exit`、`exitCode` 或程序级强制终止 API。宿主已有的停止机制继续用于
显式停止；普通程序通过完成 `main`、传播异常或返回所等待的 Future 表达自身结局。

## 实现职责

[ProcessEntry](../../runtime/process/process_entry.cc) 在入口执行前建立 `FutureRunScope` 并安装
未处理错误观察，等待根完成后关闭该作用域，在结果仍保根时复用 `WriteValue` 交付输出。
Future、等待者、微任务、检查点、timer 和完成端点保留各自的运行归属；关闭时只释放本次
运行的捕获资源。源 Future 属于其它运行时，也会移除本次入口登记在它上面的等待者。
关闭后的完成端点不再借用调度器，迟到完成返回 `Closed`。

调度器的 `WaitForCompletion` 模式允许没有生产者时休眠等待。入口向 pump 提供完成谓词，
在每个执行单元之间检查根和停止状态；停止端点唤醒同一个信号量。普通嵌入式
`PumpOne`、`PumpUntil` 和宿主 `Wait` 保留各自的工作批次与 idle 契约。

入口签名与 Future 载荷使用原生映像已有的规范类型描述；AOT 生成端和运行端共用它们，
无需增加另一份结果类型表。相关文档见[异步契约](async_tasks.md)、
[标准库](standard_library.md)、[AOT](aot.md)和[嵌入](native_embedding.md)。

| 责任路径 | 实现契约 |
| --- | --- |
| 入口结果与类型 | 从入口签名和 Future 载荷取得最终类型；区分 void 与显式 null；保留普通值范围及宿主类型化返回 |
| [共享进程入口](../../runtime/process/process_entry.h) | 分开持有程序结果与退出状态；根完成后收尾，不转换返回值为退出码 |
| [Future 调度器](../../runtime/async/future_scheduler.cc) | 支持入口完成边界；根完成后不再排空剩余微任务；挂起时正确休眠、唤醒并响应停止 |
| 异步任务及宿主资源 | 落实本次运行归属、timer 停止、续延释放、端点关闭和迟到完成隔离 |
| [CLI](../../compiler/cli/vela_main.cc)与[调试器](../../compiler/cli/debug_console.cc) | 正确输出程序结果，执行失败返回 1；显式停止不输出伪结果 |
| [AOT 程序入口](../../runtime/native/native_main.cc)及[生成端](../../compiler/aot/native_compiler.cc) | 复用相同的运行契约和类型事实；库导出继续交付原始计算结果 |
| 测试运行器、开发会话和嵌入宿主 | 复核共享接口消费者，保留各自合法的会话和普通函数调用职责 |
| 测试、示例与现有文档 | 程序结果断言与退出码断言分开；后台任务、异步等待和输出示例遵循同一契约 |

工具和宿主仍使用各自的状态分类。基准负载继续返回原校验结果，性能计时范围不加入命令行展示。

## 完成条件

实施后的验收至少覆盖以下行为，所有适用案例均对照 CLI 与独立 AOT 产物：

- 普通值、整数端点、字符串、布尔值、引用、显式 null、void 及相应 Future 结果；结果输出
  一次，正常退出码为 0，void 不输出，宿主取得原始类型化值。
- 同步异常、异步入口失败、已处理错误、未处理后台错误及结果输出失败；失败退出码为 1，
  错误栈与既有输出保持正确，不重复报告。
- 同步入口排队后立即返回、异步入口等待一个任务后返回，以及仍有周期 timer 或其他任务
  未完成的情况；根完成后不执行剩余回调，也不延迟到所有后台任务结束。
- 根 Future 在一批微任务中完成时，后续已排队回调不再执行；已完成 Future 的 await 仍保留
  现有续延语义，当前同步执行单元正常返回。
- 根 Future 长期未完成或调度器暂时 idle 时，不自动报错、退出或忙等；测试通过显式停止
  结束该场景，不把测试超时机制变成语言超时规则。
- 收尾后的 timer、挂起帧、保存状态和根释放；迟到宿主完成返回 Closed，不进入旧运行或
  新运行，不访问已释放内存；结果本身在交付前保持有效。
- 共享 Isolate 的其他运行、普通 C++ 导出调用、持久会话和测试执行不被入口清理误伤；
  Debug/Release、缓存首次编译和命中路径遵循同一契约。

仅将既有测试的退出码期望统一改成 0 不构成验收。原计算结果必须改由标准输出或
类型化宿主结果验证，原有异常、GC、调用栈和资源安全断言继续有效。
