# 解构模式与集合展开设计

> 状态：待实现。本文参考 Dart 3 的数组、Map 与对象模式，定义 Vela 的解构声明、解构赋值、循环绑定和集合字面量展开。保留 Vela 的 `const` / `let`、后置类型标注及既有类型和运行时契约。现有编译器只支持 Map 遍历专用的 `[key, value]` 绑定，不能直接运行下列新增语法。

```vela
class User {
  name: string;
  age: int;
}

const numbers: int[] = [10, 20, 30, 40];
const [first, _, ...tail] = numbers;             // first = 10，tail = [30, 40]
const [head, ...middle, last] = numbers;         // middle = [20, 30]，last = 40
const extended: int[] = [0, ...numbers, 50];

const user = User(name: 'Vela', age: 7);
const User(name: title, :age) = user;            // title = 'Vela'，age = 7

const data: Map<string, dynamic> = {'name': title, 'age': age};
const {'name': name} = data;
const updated: Map<string, dynamic> = {...data, 'age': 8};
```

`User(...)` 在模式位置检查名义类型并读取成员，不调用构造函数。Map 模式使用明确的键表达式，与类成员模式分开。数组剩余段、数组展开和 Map 展开产生新容器，内部引用保持共享。

函数通过普通参数接收一组值，例如 `func sum(values: int[]): int`，调用写作 `sum(numbers)`。本设计不提供调用展开、rest 形参或入参解构；数组模式里的 `...tail` 仅收集该数组的剩余段。

## 1. 当前基础与支持范围

| 当前实现 | 所需变化 |

| 同一 AST 中的 `Global` 只有一个名字和初始化器 | 顶层模式保留共同初始化器与绑定组，每个全局叶子分别参与导出、类型解析和声明身份管理 |

| [`SemanticModel`](../../compiler/frontend/type_checker.h) 多处按整个语句记录单个类型或绑定 | 记录每个模式节点、绑定及读取、检查和提交步骤的受检事实 |

解构覆盖局部和顶层声明、已有局部或参数的赋值，以及 `for (... in ...)` 的绑定。集合展开覆盖数组和 Map 字面量。对象模式显式列出要读取的成员；Map 模式显式列出要查找的键。

以下内容不属于本设计：record、结构化 class 类型、`match` / `switch` 的结构模式与 guard、class 字段声明模式、函数/构造函数/lambda 的入参解构、调用展开、源码 rest 形参及 rest 函数类型、条目默认值、对象/Map rest、class 字段枚举和展开、Set 字面量、空安全展开、用户迭代器与 `for-of`。泛型继续要求显式类型实参，不增加约束或类型实参推断。

已有 `push(1, 2)` 等内建方法的变长调用由现有 API 签名定义，不因本设计获得 `push(...values)` 语法。已有内建签名的 rest 元数据仍服务于真实调用方，本设计不将其扩展为用户声明语法。

## 2. 语法与解析

### 2.1 模式

```text
Pattern        := BindingName | '_' | ListPattern | MapPattern | ObjectPattern
ListPattern    := '[' (ListItem (',' ListItem)* ','?)? ']'
ListItem       := Pattern | '...' Pattern?
MapPattern     := '{' MapEntry (',' MapEntry)* ','? '}'
MapEntry       := ConstantExpression ':' Pattern
ObjectPattern  := NamedType '(' (ObjectField (',' ObjectField)* ','?)? ')'
ObjectField    := IdentifierName ':' Pattern | ':' BindingName

Declaration    := ('const' | 'let') Pattern (':' Type)? '=' Expression ';'
Assignment     := DestructuringPattern '=' Expression
DestructuringPattern := ListPattern | MapPattern | ObjectPattern
```

上述语法说明新增结构，列表分隔符、类型名和普通表达式继续使用既有规则。`const` / `let` 决定声明中所有真实绑定的可变性，`const` 不具有 Dart 编译期常量声明的含义。整个模式的后置类型标注约束源值；叶子类型由源类型及成员读取推导，不新增叶子类型标注语法。

`_` 不创建或赋值任何变量，可以重复出现。数组模式用 `_` 跳过一个元素，用裸 `...` 或 `..._` 忽略剩余段；连续逗号形成的空位非法。每层数组模式最多一个剩余段，它可以位于开头、中间或末尾，也可带嵌套模式。普通模式项和剩余段之后均允许通常的尾逗号。

Map 模式至少包含一项，键必须是现有常量求值器支持、且适合源 Map 键类型的常量表达式。字符串键必须写成 `'name'`；裸标识符作为键时引用其常量值，不隐式转换成同名字符串。没有 JS 的计算键方括号、变量键简写、条目默认值或 Map rest。按 Map 键相等规则重复的常量键报编译错误。

对象模式使用显式命名的 class / interface 类型，泛型类型实参必须写出。`User(:name)` 是 `User(name: name)` 的简写；模式名和构造函数名使用不同的语义解析，不执行构造或分配实例。重复成员名报错。对象模式允许嵌套数组、Map 或对象模式。

### 2.2 声明与赋值

```vela
let [x, y]: int[] = [1, 2];
[x, y] = [y, x];

let User(name: localName) = user;
User(name: localName) = anotherUser;

let {'name': label}: Map<string, string> = names;
({'name': label} = otherNames);
```

赋值模式只出现在普通 `=` 左侧，不能用于 `+=` 等复合赋值。其叶子必须解析为已有可写局部或形参，包含捕获的可变局部；不接受全局、隐式实例字段、setter、成员访问或下标作为目标。普通全局、字段和下标赋值仍使用现有赋值语法。重复声明名字或重复赋值同一个变量均报错。

Map 赋值语句使用外层括号，避免与语句块混淆。解析器看到 `Type(...) =` 时按对象赋值模式处理，普通构造调用仍按表达式处理；格式化和增量解析采用相同的语法事实。赋值表达式返回原始 RHS 值，保持其类型和引用身份。

模式声明必须有初始化表达式。局部模式的 RHS 在该声明的新名字进入作用域前按现有名字解析规则检查，初始化后各绑定才可使用。顶层叶子按既有全局规则预先登记，相关类型推导和循环初始化按第 4.3 节处理。模式内部没有默认表达式，不产生条目之间的默认值依赖。

当前 `ParseVariableDeclaration` 在未读到简单名字时可能无诊断地返回空节点。这种错误恢复不能被视为解构支持。D0 必须保证未完整解析的声明产生诊断；不能丢弃声明后让 `check` 返回成功。调用、形参和函数类型位置的 `...` 也必须明确拒绝。

## 3. 来源、类型和失败

### 3.1 数组模式与剩余段

普通数组模式只接受非空的 `T[]` 或运行时受检查的 dynamic 数组，不把字符串、Set 或 Map 隐式转换为数组。需要拆分其它来源时显式取得数组，例如 `set.values()`、`map.keys()`、`map.values()`、`text.codePoints()` 或 `text.graphemes()`。

没有剩余段时，源数组长度必须等于模式项数；存在剩余段时，长度必须至少等于非剩余项数。`[first]` 只接受一个元素，`[first, ...]` 才表示忽略其余元素，`[]` 检查数组为空。`_` 仍占用一个位置，不能绕过长度检查。

进入每一层数组模式时取得该层长度 `n`，完成形状检查，并据此确定前缀、中间段及后缀的下标。之后按模式书写顺序读取；嵌套 getter 若修改源数组，后续读取观察当时的值，但不会重新计算该层下标分配。数组缩短导致某次读取越界时传播现有边界错误，不跨调用保存元素存储裸地址。

绑定剩余段得到新的 `T[]`，零个元素也得到新空数组。裸 `...` 与 `..._` 不分配剩余数组。嵌套剩余段如 `[first, ...[second, third]]` 先形成该段的新数组，再应用其子模式及长度检查。只含前缀与裸剩余段的模式无需复制整个后缀。

dynamic 数组来源在入口检查实际数组类型和元素元数据，叶子按 dynamic 值检查，剩余段结果为新 `dynamic[]`；复制不改变源数组的元素类型或存储。不因来源当前只含某一种值就把它推断为该具体数组类型。

### 3.2 Map 模式

Map 模式接受非空 `Map<K, V>` 或运行时受检查的 dynamic Map。明确列出的键必须存在，其余条目忽略；不要求源 Map 大小等于模式项数。键的静态类型必须适合 `K`，叶子来源类型为 `V`。

存在性独立于 null：`{'name': name}` 在键存在且值为 null 时得到 null；键缺失时失败，不自动补 null。即使目标允许 null，也不能把不存在的键当作成功。需要默认值时显式使用现有 `get` / `has`、`??` 和普通控制流。

Map 模式不调用 class 的同名成员；对象模式也不把 Map 键解释为 class 属性。dynamic 来源检查真实容器和键类型，不把普通对象转换成 Map。嵌套模式必须继续满足对应的非空来源和形状条件。

### 3.3 对象模式

`User(name: title)` 先检查源值符合名义类型 `User`，再按普通成员读取规则取得 `name`。允许该类型的子类实例，额外成员不影响结果。interface 模式使用已有接口分派，不能通过同名属性形成隐式结构化实现。

成员名必须在模式指定的静态类型中可读，遵守可见性与 getter 规则；继承成员按普通成员解析处理。普通方法值仍按既有成员取值规则绑定接收者，不自动执行方法。具体 override 选择、getter 异常及热重载惰性字段初始化均复用正常成员访问路径。

对象模式不枚举实例字段，不复制私有状态或原生载荷，不调用 setter，也不构造另一个实例。`User()` 仅检查类型。模式要求的成员即使绑定到 `_` 也按普通成员读取处理；只有证明读取无可观察效果时才可消除。

### 3.4 错误与静态检查

| 情况 | 处理 |
| --- | --- |
| 静态已知不适用的来源、类型或成员，或可证明不满足的形状 | 编译期诊断，不发布可执行结果 |
| 运行时来源为 null、种类不符、名义类型不符或数组形状不符 | 使用现有 `TypeError` 失败路径，诊断关联具体子模式 |
| Map 必需键不存在 | 使用现有 `TypeError`，消息注明缺失键；不新增 Dart 的 `StateError` 类型 |
| dynamic 值进入具体类型目标失败 | 使用现有受检查转换错误路径 |
| getter、成员初始化、数组读取或容器分配失败 | 传播原异常或执行状态，保留发生位置和现有 handler |

解构是必须成功的绑定操作，不是自动跳过失败数据的筛选器。`for (... in ...)` 中某次解构失败同样抛错，不静默跳过该元素。本设计不增加 `if-case` 或 `match` 结构匹配入口。

## 4. 求值、提交和初始化

### 4.1 先完成解构，再提交绑定

RHS 只求值一次。各层先进行来源与形状检查，再从左至右读取和递归解构，检查叶子类型并暂存结果；整个模式成功后才提交所有真实绑定。赋值模式采用同一规则，不保留 JS 的逐项写入行为。

```vela
let left = 1;
let right = 2;
// 若 getPair() 的第二项不能进入 right 的类型，left 和 right 均不被本次赋值写入。
[left, right] = getPair();
```

提交阶段只写已经解析好的局部槽或捕获单元，不再执行用户代码、类型检查或分配。捕获单元和所需临时存储必须在提交前准备好。getter 或宿主调用自行修改外部状态的副作用保留，模式失败不回滚这些副作用。

源容器不会为了统一提交而预先全量复制。每个读取仍在自己的步骤执行；后续 getter 对源的修改不会追溯改变已经暂存的值。显式成员读取、惰性初始化和分配的效果不得被当作一条纯操作重排或重放。

### 4.2 循环与 Map 键值入口

`for (const pattern in collection)` 与 `for (let pattern in collection)` 每次迭代创建独立绑定，模式成功后才进入循环体。闭包捕获不能误用另一轮迭代的可变单元。外层集合的既有遍历、快照和结构修改规则保持有效。

保留现有 `for (const [key, value] in map)` 的键值入口语义，扩展两个槽内部的递归模式与 `_`。该入口是具有 `K`、`V` 类型的内部双槽，不通过分配异构数组模拟，也不新增可存储的 record。

Map 键值入口的外层模式必须恰好包含两个非剩余项；它不是普通 `T[]`，不接受外层数组剩余段。两个槽内的真实数组可以正常解构和收集剩余段。单变量 Map 遍历仍取得键，普通 Map 模式则用于显式查键，这三种入口的受检计划须明确区分。

### 4.3 顶层绑定组

顶层模式使用一个具有稳定身份的内部绑定组，连接全部全局叶子与共同初始化器。首次读取任一尚未初始化的叶子时，在一次尝试中计算 RHS、完成模式和类型检查，全部成功后共同发布各槽。

顶层模式必须至少声明一个真实名字，为惰性初始化提供入口；仅含 `_`、裸剩余段或空对象模式的顶层声明报错。局部可以使用无绑定模式检查来源。需要独立源副作用时放入普通函数或入口。

初始化中通过外部调用重新进入该组，使用现有 `CyclicInitialization`。失败不发布叶子，释放临时根；已发生副作用保留，下次读取按既有全局初始化重试政策重新计算。组和每个导出叶子使用稳定声明身份，不以行号或 token 偏移标识。

全局类型解析以绑定组为共同来源，分别产出每个叶子的类型，不能为推导每个名字重复检查初始化器并建立不同实例化事实。递归类型推导沿用显式标注要求；任何同组叶子的运行时读取都须经过组状态，不能读取尚未发布的槽。

更改已初始化组的叶子集合或模式结构，若需要重读源值建立新槽，要求 Reload；Hot Reload 不重放已完成初始化。只修改初始化表达式时，已完成值保留，尚未初始化的组使用当前初始化器。这是 Vela 惰性全局模型的规则，不照搬 Dart 的局部模式声明范围。

## 5. 集合字面量与展开

### 5.1 语法和来源

```text
ArrayElement := Expression | '...' Expression
MapElement   := Expression ':' Expression | '...' Expression
MapLiteral   := '{' (MapElement (',' MapElement)* ','?)? '}'
```

| 目标 | 可展开来源 | 行为 |
| --- | --- | --- |
| 数组字面量 | 非空 `T[]`、`Set<T>` 或受检查的 dynamic 数组/Set | 按数组顺序或 Set 插入顺序追加元素 |
| Map 字面量 | 非空 `Map<K, V>` 或受检查的 dynamic Map | 按源 Map 插入顺序复制键值条目 |

数组展开不直接接受 Map、string 或 class；按需显式取得键、值、码点或字素簇数组。Map 展开不读取 class 字段，不将数组下标当成键。null 来源报错，不采用 JS 的对象展开空操作，也不增加 `...?` 语法。

Map 字面量明确写键和值，例如 `{'name': name}`、`{selectedKey(): value}`；没有 `{name}` 简写或隐式字符串键。字面量键可以是普通表达式，模式键才要求常量。键表达式只求值一次且先于对应值表达式。

### 5.2 类型、顺序和复制

数组有 `U[]` 上下文时，普通元素和各展开元素都必须能进入 `U`；Map 有 `Map<K, V>` 上下文时，逐项检查键和值。无上下文时沿用严格同类型推断；异构值需显式 dynamic 元素或值类型，不能因推断失败自动降级。只有展开项时可从其静态类型取得结果类型；空字面量和仅有 dynamic 来源的字面量需要明确的容器上下文。

容器存储保持不变性。从 `int[]` 逐元素复制到新 `dynamic[]`，或向新 Map 复制可赋值的键值，不会改变源容器的类型实参。`{}` 在有 Map 上下文时表示空 Map，不引入 Set 或匿名对象的推断歧义。

所有项按源码顺序求值。遇到展开立即检查并消费来源，完成后才执行后续项：

```vela
const result = [...values, change(values), ...values];
```

第一次展开得到的值不因 `change` 重新读取，第二次展开观察修改后的来源。Set / Map 消费复用既有有序快照规则；消费和元素检查之间不主动调用用户转换函数。失败时后续项不执行，构建中的结果不交付，已发生的源副作用保留。

Map 重复键由后者覆盖，位置保持该键第一次插入的位置；删除后再插入的源顺序沿用现有 Map 契约。字符串形式的数字键不另作排序。

数组和 Map 结果具有新容器身份，嵌套引用共享。实现复用受堆内存核算的存储和扩容机制；仅在不改变副作用顺序时预留容量。不以反复拼接整个累计结果实现展开，也不为没有绑定的数组剩余段分配临时容器。

## 6. 编译与运行时实现

### 6.1 模式树与受检计划

模式树统一表达名字、通配符、数组及剩余段、Map 键和对象成员。绑定上下文决定创建名字还是引用已有局部/参数，不能靠多个 `Statement::name` 字段模拟。数组/Map 字面量分别保存普通项与展开项及准确源范围。

语义检查产生来源类型、长度或键存在性检查、名义类型检查、读取次序、成员身份、受检查转换、临时结果、剩余数组类型和最终提交目标。lowerer 直接消费这些事实，不重新推导类型、可见性或键含义。

模式遍历接入 AST 克隆、模块绑定、模板特化、捕获、初始化分析、控制流、lowering、语义索引与格式化。现有 Map 循环两名字转为同一模式树及双槽来源计划，删除 `second_name` / `destructuring` 专用路径和固定 token 偏移。现有 `match` 的通配符及绑定可以复用节点与访问器，其常量匹配和穷尽性规则保持现有范围。

### 6.2 IR 和容器操作

源值、长度、键值、暂存叶子和结果容器使用明确临时值。Map 存在性可复用 `has` / `get`：同一键不重复求值，两者之间不执行用户代码，不以 null 推断缺失。对象成员使用正常字段/getter/方法值解析及运行时访问契约。

先生成全部读取和检查，再生成局部槽或捕获单元提交。类型检查、分配和 getter 失败的后继边必须绕过提交。顶层组的发布沿用同一成功边界，并接入真实的全局初始化状态。

数组剩余段和集合展开复用已有数组、Map、Set 快照及元素读写接口。确需新增操作时，同步补齐公共效果分析、定义/使用、异常后继、寄存器分配、字节码编码及验证、镜像读写、LLVM 发射和运行时符号；不能只在解释器实现。

此功能不扩展调用签名、函数类型或宿主 ABI。仅当实际新增的编码或持久化数据改变布局时更新对应格式版本及构建身份；调用继续使用现有参数绑定和物理参数布局。

### 6.3 GC、异常与挂起

原始源、暂存叶子、键、剩余数组、构建中的集合及捕获单元在每个可分配/可调用步骤精确保根。扩容、getter、惰性初始化和热重载安全点后重新取得可能失效的内部地址，不跨调用借用字段块或元素存储裸地址。

模式条目没有默认表达式，但 RHS、集合项或展开来源表达式可以按既有 async 规则包含 `await`。挂起和去优化记录当前步骤、已消费项和暂存结果，恢复后不重放 getter、复制或用户副作用。模式只在全部步骤成功后提交，循环体和后续语句不能提前观察新绑定。

分配失败按现有 `OutOfMemory` 与异常封套政策处理，释放临时根与构建状态；不交付半成品容器，不回滚外部副作用，不切换到解释器重试。未来分配消除须遵守[逃逸分析设计](escape_analysis.md)的身份、可观察效果和恢复契约。

## 7. 热重载、工具与诊断

局部模式随函数体版本化。旧帧、挂起续延和捕获闭包继续使用原版本步骤与绑定身份；后续调用选择当前声明。顶层组按第 4.3 节复核。对象模式的具名类型及可读成员进入现有声明依赖，跨 getter 和字段惰性初始化使用正常重载安全点与代码退休协议。

LSP 为每个真实绑定建立符号，`_` 与裸剩余段不产生变量。`User(:name)` 中成员与局部名字是两个角色：局部重命名为 `title` 后展开为 `User(name: title)`，成员名保持不变；成员重命名时保留原局部身份。Map 字符串键是数据，不伪造成 class 成员或随局部变量一起重命名。

补全在对象成员位置使用显式类型，在类型位置提供正常命名类型，在绑定位置使用模式上下文。格式化、语义 token、VS Code 高亮、文档查询、REPL 多行输入及错误恢复统一理解嵌套模式、`_`、剩余段与集合展开。

诊断至少覆盖：非法来源、数组形状不符、缺失键、成员不存在或不可读、非常量模式键、重复键/成员/绑定/赋值、不可写目标、多个剩余段、逗号空位、默认值、对象/Map rest、容器类型不符，以及调用或形参位置的非法 `...`。错误位置落在具体子模式、键、成员或展开项。

## 8. 与 Dart 3 的关系

| 项目 | Vela 的取舍 |
| --- | --- |
| 数组模式 | 采用长度匹配、`_`、任意位置的单个剩余段；容器类型仍为 `T[]` |
| Map 模式 | 明确常量键，忽略额外键，缺失失败；使用现有 Vela 错误状态 |
| 对象模式 | 显式名义类型与具名成员，支持 `:name` 简写；成员访问复用 Vela 契约 |
| 解构赋值 | 只写已有可写局部/参数，全部解构成功后提交，不接受字段或下标目标 |
| 变量声明 | 保留 `const` / `let` 与整个模式的后置类型标注，不新增 Dart 叶子类型语法 |
| 顶层声明 | 使用 Vela 惰性绑定组，明确初始化、失败重试及 Hot Reload 行为 |
| 集合展开 | 数组接受数组/Set，Map 接受 Map；本设计不增加 Set 字面量、空安全展开或集合控制流元素 |
| 函数 | 无入参解构、调用展开或源码 rest 形参；一组值通过普通数组参数传递 |
| 其它模式能力 | 不因引用 Dart 3 而引入 record、结构匹配、逻辑/关系/转换/空检查模式或 guard |

## 9. 实施阶段与验收

| 阶段 | 生产路径 | 完成条件 |
| --- | --- | --- |
| D0：语法与受检事实 | 模式树、集合项、来源计划、错误恢复、统一遍历 | 所有语义和失败边界可表示；非法声明和非法调用语法不能被静默丢弃 |
| D1：数组模式 | 局部声明、赋值、嵌套、通配符、剩余段、Map 循环双槽迁移 | 形状检查、先解构后提交、类型与 GC 正确；旧两名字专用路径删除 |
| D2：Map 与对象模式 | 常量键、存在性、具名类型、成员/getter/方法值、普通及简写字段 | class 与 Map 不混用；缺失与 null 分开；成员与局部符号身份正确 |
| D3：集合构造与展开 | 数组/Map 字面量、上下文类型、数组/Set/Map 来源、有序复制 | 即时消费、覆盖顺序、浅复制、资源核算与失败路径在全部后端一致 |
| D4：初始化与工具 | 顶层组、捕获、async、去优化、Hot Reload/Reload、缓存、REPL、LSP | 无部分提交或副作用重放；导航、重命名与格式化反映真实结构 |
| D5：完整验证 | 中英文文档、示例、VM 与原生执行配置、工具与分发、Release 基准 | 完整目标套件、静态检查及必要性能验证通过，废弃的专用机制已清理 |

设计的完成范围包含全部阶段及其生产路径，不以 parser 接受语法或局部数组测试通过作为全部功能完成。D3 仅指集合展开，不包含调用参数机制。

### 9.1 正确性矩阵

- **解析与类型**：模式/构造调用区分、嵌套、泛型显式实参、后置标注、键与成员语法、上下文推断、Map 空字面量；拒绝空 Map 模式、逗号空位、默认值、Map rest、调用展开及 rest 形参/函数类型。
- **形状与失败**：精确长度、最小长度、前/中/后剩余段、空数组、缺失键、存在的 null、dynamic 来源、错误名义类型、重复键和绑定；任何叶子失败都不提交赋值结果。
- **求值与副作用**：RHS 一次、从左到右的 getter 与嵌套读取、getter 修改源容器、已暂存值、捕获单元提交、集合键先于值、即时消费、异常后后续项不执行。
- **身份与资源**：新容器与共享子对象、无绑定剩余段不分配、高压 GC、每个分配边界失败、扩容、Set/Map 快照及惰性字段初始化。
- **状态与工具**：循环闭包逐轮独立、顶层组失败重试与循环初始化、跨挂起恢复与去优化、重载拒绝及 Reload、简写重命名展开、Map 键保持、格式化幂等和未完成输入恢复。
- **生产交付**：模板克隆和跨模块导出、字节码恢复、代码缓存、独立原生分发、原有普通函数与内建变长调用保持现有调用契约。

正常语义对照 VM、封闭 AOT、可重载 JIT 初始层与优化层；分配失败按各配置真实存储边界断言，不要求执行相同次数的不可观测分配。

### 9.2 性能与文档同步

Release 基准覆盖精确数组解构、无绑定剩余段、中间段复制、大数组与 Set 展开、多段混合展开、Map 键查询与合并、对象 getter、捕获赋值和顶层组。保留无模式的普通声明与无展开的集合构造作对照，记录中位数、波动、编译成本、分配量、GC、寄存器/帧和代码体积。

数组剩余段及集合复制应为输入规模 O(n) 或均摊 O(n)，Map 查询复用已有索引。裸剩余段无需遍历后缀，不接受通过反复复制累计结果产生的 O(n²) 实现。

实现完成时同步更新中英文 [`core_language.md`](core_language.md)、[`arrays.md`](arrays.md)、[`json.md`](json.md) 和示例。JSON 仍映射为原生数组和 Map；字面量不改变数字、null 或业务构造语义。数组文档中 `...items` 仅表示内建 API 变长项的说明继续准确，不能改写为通用调用展开支持。设计阶段保留这些文档对当前实现的描述。
