# Map 字面量设计

> 状态：M0–M5 已实现并完成 Windows x64 验收。本文定义 Vela 的 Map 字面量，包括语法、类型推导、求值顺序及编译和运行时交付。解构与集合展开暂不纳入本设计；`Map<K, V>()` 和 `set` 仍是普通集合 API。

```vela
const scores: Map<string, int> = {'Vela': 42, 'Dart': 40};
const names = {'language': 'Vela', 'version': 'next'};
const empty: Map<string, int> = {};

let key = 'name';
const data: Map<string, dynamic> = {key: 'Vela', 'age': 7};
```

字面量产生普通的 `Map<K, V>`，沿用现有键相等性、插入顺序、类型不变性、引用与内存管理规则。`{key: value}` 使用表达式 `key` 的值作为键；`{'key': value}` 使用字符串 `'key'`。

## 1. 当前基础与支持范围

| 生产路径 | 实现契约 |
| --- | --- |
| [`Expression`](../../compiler/frontend/syntax/ast.h) 的 `MapLiteral` 和有序 `MapEntry` | 键和值保留独立表达式与源码位置，源范围来自同一词法快照 |
| [`parser_collections.cc`](../../compiler/frontend/syntax/parser_collections.cc) 与 [`parser.cc`](../../compiler/frontend/syntax/parser.cc) | 表达式位置解析 Map，lambda 与语句块保持独立语法，未完成条目保留已知部分 |
| Map 显式构造、键值类型和有序 `set` | 字面量复用同一类型、构造和插入契约 |
| [`SemanticModel`](../../compiler/frontend/typing/type_checker.h) 发布表达式类型、调用与转换事实 | 发布字面量的具体 Map 类型和各条目的受检查转换 |
| IR 与后端的集合构造和 Map 写入路径 | 按源码顺序生成构造、键求值、值求值和插入，显式记录写入操作的 void 结果类型 |
| 格式化、语义索引、文档工具和 REPL | 遍历键值表达式，保留 lambda 括号、文档键值结构及未完成输入，变量改名按模块返回编辑 |

Map 字面量可用于初始化器、赋值右侧、实参、返回值、字段默认值及其它接受表达式的位置，支持嵌套 Map 和数组值。它不创建匿名 class 或独立的 JSON 对象类型。

本设计不增加解构声明、解构赋值、对象/数组/Map 模式、数组或 Map 展开、Set 字面量、调用展开、源码 rest 形参、集合控制流元素或字段名简写。现有 Map 遍历专用的 `[key, value]` 绑定和 `match` 能力不在本次调整范围内。

## 2. 语法与解析

```text
MapLiteral := '{' (MapEntry (',' MapEntry)* ','?)? '}'
MapEntry   := Expression ':' Expression
```

键和值都是普通表达式，允许函数调用、变量引用、条件表达式及嵌套集合。每个条目必须同时具有键、冒号和值，允许尾逗号，不允许逗号空位或 `{name}` 简写。裸标识符键按正常名称解析规则读取变量或常量，不隐式转成同名字符串。

```vela
const values: Map<string, int> = {
  selectedKey(): calculateValue(),
  'fallback': 0,
};
```

语句起始的 `{` 继续表示代码块。单独作为表达式语句的 Map 字面量须加括号，例如 `({'key': value});`。声明或赋值的右侧、实参和 `return` 之后已经处于表达式位置，可直接书写字面量。

Lambda 的 `=> {` 始终开始代码块，不根据预期返回类型或后续条目改判为 Map。表达式体直接返回 Map 时必须加括号；代码块体使用显式 `return`：

```vela
const makeMap: (int) => Map<string, int> = x => ({'key': x});
const makeEmpty: () => Map<string, int> = () => ({});
const makeMapWithBlock: (int) => Map<string, int> = x => {
  return {'key': x};
};
```

`=> {}` 是合法空代码块。格式化、增量解析和 REPL 使用相同规则，不把非法代码块自动恢复为可执行的 Map 表达式。

## 3. 类型检查与推导

### 3.1 有预期类型

存在 `Map<K, V>` 上下文时，每个键按 `K` 检查，每个值按 `V` 检查。别名先按现有规则解析；嵌套字面量、lambda 和泛型调用复用现有上下文与延迟推导，不建立字面量专用的第二套推导器。类型实参由上下文或条目推导确定，不新增 `<K, V>{key: value}` 这样的前置类型实参语法。`void` 不能用作键或值。

```vela
const items: Map<string, int[]> = {'first': [1, 2], 'empty': []};
const payload: Map<string, dynamic> = {'name': 'Vela', 'age': 7, 'active': true};
const nullableKeys: Map<string?, int> = {null: 1, 'name': 2};
```

`dynamic` 键和值沿用既有受检查转换及诊断策略。进入具体键值类型时不能依据运行时当前内容猜测类型，也不执行隐式数值转换。泛型定义中的字面量在抽象参数环境下检查，执行前再接入规范化的具体 Map 类型。

容器存储保持不变性。`Map<string, int>` 不因字面量语法获得到 `Map<string, dynamic>` 的隐式容器转换；显式 `Map<string, dynamic>` 字面量可以逐项接收整数值，并按已有 dynamic 值表示保留实际种类。

### 3.2 无预期类型

非空字面量的键类型和值类型分别按现有严格同类型规则确定。`{'name': 'Vela'}` 推导为 `Map<string, string>`，`{1: 'one', 2: 'two'}` 推导为 `Map<int, string>`。不同键类型或不同值类型不自动归并为 dynamic，`int` 和 `double` 不隐式合并；需要异构内容时提供明确的 `Map<K, V>` 上下文或显式 dynamic 值。

null 只能进入已经确定且允许 null 的键或值类型。无上下文时，null 不提供类型推断起点，也不把其它条目推断出的类型自动提升为可空类型，与现有数组元素规则一致。

空 `{}` 需要明确的 Map 上下文；缺少上下文时报告 `empty map requires an expected map type`。单独的 dynamic 上下文不确定 `K` 和 `V`，不能使空字面量自动变成 `Map<dynamic, dynamic>`。本设计不引入 Set 或匿名对象与空 Map 之间的推断歧义。

## 4. 求值、键语义与失败

每次求值先创建一个新的空 Map，再按源码顺序处理条目：求值键、完成键的受检查转换，求值对应值、完成值的受检查转换，然后插入该条目。每个键和值表达式只求值一次，当前条目完成后才执行后续条目。不为类型推导、容量计算或优化提前执行用户表达式。

Map 键相等性复用现有集合契约：字符串按内容比较，普通引用按对象身份比较，枚举按名义枚举类型及值比较；所有 NaN 视为同一个键，`+0.0` 与 `-0.0` 视为同一个键，null 与 null 相等。动态键区分运行时值种类，`1` 与 `1.0` 不是同一个键；不执行字符串化或数值类型转换。

允许重复键，后者覆盖前者的值，位置保持该键第一次插入的位置。即使键是可证明重复的常量，也必须保留各条目表达式的正常求值及副作用。

```vela
const result = {'first': 1, 'second': 2, 'first': 3};
// get('first') 为 3，keys() 的顺序为 ['first', 'second']。
```

每个字面量求值结果具有新的容器身份，包括空 Map。条目中的引用值按普通 `set` 规则共享，不复制子对象。`const` 仅限制变量重新绑定，不冻结 Map 内容。

键或值的求值、受检查转换、分配或插入失败时，后续条目不执行，构建中的结果不交付，已发生的外部副作用保留。异常与分配失败复用现有错误类型和执行状态，不增加字面量专用异常或回滚机制。

## 5. 前端与 IR

AST 使用独立的 Map 字面量表达式与有序键值条目，保留每个子表达式的源范围。模块绑定、AST 克隆、模板特化、捕获、初始化分析、控制流、语义索引和格式化均遍历键和值，不能通过字符串重解析或生成临时源码补齐语义。

类型检查器产出最终 `Map<K, V>` 类型、各键和值的类型及必要转换。lowerer 直接消费这些事实，不重新推导键值类型或决定是否接受异构内容。

构造复用现有 [`NewCollection`](../../compiler/ir/lowerer_collections.cc) 路径，再按条目顺序调用既有 Map 写入操作。目标 Map、键和值使用明确的临时值；转换和插入之间保留正确的异常后继与源位置。本设计不增加 Map 容量预留接口，也不通过反复创建、合并临时 Map 实现字面量。

优先复用现有集合操作、公共效果分析和定义/使用关系。若实现确需新增 IR 或编码，必须同时接通异常边、寄存器分配、字节码验证、镜像读写、原生发射和运行时符号，不能只在 VM 实现。

## 6. 资源与执行配置

构建中的 Map 和尚未插入的键值在每个可分配、可调用步骤精确保根。键必须跨对应值表达式的求值保持有效。扩容、getter、宿主调用或安全点之后重新取得可能失效的内部地址，不跨调用借用条目存储裸地址。

键和值表达式可以按既有 async 规则包含 `await`。挂起和去优化状态记录当前条目、已求值的键值及构建中的 Map；恢复后不重放已完成条目、键求值或用户副作用。

分配、扩容和键值存储沿用现有堆内存核算、GC 与写屏障。失败时释放临时根和构建状态，不交付半成品，不切换执行后端重试。分配消除仍须满足[逃逸分析设计](escape_analysis.md)对身份、可观察效果和恢复的要求。

VM、封闭 AOT、可重载 JIT 初始层与优化层必须提供相同的结果、顺序和错误边界。Map 仍是现有运行时类型；字面量不扩展函数调用签名或宿主 ABI。只有实际序列化布局发生变化时才更新对应格式版本，缓存构建身份和依赖指纹必须覆盖新的语法与语义实现。

## 7. 初始化、热重载与源码工具

Map 字面量是普通初始化表达式。局部变量、字段和全局变量使用已有初始化流程；全局惰性初始化失败、循环初始化与重试沿用[模块契约](modules.md)。

字面量随所属函数或初始化器版本化。旧帧和挂起续延使用原版本的条目与具体类型，新调用使用当前声明；Hot Reload 不重放已完成的全局初始化。声明类型变化按既有结构与存量依赖规则判断是否要求 Reload。

LSP 对键和值中的变量、类型、调用及成员访问提供正常的查询与重命名。字符串键是数据，不伪造成 class 成员；变量键则保留其真实符号身份。文档生成保留字面量的键值结构，不执行表达式。

格式化、语义 token、编辑器高亮与 REPL 多行输入须识别空字面量、嵌套条目和尾逗号。格式化表达式体 lambda 时保留必需括号，格式化后再次解析不得改变 Map 表达式与代码块的含义。

诊断至少覆盖缺少键、冒号或值，连续逗号，键值类型不匹配，null 缺少可空上下文，以及空 Map 缺少预期类型。错误位置落在对应键、值或分隔符；未完成输入和错误恢复不得静默丢弃条目后发布可执行结果。

Lambda 代码块开头若出现 `'key': value` 或变量键条目等 Map 字面量语法，报告 `map literal in a lambda expression body requires parentheses`，并给出 `=> ({'key': value})` 的修复示例。`=> {}` 仍是代码块，不能仅凭返回类型改判为空 Map。解构和 `...` 展开语法不作为本功能的一部分被接受。

## 8. 与 Dart 集合语法的关系

| 项目 | Vela 的取舍 |
| --- | --- |
| Map 字面量 | 采用 `{key: value}` 和尾逗号，结果为现有 `Map<K, V>` |
| 类型 | 保留严格同类型推断、容器不变性及显式数值转换；异构内容需要明确类型 |
| 重复键 | 按既有 `Map.set` 规则覆盖值并保留首次插入位置，各条目正常求值 |
| 空字面量 | 需要 Map 上下文，不推断 Set 或自动补 dynamic 类型实参 |
| 常量与初始化 | `const` 保持 Vela 的绑定语义，全局变量沿用惰性初始化 |
| 本次范围 | 仅增加 Map 字面量，解构、展开、Set 字面量及集合控制流元素暂不纳入 |

| 阶段 | 生产路径 | 完成条件 |

| M3：原生与状态 | AOT、JIT 两层、async、去优化、缓存、镜像及热重载 | 各执行配置一致，恢复不重放副作用，旧帧保持原版本语义 |

本设计的完成范围包含全部阶段及其生产路径，不以 parser 接受语法或一个 Map 测试通过作为完成。

### 9.1 正确性矩阵

- **解析**：空与非空 Map、嵌套 Map/数组、变量键和表达式键、尾逗号、语句块区分、lambda 的括号与显式 `return`、缺失键/冒号/值及未完成输入恢复；拒绝集合展开和新增解构语法。
- **类型**：明确上下文与无上下文推断、空 Map 缺少预期类型、嵌套上下文、可空键值、dynamic 转换、异构内容、拒绝 void 键和值、严格数值类型、容器不变性、别名、泛型定义及具体化。
- **顺序与错误**：键先于值、条目按源码顺序、每个表达式一次、重复键仍执行所有表达式、转换和插入失败后停止后续条目、外部副作用保留；跨 `await`、异常和去优化不重放。
- **键语义与资源**：字符串、引用身份、名义枚举、NaN、正负零、null 和动态数值种类；覆盖值与首次插入位置；新容器身份、共享引用值、高压 GC、扩容及真实分配失败边界。
- **状态与工具**：局部、字段和惰性全局初始化，初始化失败重试与循环初始化，旧帧和续延的版本，变量键重命名与字符串键保持，格式化幂等、REPL 多行及跨模块查询。
- **生产交付**：AST 克隆、模块绑定、捕获及初始化分析、字节码恢复、代码缓存、宿主具体类型边界和独立原生分发；回归现有 Map API、数组字面量、Map 遍历与普通调用。

正常语义对照 VM、封闭 AOT、可重载 JIT 初始层与优化层。分配失败按各配置真实存储边界断言，不要求执行相同次数的不可观测分配。

### 9.2 性能与文档同步

Release 基准覆盖空、小型和大型 Map 字面量、重复键、动态键值及嵌套引用，保留等价的 `Map<K, V>()` 加逐项 `set` 作对照。分别记录编译成本、执行耗时的中位数与波动、分配量、GC、寄存器/帧和代码体积。

构造 n 个条目应使用现有哈希索引与几何扩容，插入成本均摊 O(n)；字符串键另计其哈希读取的字节数。不接受通过反复复制累计结果形成的 O(n²) 构造路径。

中英文 [`core_language.md`](core_language.md)、[`json.md`](json.md)、[类型推导](type_inference.md)、[源码工具](source_tooling.md)及集合示例已同步。JSON 继续映射为原生数组和 Map，字面量不改变 JSON 数字、null 或业务对象构造语义。

Windows x64 验收覆盖 Debug、Release 各 2,199 个 C++ 测试，182 个工具与独立发行测试、445 个 AOT/VM 程序对照，以及 659 个 C++ 文件的静态检查。原生宿主验证包括真实分配/插入失败和具体 Map 类型通过公开 ABI 的生命周期与类型边界。

[`maps/` Release 基准](../../benchmarks/README.md)覆盖六种形状、两种写法、四个执行配置的编译与执行，共 96 个用例，各重复 7 次。[滚动汇总](../../benchmarks/results/rolling_summary.json)保留命令、源码身份、中位数、波动和计数器。字面量与等价 API 写法的执行侧采样分配、寄存器/帧及根槽指标一致，VM/JIT 报告的执行代码规模也一致，回收后的额外存活量均为零。单独编译的 AOT 对象包含源码等元数据，大小比约为 0.977–1.000。执行耗时比为约 0.915–1.259；最短用例的波动较大，不据此宣称速度优势。分配字节表示禁用自动 GC 的单次执行所增加的活跃堆存储，包含遍历快照，不包含扩容中已释放的旧存储或分配器记账。
