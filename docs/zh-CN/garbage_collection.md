# 垃圾回收架构

[English](../en/garbage_collection.md) | [**简体中文**](garbage_collection.md)


Vela 采用精确、非移动式、增量标记清除（incremental mark-and-sweep）垃圾回收器。
运行时在内存分配过程中以协作方式推进垃圾回收，避免长时间的 Stop-The-World（STW）停顿，
同时保持可预测的单线程执行模型与紧凑的内存占用。

## 回收器架构

回收器采用受 Luau 等系统启发的增量标记清除架构：

- **精确根追踪（Precise Rooting）**：回收器精确追踪所有活跃引用。根集合涵盖活跃调用栈帧中的虚拟机寄存器（`RootRange`）、全局与模块变量表、字符串与常量池以及宿主托管的根句柄，不存在任何保守栈扫描。
- **三色标记（Tri-color Marking）**：对象在逻辑上分为白色（未访问/不可达）、灰色（已发现但子引用尚未扫描）和黑色（已访问且子引用已完全扫描）。
- **增量切分（Incremental Steps）**：回收器将完整的标记和清除周期划分为多个小步长 `Step`，在变异线程（mutator）进行内存分配时交错执行，避免一次性停顿。
- **写屏障（Write Barriers）**：当黑色对象被赋予指向白色对象的引用时，写屏障（前向或后向屏障）介入以保持三色标记不变式。基本类型数值（整数、浮点数、布尔值）的写入绕过写屏障。
- **非移动式分配（Non-moving Allocation）**：对象在其整个生命周期中保持固定的堆地址。这消除了对象移动重定位指针的开销，并显著简化了 C++ 原生嵌入与宿主对象交互。

## 分代权衡与设计决策

Vela 在基础回收器中明确未引入新生代（nursery）与记忆集（remembered set）：

- 分代垃圾回收在严格满足弱分代假说（多数对象朝生夕灭）的负载中具有显著优势。然而在对象存活率较高或长寿命对象图频繁更新的场景下，分代机制带来的额外开销（如卡表、记忆集、老年代到新生代写屏障以及主/次 GC 节奏协同）可能反噬性能。
- 引入新生代需要对所有对象引入代龄元数据、对象晋升策略以及更复杂的变异线程写屏障。
- 保持统一的非分代增量收集器能够最小化对象头开销，避免双模式回收器的系统复杂度，并在各类混合负载下提供更加平稳、可预测的延迟表现。

## 步长预算与调度机制

垃圾回收工作以协作方式进行预算切分与调度：

- **预算单位**：`Step` 步长预算以标记或清除的离散对象数量为单位，不依赖不可靠的 CPU 时间戳或墙钟纳秒计时。
- **回收配速（Pacing）**：随着内存分配压力的增加，虚拟机按分配字节数的比例推进增量 GC 步长，确保在达到堆内存阈值前完成回收，而无需中断主程序执行。
- **原子操作限制**：标记阶段结束时的根集合重扫（root rescan）以及扫描单一巨型数组或集合目前是单步内的原子操作。如果系统需要严格的亚毫秒级步长，未来必须支持对巨型连续缓冲区的分片增量扫描。
- **线程归属**：所有 GC 步长、根扫描和清除操作均严格在所属 `Isolate` 的主线程上同步执行。多线程宿主通过消息队列跨 Isolate 通信，禁止跨线程传递裸 GC 指针。

## 写屏障与字段更新契约

- **引用写入**：向对象字段、数组元素或闭包捕获槽写入堆引用会触发 GC 写屏障。屏障通过染灰目标对象或待赋新值来维持三色标记不变式。
- **基本类型写入**：整数、浮点数、布尔值和 null 的写入完全绕过写屏障，允许热路径上直接执行寄存器到内存的原生存储。
- **栈帧复用安全**：被复用的寄存器栈帧在注册前统一清空引用标记，防止先前调用留下的过期引用导致对象被错误保活。

ByteArray 将对象头和固定原始字节放在同一次、计入核算的堆分配中，按叶对象追踪，不扫描字节内容寻找引用。ByteData 在发布前初始化所有者强引用，空视图也追踪并保活完整所有者；字段、闭包、强类型容器、Expected 或挂起异步栈帧引用的视图沿用同一路径。详见[字节所有权契约](byte_data.md#所有权修改与-gc)。

## 验证与正确性契约

垃圾回收的正确性与内存不变式通过以下机制持续验证：
- 严格存活断言：合成对象图和端到端测试在每个回收周期后核验活跃对象数量是否与理论可达拓扑严格一致。
- 高压模式（GC Stress）：在每次分配时强制推进增量步长，验证根集合覆盖的完整性与写屏障的健壮性。
- 宿主边界核验：确保宿主持有的外部句柄、异常展开路径以及虚拟机上下文销毁时能正确释放或追踪 GC 资源。
