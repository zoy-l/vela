# 原生 AOT 编译设计

[English](../en/aot.md) | [**简体中文**](aot.md)

> 状态：A2/A3 原生执行及 A4 的 `exe`/`obj`/`staticlib` 接口已实现。Windows x64 的 Debug/Release 回归、仅链接原生运行时的宿主测试、显式 SDK 发行包测试、静态检查及 Release 测量已通过。Linux/macOS 目标包和干净主机验收仍未完成，因此 A4/A5 尚未全部验收，不宣称三平台正式发行已获认证。

Vela AOT 从共享的 Typed IR 生成原生目标文件，通过随工具链分发的链接工具生成可执行文件或静态库。LLVM 作为编译器内部依赖集成；使用官方发行包的用户无需单独安装 Clang 或 LLVM。生成的程序依赖 Vela 运行时和目标平台库，不依赖 LLVM、Vela 编译器或字节码解释器。

本设计覆盖源码编译、原生执行、GC、异常、异步、宿主嵌入、链接与发行。语言语义以现有各主题契约为准；AOT 不定义第二套语言行为。系统 SDK 的获取与许可要求独立于 LLVM 的打包，不能把“无需安装 LLVM”解释成“所有平台都不需要系统 SDK”。

## 用户接口与范围

独立程序构建接口：

```sh
vela build main.vela -o app
```

库入口文件可以导出宿主调用的函数：

```vela
export func add(left: int, right: int): int {
    return left + right;
}
```

```sh
vela build math.vela --emit=obj --export=add -o math.o
vela build math.vela --emit=staticlib --export=add -o libmath.a
```

`--emit` 默认是 `exe`，另外接受 `obj` 和 `staticlib`。`--export` 可重复，按入口模块的公开顶层函数选择原生导出；它不改变语言内的 `export` 可见性规则，不隐式导出导入模块，也不允许直接导出尚未具体化的泛型函数。类型检查仍覆盖加载的源码；导出选择不能隐藏非法源码。

可执行文件使用现有无参 `main` 契约，沿用同步或 Future 结果、退出码、未处理错误和 `AsyncIdle` 行为。库不要求 `main`，实例化不执行用户入口函数。目标文件覆盖入口文件的完整导入图；静态库封装同一编译单元，不表示各 Vela 模块可以独立二进制链接。

库产物同时生成 `<输出路径>.h` 和 `<输出路径>.aot.json`，提供导出包装声明与链接清单。Windows 的目标文件、静态库与可执行文件分别使用 `.obj`、`.lib` 与 `.exe`。路径示例不规定跨平台文件后缀转换规则。

构建工具消费库之前，可以运行 `vela build --verify-manifest=math.o.aot.json`，检查目标、运行时和工具链身份、二进制与头文件指纹，以及发布代次；混用或修改过的文件会被拒绝。清单记录 generic CPU/PIC 代码生成、优化等级、函数帧与根槽成本、签名，以及可用时的配套目标支持身份。

可执行文件和归档构建从安装的编译器相对路径读取 `share/vela/target.json`，也可用 `--target-support=FILE` 显式选择配置。仅生成目标文件时，不需要最终 SDK 或链接输入。配置通过 SHA-256 固定包内工具与运行时，并记录 SDK 版本、来源、许可、必需输入和链接参数；不从 `PATH` 选择工具。

开发者可以运行 `python -m tools.vl package release OUTPUT` 创建 Windows 开发包。清单提供精确的 MSVC、Windows SDK/UCRT 版本及安装说明；按清单将 `VELA_MSVC_TOOLS` 设为带版本的 MSVC 工具目录，将 `VELA_WINDOWS_SDK` 设为 Windows Kits 根目录，无需 Visual Studio IDE。SDK 链接输入保留在外部。其他主机目前需要通过经过审计的 `--support-spec` 描述 SDK/sysroot 输入及随包文件，仍须完成各平台验收。

首期支持本机编译本机，目标发行矩阵与现有引导主机一致：Windows x64、Linux x64、macOS arm64；每个平台必须独立通过发行验收后才能宣称支持。本 AOT 交付范围不包含原生动态库装载、跨发行版本 ABI 兼容、独立模块二进制分发或 VM/AOT 相互调用；JIT 与热重载由[开发模式](hot_reload.md)提供。REPL 和现有 VM 调试器继续服务字节码路径。未支持的 AOT 操作必须明确报错，不能执行内嵌字节码兜底。

## 共享实现与 AOT 职责

| 共享实现 | AOT 职责 |
| --- | --- |
| [IR](../../compiler/ir/ir.h) 使用 32 位虚拟寄存器 ID，携带类型、源码位置及异常处理器；[公共分析](../../compiler/ir/analysis.h)提供指令效果和异常/恢复边活跃性 | 按值定义的类型事实生成类型化原生值与根槽，原生能力不受字节码字段宽度限制 |
| [编译准备](../../compiler/ir/preparation.cc)离线完成前端、布局描述与公共优化，返回不借用 AST 或 Isolate 的 IR；VM 分配和编码位于独立后端 | 从同一 IR 分流到共享 LLVM lowering 与代码生成 |
| [布局实例化](../../runtime/program_layouts.cc)消费无指针描述表；绑定检查消费具体签名 | 原生实例复用布局实例化，拥有原生导入表、常量根池与全局状态 |
| [NativeFunction](../../runtime/native_function.h) 由 C++ 签名生成 VM 与原生入口 | 复用声明和类型编解码规则，按签名选择直接或受检查的 AOT 入口 |
| [Future 调度器](../../runtime/future.h)拥有共享状态和调度语义；VM 拥有字节码挂起帧与执行器 | 使用原生续延与原生回调入口，不依赖 VM 执行器 |
| [GC](garbage_collection.md)提供精确根、非移动堆和引用写屏障 | 生成原生根槽和安全点，复用堆与屏障，不使用保守栈扫描 |

这些生产路径已接通；目标支持包与发行验收的剩余范围见本文状态和完成条件。

## 编译管线与模块职责

```text
源码及导入图
  → 解析、模块绑定、泛型特化、静态检查
  → Typed IR、公共优化
      ├─ VM 寄存器分配 → 字节码编码 → VM
      └─ AOT lowering → LLVM IR → LLVM 优化与目标代码生成
                              → 目标文件 → 归档或链接
```

`compiler/frontend` 负责语言语义，`compiler/ir` 负责共享 lowering、控制流及语义优化。`compiler/native` 为 AOT 与 JIT 提供共享 LLVM 转换、根槽规划及原生 ABI 调用；`compiler/aot` 负责封闭程序优化、导出和目标文件生成，构建驱动负责平台选择、链接、归档及产物发布。LLVM 头文件和类型留在编译器的原生后端内，runtime 不依赖 LLVM。

`runtime` 提供对象、GC、Future、错误与执行所需的公共服务；原生执行支持负责程序实例、原生调用及源码追踪。它们不得依赖 frontend、IR、LLVM 或 VM。CLI 可以同时链接 VM 与 AOT 编译后端，纯 AOT 应用只能链接其实际执行所需的运行时组件。现有 `Compile*` 返回 VM 程序的接口继续服务 VM；AOT 不复用这一路径创建一个无用途的临时 VM 程序。

当前 IR 是可重复赋值的虚拟寄存器指令表示，不是已经完成 SSA 转换的 LLVM IR。AOT lowering 必须为定义、块合流和循环构造正确的 SSA 值或可提升的类型化局部槽；异常后继和 await 恢复边同样参与数据流分析。完整类型、空值形状、函数签名和引用种类必须由上游明确提供，不能从字符串类型名或 VM 运行值猜测。

共享 IR 的操作事实需要涵盖是否可能失败、分配、触发 GC、调用宿主和挂起，供优化、活跃性与两个后端消费。扩充现有分析的责任范围，不为每个后端维护一份语义不一致的操作表。当前无法证明无 GC 的调用按可触发 GC 处理；只有经契约证明的叶操作才能省略保根。

移除公共路径对 8 位操作数、256 个物理寄存器和字节码跳转距离的依赖。VM 继续在自己的分配和编码边界诊断这些限制。AOT 的原生栈、目标格式和元数据容量限制单独诊断，不能把所有限制都删除后交给 LLVM 崩溃。

## 值表示与原生 ABI

普通局部 `int`、枚举序号、`double` 和 `bool` 分别使用 64 位整数、64 位整数、binary64 与布尔表示；非空引用使用非移动堆指针。可空基本值携带独立的有效性信息，不能占用一个合法数值作哨兵。堆字段、数组、动态值、闭包捕获与运行时类型身份继续遵循现有对象模型。局部去装箱不等于修改堆布局。

函数描述标记需要在运行时边界盒装的枚举标量结果，其他结果直接跳过盒装分派。原生值编解码只复制共享的载荷与标签前缀，保留载荷位模式，并在编码时将 ABI 保留字段清零。

堆内 `Value` 槽采用显式的 16 字节载荷与标签表示，由 C++、GC 和生成代码共用。AOT 通过 `NativeMemoryLayout`、`sizeof` 与 `offsetof` 获取偏移，不读取标准库 variant 的私有表示。基本值数组继续使用紧凑元素存储；可空基本值和动态元素使用标签槽，引用使用指针槽。运行时 ABI 指纹覆盖这些布局定义，拒绝混用不同构建的产物。

数组访问指令保留降低时确定的数组布局编号。临时值擦除为 `dynamic` 只改变寄存器表示，不能丢失初始化或读取数组所需的元素存储事实。读写操作在该存储形状与目标或来源寄存器表示之间转换。

原生调用区分三个边界：

| 边界 | 契约 |
| --- | --- |
| 编译单元内部 | 类型化参数与结果；隐藏执行上下文携带程序实例、Isolate 和执行状态。该调用约定由编译器私有控制 |
| 生成代码与运行时 | 版本化的内部 ABI，明确固定宽度字段、指针、布局、对齐、结果与错误通道；不依赖 C++ 名字修饰或标准库对象布局 |
| 宿主导出/导入 | 生成的 C ABI 包装层及 C++ 类型安全外观；原始机器码入口不直接作为公共 C++ 函数发布 |

导出包装使用显式实例参数、状态结果和成功值输出。基本类型使用固定宽度表示；字符串、对象、Future 等托管结果通过带 Isolate 归属的保根句柄交付，宿主显式释放。复合值的结构签名仍参与检查，不把对象内部布局暴露为宿主结构体。公共包装不得暴露 `std::string`、`std::expected` 或 `std::shared_ptr` 的二进制布局。现有 VM 的借用结果接口保持其原有契约，不能把借用值误当成新的保根导出结果。

原生执行支持维护逻辑调用帧和源码位置，使错误栈与机器寄存器分配无关。沿用当前调用深度策略和 `StackOverflow` 状态，在进入下一层脚本调用前检查；内联不能意外改变可观察的深度与追踪行为。原生帧大小必须受控，大型暂存通过可返回失败的运行时存储管理，不能让用户源码造成无检查的原生栈耗尽。帧及根记录在正常、错误和挂起出口统一清理。

逻辑帧位于原生栈上，在执行上下文中组成链表。生成代码直接登记位置和深度，标量调用不构造资源帧。小型帧在局部值与暂存区共用的大小预算内使用栈上根槽；大型存储仍显式报告分配失败。类型化局部槽与地址会传给运行时的 ABI 暂存区保持分离，使 LLVM 能将局部值提升为 SSA。调用、显式 throw 和异步边界在进入运行时前发布位置，纯检查只在失败分支记录位置。

栈上根直接登记到现有 `RootRange`，不构造拥有堆存储的资源帧。大型帧由资源帧拥有分配的根区和暂存区，并显式处理分配失败。生成代码直接写入和清空根槽，异步恢复也使用同一路径，不逐槽调用运行时。这些地址在嵌套调用期间保持稳定，直到对应帧退出后失效。逻辑帧独立于资源存储，保持相同的调用深度额度和异常栈。

返回标量、栈存储有界、没有异常处理器且成功路径没有 GC 安全点的函数，在入口直接检查调用深度，只在失败时实体化逻辑帧。这类函数可以读写字段、数组和全局槽。失败时，生成代码将活动引用紧凑写入栈槽；失败 helper 在分配异常封套前登记这段根区，并在退出时一并释放根记录和临时逻辑帧。全局读取仅在没有托管局部值需要跨惰性初始化保根时适用，初始化 helper 会临时登记调用者逻辑帧。延迟传递的位置使用 64 位标量，高 32 位为函数编号，低 32 位为指令编号；失败检查与惰性全局读取均不生成位置全局变量。原生 ABI 版本 2 覆盖这些标量 helper 签名，旧对象文件需要重新编译。其他函数继续在整个执行期间登记逻辑帧。入口准备仅在最外层调用清理上次失败状态。

当前函数内创建的普通函数值和闭包，若单一定义及复制链能确定其不可变目标，且实参与结果类型匹配，就直接调用类型化函数体。闭包仍传递隐式捕获对象。来自参数、全局槽、字段或可能被重写局部变量的函数值，继续由运行时解析目标及来源实例。直接调用保留逻辑深度检查、错误位置、捕获和回调副作用。数组回调结束后直接比较接收者的结构版本，快照排序和稳定的等值顺序保持现有契约。

## GC 根、安全点与写屏障

首期采用显式影子根槽，复用 `RootRange` 和现有带标签的 `Value` 根存储。只有跨安全点存活的托管引用需要根槽；纯数值留在机器寄存器或普通局部槽。注册的槽必须含有有效值：普通帧先初始化为空，延迟登记的叶函数失败根区只包含紧凑排列的活动引用。函数退出前注销根区。槽位可按引用活跃区间复用，引用死亡后清空，不因整帧存活而长期保留已无用途的对象。

安全点包括可能分配或推进 GC 的运行时调用、可能进入此类操作的脚本调用以及宿主调用。运行时仍在 Isolate 所属线程协作推进 GC；纯算术循环不引入异步收集或新的任务调度点。若以后增加显式轮询，必须进入相同效果与根分析。

公共效果信息区分成功路径收集与错误封套分配。只有失败时才可能触发 GC 的指令，在失败块创建封套之前写入活动根；成功路径不为该指令写入根槽。

生成代码必须满足以下顺序：

1. 在安全点前写入全部存活引用，包括实参、调用接收者、闭包环境、待定异常与 finally 保存的返回值。
2. 根登记与实际调用之间不能出现未计入分析的分配。运行时 helper 接收借用引用时，调用方根必须覆盖 helper 的整个执行。
3. 被调用方返回引用后，调用方在下一次安全点前将其放入已注册根槽。被调用方释放根到调用方接收结果之间不得触发 GC；宿主导出包装负责在返回前完成保根句柄交付。
4. 只有当续延状态已由可达 Future 图追踪，挂起路径才能注销原生帧根。

根槽地址及注册记录必须对 GC 扫描可见。LLVM 的别名、内存效果及调用属性必须准确建模；不得给可能观察根槽的 helper 标记错误的 `readnone` 等属性，也不能让优化器删除或跨安全点移动保根写入。GC 压力验证必须覆盖优化后的机器码。

对象字段、引用数组、集合、全局槽、捕获单元和续延引用的更新全部经过现有写屏障契约，覆盖标记与清除阶段。类型化字段、数组和全局槽访问生成直接读写；全局赋值直接将槽标记为 Ready，不执行初始化器。数组保留同时拒绝负数和超长索引的无符号边界检查，非空托管引用写入仍调用共享 GC 屏障，空值和标量写入无需屏障。数组追加在容量充足时直接写入，容量不足时使用现有堆扩容操作，并在扩容后重新读取缓冲区指针。非移动对象不意味着可增长数组的底层缓冲区永不移动，元素地址不能跨可能扩容的调用保留。

单元素 `push(value)` 直接降低为两个后端共用的标量追加操作，不再分配单元素临时数组；多元素追加继续保留实参求值顺序和批量插入。

这些做法参考 [Luau 原生代码生成](https://github.com/luau-lang/luau/blob/master/CodeGen/src/IrLoweringA64.cpp) 中显式的内存操作。进一步消除边界与溢出检查需要类似 [Go SSA 分析](https://github.com/golang/go/blob/master/src/cmd/compile/internal/ssa/prove.go) 和 [Dart 范围分析](https://github.com/dart-lang/sdk/blob/main/runtime/vm/compiler/backend/range_analysis.cc) 的范围与控制流证明。整数溢出检查、失败位置、可观察写入和逻辑调用深度都是语言契约，启用 LLVM 优化本身不能提供这些证明。

不引入保守栈扫描、LLVM stack map 或第二套 GC。以后替换保根机制须有 Release 基准支持，并完整替换受影响路径。

## 数值、失败与异常

AOT 保留现有受查整数溢出、除零、索引、类型转换、字符串与容器失败行为。LLVM 整数运算不能把语言错误变成 poison/未定义行为；除法在执行前检查零除数及有符号溢出，移位和转换按语言契约 lowering。浮点数保持 NaN、无穷、次正规数和有符号零，以及 Vela 的浮点除零错误；默认禁止 fast-math 和会改变这些行为的重写。

Release 优化在 LLVM SSA 上分析整数循环。严格有符号边界下的单位递增、递减不会越过 `int64` 端点，可删除该步的溢出检查。对无副作用的单累加器循环，若累加项在整个循环中同号或保持不变，使用 `i128` 精确累加，并在正常出口检查最终结果能否表示为 `int64`；随后由 LLVM 的循环优化计算出口值并删除循环。宽运算本身的范围证明覆盖最多 `2^64-1` 次迭代，不依赖最终检查。零次循环保留初值，失败沿用原累加语句的错误与源码位置。跨零且无法证明前缀安全的归约、其他可能失败的运算，以及在异常路径可观察中间状态的循环保留逐次检查。

严格计数循环中的字段单位增减，在对象保持不变且没有其他可观察操作时可以折叠。归约以 `i128` 计算最终值；若溢出，先写回最后一次成功的 `int64` 边界值，再进入原失败块，因此别名和 finally 仍观察到相同的字段修改前缀。暴露中间索引或包含其他副作用的循环保留逐次执行。

首期使用显式状态传播，不使用 C++ 异常或 `longjmp`。可能失败的调用返回状态与成功载荷，异常载荷由受 GC 追踪的异常封套持有。调用者按 IR 的异常后继跳转至 handler，或清理本帧后继续向外返回。只有证明不会失败的内部调用可以省略错误通道。

[异常契约](exceptions.md)规定的 catch 类型顺序、finally 覆盖待定完成、原始抛出栈保留、显式重抛起点和惰性初始化失败回滚全部保持。错误封套的分配失败直接返回 `OutOfMemory`，不得递归尝试创建另一份错误。成功路径不分配异常或追踪对象。

## 程序映像、实例与模块状态

AOT 产物包含机器码、不可变描述表和重定位信息。描述表记录函数和类型身份、字段与分派定义、UTF-8 字符串字节、浮点位模式、原生导入、全局初始化器与源码位置。不得嵌入编译进程中的堆指针、Isolate 地址、C++ 对象快照或宿主回调地址。

同一份只读代码可以被多个 Isolate 使用；每次实例化创建独立的布局绑定、字符串根池、原生导入表和全局状态。同一实例的句柄共享这些状态，新实例不共享。代码身份与程序内类型 ID 联合确定名义身份，避免不同编译单元碰撞；继承和接口分派继续使用已解析的槽位。

实例化先验证目标与 ABI、解析全部原生导入、建立布局，再在注册根后分配常量。完全成功后才发布实例句柄；失败释放临时根、常量和布局事务，不留下半可用实例。用户全局变量仍按[模块契约](modules.md)惰性初始化，保留 `CyclicInitialization` 与失败重试语义，不迁移为进程启动时的 C++ 静态初始化。

生成的全局读取检查实例持有的定长初始化状态，Ready 值直接从现有 GC 槽按类型读取；其他状态调用运行时初始化器，初始化失败恢复为 Uninitialized 以便重试。全局写入继续经过共享写屏障，完成后发布 Ready。各路径的偏移取自 C++ 布局事实，不暴露标准库容器布局。

外部实例/函数句柄持有必要的代码描述和根；异步内部引用通过 Future 图追踪全局槽与常量，不为不可达挂起任务建立永久外部根。Isolate 必须晚于实例、托管句柄、续延和原生生产者销毁；销毁及根操作在所属线程执行。首期代码静态链接到进程，不提供运行时卸载。

## 宿主绑定与动态调用

`external func` 的源码声明足以进行离线类型检查和生成导入记录。编译库时不要求运行宿主或创建 Isolate。实例化使用逻辑符号及精确签名一次性绑定到已注册的宿主实现，缺失或不匹配时拒绝发布实例。每次原生函数调用在入口缓存直接使用的不可变 import 目标和调用约定，循环内复用。LLVM 可将直接调用与可失败调用的选择移到循环外。

`NativeFunction::Bind` 的签名描述与编解码规则是 VM 寄存器适配器和类型化 AOT 入口的共同来源。宿主函数可带有或省略首位的 `NativeContext&`。普通标量结果通过寄存器返回，标量 ABI 完全一致时保留原 C++ 函数指针，布尔及托管参数经 ABI codec 转换。可失败或托管结果使用带状态传播及调用方输出槽的检查入口。两种调用约定都保留逻辑栈帧、深度限制和 GC 根。AOT 不构造 VM 参数窗口；原生失败、UTF-8 验证、Future 载荷验证及所属线程规则继续共用。

独立可执行文件的启动支持只注册发行包提供的标准绑定；首期构建时拒绝需要自定义宿主绑定的可执行文件。此类应用生成库，由宿主注册绑定后实例化。未来若增加宿主对象文件输入，必须同时定义注册入口和签名清单，不能仅凭系统链接器找到了同名符号就接受绑定。

闭包、绑定方法、接口调用、动态成员访问和 Future 回调必须能调用原生目标。代码身份和签名检查复用公共元数据，执行入口由原生后端提供。死代码删除必须从选定导出、main、初始化器、可达类型的动态成员、闭包及异步恢复入口计算可达性；不能只沿静态直接调用边删除代码。首期不允许把 VM 函数值作为 AOT 回调，相关宿主输入在边界明确拒绝。

内部的 `dynamic` 值和签名本身不会保留所有类方法。跨选定导出或原生导入的动态约束沿字段、数组、集合、回调和 Future 载荷传播。宿主可能携带的未知值，以及解析任意动态调用的操作，继续保守保留其成员调用范围。函数和成员剪枝保持类型及布局编号稳定。

## 异步 lowering

复用现有 `FutureScheduler`、Future 状态、宿主消息队列和 timer。AOT 将 async 函数编译为初始执行入口及按恢复状态分派的原生续延；续延保存代码/实例身份、恢复编号、活动局部值、异常处理状态及 await 来源。恢复编号指向生成的原生块，不是字节码 PC。

首次 await 前立即执行函数体；无 await 的完成不创建挂起帧。每个 await 都是异步边界，包括普通值和已完成 Future。续延排队、通知次序、Future adoption、错误处理、取消与 idle 行为严格沿用[异步契约](async_tasks.md)。await 的失败边也参与活跃性，跨 await 的 catch/finally 必须保存待定异常或返回值。

挂起只保存恢复所需的活动状态，GC 精确追踪引用，调度器沿用挂起帧数量与保存字节统计。可复用现有 Future 引用追踪机制，但不能通过捕获永久保根句柄让不可达任务循环无法回收。恢复时先建立原生根，再释放或更新续延保存状态；恢复一个任务不扫描整个程序。

首次挂起创建一个结果 Future 和一份按最大挂起点确定容量的固定激活存储，后续 await 复用二者；返回普通值或失败时直接完成该结果。返回另一 Future 时仍保留 adoption 边界。恢复代码按共享 ABI 布局读取保存值，常量直接重建。已由 async/import 生产者保证的结果类型可消除基本块内的重复绑定。激活所有权由可达 Future 引用和排队监听器持有，不可达的待定任务图仍可回收。

位于 VM 执行层的 Future 组合操作需要按责任拆分：组合与调度语义移入可由两后端调用的运行时服务，字节码帧恢复留在 VM，原生帧恢复属于 AOT。不能复制一套 Future 语义，也不能让原生续延调用 VM 执行器。

## 目标文件、链接与版本身份

默认生成本机架构的基线指令集，不自动采用构建机器特有 CPU 指令。目标描述必须明确对象格式、调用约定、数据布局、重定位模式、最低系统版本及运行时变体。共享部署所需的可重定位代码由目标配置决定，不能由宿主编译器默认值碰巧决定。

目标文件内嵌描述表和实例化入口；JSON 清单只供构建工具使用，运行时不依赖旁置文件。清单记录格式版本、编译单元身份、工具链构建身份、运行时 ABI 身份、目标、导出/导入签名、所需库与链接顺序。静态库不嵌入第二份 Vela 运行时；宿主最终链接一次匹配运行时，显式引用实例化入口以防归档成员或描述表被裁剪。

首期使用完全匹配的运行时 ABI，不承诺跨版本兼容。ABI 身份覆盖生成代码可观察的对象布局、根协议、helper 签名、调用及异常协议；LLVM 版本和优化选项另外进入工具链构建身份。版本化链接符号及实例化边界检查拒绝不匹配产物，不在每次函数调用中重复验证。多个编译单元不得合并不同 ABI 的运行时或共享未经检查的布局。

链接驱动使用绝对路径调用随包工具，结构化构造参数或响应文件，正确处理 UTF-8 路径。它根据目标配置提供启动对象、运行时、系统库和必要的 C/C++ 支持库，不需要 Clang 充当驱动。先在临时位置完成目标文件与链接，再发布产物；编译或链接失败不覆盖有效旧产物，单文件发布采用原子替换。库及其头文件/清单以清单最后发布并携带一致性身份的方式交付，消费端拒绝混合构建代次，不宣称多个文件能一起原子重命名。发布途中发生 I/O 错误须明确报告；可能出现的混合文件不能被当作成功构建使用。

首期不新增持久化 AOT 编译缓存；[字节码缓存](compilation_cache.md)不用于原生代码。以后新增缓存必须覆盖源码/导入解析、完整工具链身份、目标/CPU、优化、运行时 ABI、SDK/链接输入及导出集合。LLVM bitcode 不是公开的跨版本分发格式。

## 工具链发行与系统依赖

```text
发行包（逻辑组成）
  bin/vela                    编译器，静态集成所需 LLVM 后端
  libexec/                    固定版本的链接器与归档工具
  lib/<target>/               Vela 运行时、启动支持及可分发依赖
  include/                    嵌入接口与 ABI 包装声明
  share/vela/                 目标配置、构建身份与许可证
```

LLVM 与 LLD 版本随发行包固定，只包含该发行矩阵所需后端。用户构建 Vela 源码时无需 Python、GN、Ninja、LLVM 开发包或 Clang。开发 Vela 编译器本身仍沿用现有 [DEPS/GN/vl 工具链](toolchain.md)；新增依赖及许可证记录纳入同一路径，不修改用户全局 PATH。

| 平台 | 随包提供 | 外部平台前提 |
| --- | --- | --- |
| Linux x64 | LLVM 集成、ELF 链接/归档工具、Vela 运行时及启动支持 | 发布时固定支持的 libc/sysroot 基线；许可允许的启动文件和链接库随目标支持包提供，并在无开发工具环境验收 |
| Windows x64 | LLVM 集成、COFF 链接/归档工具、匹配的 Vela 运行时 | 明确 Windows SDK、UCRT 及所选 C++ 运行库的来源和最低版本；不能假定安装了 Visual Studio 或 Clang |
| macOS arm64 | LLVM 集成、经验证的 Mach-O 链接/归档工具、Vela 运行时 | Apple SDK 与平台要求的签名工具；通常通过 Apple Command Line Tools 获取，即使其包含 Clang，Vela 也不调用其编译前端 |

目标支持清单必须记录每项系统输入由发行包提供还是由 SDK 提供、定位方法、支持版本和分发许可。SDK 可以显式配置，或通过平台规定的位置发现；不得静默换用 PATH 上其它编译器/链接器。缺失或不受支持时，在编译前诊断并给出安装/配置路径。没有通过该平台 SDK、链接、签名及干净环境验证的发行包不得标为正式支持。

发行维护者通过 `--support-spec=FILE` 提供已审计的 SDK/sysroot 配置。JSON 指定 `target`、`minimum_os`、`object_format`、`runtime_variant`、`application_dependencies`、`archive_arguments` 和 `link_arguments`。每个 `external_roots` 项记录 SDK 根目录名称、环境变量、精确版本、来源、许可证及安装说明；每个 `files` 项记录展开路径、SHA-256、用途、来源、许可证及分发条件。可选的 `bundled_files` 项包含相对配置文件的 `source_path`、包内相对路径 `destination`、来源和许可证，由打包工具复制并计算指纹。参数可使用 `{package}`、具名 SDK 根目录、`{object}`、`{output}` 和 `{runtime}`。用途为 `link` 的 SDK 文件仅在生成可执行文件时必需；目标文件和归档输出不依赖最终 SDK 输入。

发布包目录前，打包工具使用暂存包内的编译器及声明的 SDK 输入构建、运行异步原生程序，并清除构建工具和库搜索环境变量。缺少链接输入或运行时 ABI 不匹配时，拒绝发布且不留下已发布目录。该检查确认包在本机可用；各平台仍须完成完整发行验收矩阵。

各主机配置好 SDK 后，用 `VELA_TEST_TARGET_SUPPORT_SPEC` 为 `python -m tools.vl test release tooling` 指定上述审计配置。发行测试会清除构建工具环境变量，覆盖含中文和空格的路径、VM/原生程序对照、两个库共享同一运行时、不一致发布拒绝，以及删除源码与发行包后再次运行产物。Windows 也可使用内置开发 SDK 探测。跳过某平台测试不代表该平台发布验收通过。

只生成目标文件不需要最终系统链接输入。宿主选择将 Vela 库嵌入 C++ 应用时仍需要自己的 C++ 开发环境，这与编译 Vela 源码不要求另装 Clang/LLVM 并不冲突。生成程序的动态依赖必须列入发行清单；静态链接 Vela 运行时不意味着整个程序没有系统动态库依赖。

交叉编译作为后续扩展，必须同时提供目标代码生成、目标运行时、链接器能力、SDK/sysroot 和测试环境；仅启用 LLVM target 不构成完整支持。

## 诊断与可验证性

编译错误继续使用现有源码诊断格式。运行时错误码、原始抛出点、调用位置和 await 边界不依赖 LLVM 调试信息是否开启；原生逻辑位置映射独立存储。可选的 DWARF/CodeView 信息用于平台调试工具，不宣称现有字节码断点和单步协议已支持 AOT。优化必须保留足够的来源信息解释内联位置。

原生目标文件和可执行文件是受信任的代码制品，ABI 检查不构成沙箱或生产者鉴权。首次执行不读取源码、不调用编译器、不进行 JIT 编译。

## 实施阶段与完成条件

各阶段是依赖顺序，不能把整数示例可运行当作完整 AOT 交付。

Windows 验证覆盖 1,563 项 C++ 测试、114 项工具测试、396 个 VM/AOT 语料对照及 30 项链接后的原生宿主契约。仓库级 clang-tidy 检查 431 个 C++ 文件，未报告诊断。Release 执行、编译、链接/归档探针、包体积、RSS、根槽及续延成本保存在[滚动聚合证据](../../benchmarks/results/rolling_summary.json)中。这些结果不能代替 Linux/macOS 实机执行及 SDK/签名验收。

| 阶段 | 实现范围 | 完成条件 |
| --- | --- | --- |
| A1：共享编译边界 | 分离公共优化、VM 分配、离线描述与实例化；补齐类型/效果事实 | VM 全量回归通过；AOT 前置编译不创建 Isolate，不受字节码编码上限约束 |
| A2：同步原生执行 | LLVM 目标文件、内部 ABI、实例化、根槽、同步直接调用路径、异常与宿主绑定 | 宿主可链接执行；GC 压力与对应同步语义差分通过，不链接 VM |
| A3：完整异步与动态路径 | 原生续延、所有 Future 组合、闭包/接口/动态调用与异步 main | 全部异步契约、宿主线程完成与不可达循环回收通过，无 VM 回调执行路径 |
| A4：用户构建与发行 | exe/obj/staticlib、导出包装、清单、版本校验、三平台包及诊断 | 无独立 Clang/LLVM 安装的干净环境构建、链接、运行通过；SDK 前提与许可证可审计 |
| A5：发布验收 | 全回归、静态检查、Release 性能与包依赖检查 | 下列矩阵完成，相关旧耦合与重复实现清理，未完成项目不能隐藏在发行声明中 |

验收矩阵：

- 语言差分：同一合法程序分别运行 VM/AOT，比较值、输出、副作用次序、错误码和源码栈；覆盖模块初始化、继承、泛型、动态值及全部已实现标准库。按契约比较 NaN 和非确定性 API，不用偶然相同的随机数或墙钟结果判等。
- GC 与所有权：每个可收集边界施压；覆盖返回交接、宿主内 GC、闭包共享修改、数组扩容、异常/finally、多个 Isolate、挂起/恢复及结果循环回收。验证根、布局事务和挂起统计在退出后恢复。
- 异步：首段同步副作用、普通值/已完成 Future 的 await、FIFO、adoption、组合失败、取消、timer、后台错误、外部线程完成及 idle；不添加 AOT 专属调度次序。
- ABI 与链接：目标/版本/签名不匹配、缺失导入、多个实例、多个静态库共用运行时、归档裁剪、Unicode/空格路径、编译或链接失败不覆盖旧产物、发布 I/O 失败与混合清单拒绝。
- 发行：在每个目标的干净环境中移除独立 Clang/LLVM 及非声明构建工具，按公开 SDK 前提构建和运行；移走源码和 Vela 工具链后仍能运行产物。检查二进制依赖和链接映射，确认没有 LLVM、编译器及 VM 执行器依赖。
- 性能：Release 下与 VM、同语义 C++ 比较算术、调用、字段、数组、宿主绑定、GC 与异步负载；分别记录编译、链接、首次/稳态执行、工具链/产物体积、RSS、根槽与挂起状态开销。按[基准保留规范](../../.agents/benchmark_results.md)保存证据，不预先承诺速度倍率。

首期发布所需语言路径不得保留“未实现时执行 VM”的分支。迁移共享服务时同步移除失去调用方的 VM 私有副本、重复元数据及仅为旧绑定方式存在的适配层；VM 自身仍需要的执行实现继续归 VM 所有。
