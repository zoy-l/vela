# 虚拟机存储、常量与分派

[English](../en/vm_storage.md) | [**简体中文**](vm_storage.md)


Vela 的虚拟机寄存器采用分离式存储结构：连续的 8 字节有效载荷（payload）数组，加上每个槽位 1 字节的 `ValueKind` 类型标记。基本运算指令直接读写原生的 int64/double/bool 载荷，函数调用参数窗口则将载荷与类型标记打包拷贝。因此，每个保留的寄存器仅需 9 字节，而公开的 `runtime::Value` 需要 16 字节。公开的宿主值以及常规类字段仍保留其现有的表示法。这并非 NaN Boxing：所有的 int64 整数值以及所有 double 浮点二进制位模式（包括各种 NaN 载荷和 -0.0）均能得到完好保留与表示。

有效载荷在类型边界使用对齐的字节存储和固定大小的 `memcpy`，在不产生对非活跃联合体成员未定义访问的前提下安全存储对象指针。Clang 会将这些拷贝在热路径上直接优化为普通的原生读写加载指令。

物理槽位在不同生命周期内可以被复用于不同的静态类型。类型标记反映其当前存储的实际形态；精确垃圾回收器仅扫描标记为对象或字符串的槽位。被复用的栈帧在注册前会统一清空标记，防止先前调用的对象引用被错误保持存活。复用时无需清零基本类型的载荷字节。寄存器视图借用载荷/标记数组，生命周期绝不能超过其活跃栈帧；对槽位引用的赋值是写入具体数值而非重新绑定引用。对槽位引用的移动操作同样遵循该契约。

内置函数在其输入边界最多具体化 3 个公开值。原生 C++ 回调仅在虚拟机持有的一块可复用缓冲区中具体化其实际参数数量，该缓冲区仅在首次遇到更大调用窗口时扩容。显式数值转换使用专用的单值转换通道，绕开通用的 3 参数数组及通用内置函数分派流程。宿主内置函数路径使用相同的范围与类型检查；未更改任何转换规则。无需反复进行堆分配，也无需初始化完整的 256 槽位数组。实际的寄存器窗口在整个分配和回调执行期间均被牢固保根。

## 常量池管理

较小的整数常量字面量直接走有符号 int16 立即数快速路径。其它 int64 常量保存在函数级去重、不可变的常量池中；常量折叠现在可以具体化完整的受查 int64 范围。Double 浮点常量池基于二进制位模式去重并保留负零。字符串共享程序级的不可变、精确保根的字符串常量池；编译器通过哈希查找替代原先的线性遍历。

加载整数、浮点数和字符串常量使用无符号 16 位常量池索引，支持 0..65535 个常量项。程序加载时对数值常量池和字符串根进行快照，并对索引执行单次统一校验。编译器编码阶段会在索引截断前先做越界诊断。类、布局、字段和调用操作数保留各自独立受查的字节编码上限。任何超出范围的常量绝不会被悄悄截断或错误解释为立即数。

## 拷贝传播、跳转与热路径执行

拷贝传播追踪基本块局部的数值标识符（value identity）及当前的代表值。覆盖某个代表值会将其置为无效，而不会改变其余副本的数值标识符。显式调用窗口保持其原有的连续内存布局。无效的 move 操作随后在常规的活跃性消除中被剔除；寄存器分配后仍保留物理自移动（self-move）消除。跳转穿透（jump threading）在线性时间内解析跳转链，保留无限跳转循环，剔除跳转到下一条紧邻指令的冗余跳转，并在紧凑化期间重映射源码及异常元数据。

直接调用入口与返回、强类型算术运算以及主分派逻辑借助 Clang 的 `always_inline` 属性保留在同一编译器优化边界内。较慢的内存分配、原生函数调用以及异常对象具体化则保持分离。字段访问在现有布局越界检查下直接解析为固定偏移量；基本类型字段的写入避免调用 GC 写屏障，而引用类型字段的写入则保留写屏障。运行时不存在字段名称哈希查找或重载查找开销。
