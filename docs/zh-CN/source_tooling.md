## 代码格式化工具

`vela fmt FILE` 将格式化后的源代码输出到标准输出。`vela fmt --write FILE` 原子地替换原文件；`vela fmt --check FILE` 在格式化会改变原文件时以退出码 `1` 退出。若存在语法错误，工具将返回常规的源码诊断信息并以状态码 `65` 退出；I/O 失败返回 `74`。在发生语法错误时绝不会重写任何文件。

格式化工具复用生产环境的词法分析器与语法分析器。Token 独立保留其原始字节区间及解码后的字面量值；解析器对泛型类型定界符和前缀运算符添加标注。格式化规则采用 2 空格缩进、LF 换行符、花括号代码块分多行书写、类型/命名参数冒号后加空格、二元运算符两侧加空格，且泛型尖括号内侧不留空格。顶层声明之间以空行分隔；连续的 import 保持紧凑，代码块内部已有的空行最多压缩为一行。长圆括号/方括号列表在逗号边界处换行折行。这是确定性的排版布局，不对不可分割的 token 或超长单行表达式做硬性最大列宽保证。

注释保持源码书写顺序，包括行尾尾随注释及插值内部的注释。单引号与双引号均生成 `string` 类型的值并支持 `${...}` 插值。格式化默认统一采用单引号（包括插值内部的嵌套字符串字面量），转义单引号字符，并移除不必要的双引号转义。其它转义拼写方式与插值表达式布局保持不变。重新格式化是幂等的，严格保留每个语言 token 的词法种类与解码数值。格式化不进行类型检查，也不执行源代码；包含未解析导入或存在暂时类型不一致的文件依然可以正常格式化。

## API 文档生成

`vela doc FILE OUTPUT.md` 检查完整的模块依赖图，并为主入口模块导出的所有声明生成 Markdown 格式的 API 文档。它消费与模块加载完全相同的不可变源码快照，不运行任何全局初始化器或 `main` 函数。各个模块导入的符号保持模块局部私有，不会作为二次导出写入文档中。

文档注释采用紧贴在声明上方的连续三斜杠 `///` 格式（遵循 Dart 社区惯例），支持 Markdown 语法。生成的文档涵盖函数、类型别名、枚举、接口、全局变量、类字段与方法、泛型签名、可空/数组/函数类型以及命名的构造参数。类的私有成员会被剔除；自动构造签名仅包含公开实例字段，显式构造函数展示自身的参数列表。默认表达式与可执行函数体以 `…` 占位表示，绝不进行求值。推导出的全局变量类型标注保持省略，与源码声明完全吻合。

`examples/documented_library.vela` 提供了完整示例：

```powershell
out/debug/vela.exe doc examples/documented_library.vela api.md
```

内存级 API `GenerateModuleDocumentation` 解析传入的单个模块且不解析其依赖导入。文件入口点则在生成前先执行全量类型检查。二者均渲染源码级声明，而非内部特化或带模块前缀的底层符号名。

## 编辑器语言服务协议（LSP）参考

`vela lsp` 通过二进制 stdio 运行语言服务器。其实现严格遵循 [LSP 3.17 规范](https://microsoft.github.io/language-server-protocol/specifications/lsp/3.17/specification/)：基于 Content-Length 字节计数的帧协议、JSON-RPC 生命周期管理、文档内存覆盖（document overlays）及协商确定的文本行列坐标。编辑器功能完整复用生产环境的类型检查器与格式化工具，不另行定义第二套语言语法。

服务端支持 initialize/shutdown/exit 生命周期、open/change/close/save 文档事件、被监听文件变动失效、带版本号的错误诊断、代码补全、悬停提示（Hover）、跳转到定义、文档链接及整篇文档格式化。全量语义高亮 Token（Semantic Tokens）对用户类型与内置类型进行细粒度分类，涵盖构造函数、类型标注、导入引用及泛型参数。UTF-16 为默认协议编码；声明支持 UTF-8 的客户端可使用字节坐标。增量文本编辑按序应用并原子提交；非法编辑将保持文本内容与版本号不变。过期版本的请求被安全忽略。

所有处于打开状态的文档内存覆盖均参与每次模块类型检查。被导入文件的诊断信息使用实际加载的源码快照（包括语法错误）。系统会自动去重并清理已过期的依赖项诊断。所有请求以同步方式处理；内容变动时重新检查已打开的模块图，而非维护复杂的增量语义图。VS Code 客户端默认对打字更新做 150 毫秒的防抖合并。代码格式化强制使用 Vela 规范的 2 空格风格。

每个 RPC 消息体上限为 64 MiB，协议头上限为 8 KiB。在完整数据帧中若解析到非法 JSON 会返回 JSON-RPC 解析错误，后续数据帧依然可正常读取；底层帧结构损坏则直接终止会话。不支持的请求返回明确错误。编辑器查询绝不执行脚本代码，也不主动写回源码文件。

`textDocument/completion` 补全项包含已有声明、可见的局部变量与参数、导入导出的符号、枚举值、类/接口成员以及内置全局 API。`.` 为成员访问触发符；补全文本替换光标周围完整的标识符。成员选择使用生产检查器的接收者类型（包括非空类型细化），并自动过滤私有成员和静态成员。查询专用的临时快照会补齐光标位置的标识符与结尾定界符，从而允许在不破坏真实文档的情况下对未写完的 `object.` 进行安全检查。编辑器加载模块在产出语法诊断的同时保留生产解析器的完整声明与语句；缺少分号不会导致下一条语句或整个模块图被直接丢弃。编译流程则继续严密报错。解析器确实无法保留的未完成残缺声明不会参与语义查询。

在函数调用内部，`textDocument/completion` 还会从已通过检查的构造函数、普通函数和方法中提供未填写的命名参数补全。`(` 和 `,` 为触发符；选中 `value:` 补全项将插入 `value: ` 且不会重复生成既有的冒号。参数候选排在常规符号之前，局部变量依然可见。参数类型与默认值展现在补全详情中。查询快照在不改变编译器诊断的前提下修复不完整的参数槽位。函数类型变量仅接收位置实参，不提供命名参数提示。

`textDocument/definition` 将词法绑定标识、函数/类型/全局变量名、成员与命名参数精准解析为声明所在的精确源码区间，包括未保存的外部依赖文件。位于标识符内部及紧随其最后一个字符之后的光标位置均解析为同一声明。通过检查的快照在多次重复的定义与悬停请求间复用，并在文档编辑、保存或被监听文件发生变动时立即失效。没有对应磁盘源文件的内置声明返回 `null`。诊断与查询跨编辑共享模块解析快照，变化的内存覆盖只替换自身缓存的语法。补全修复后的源码相同时复用索引。文档修改使语义索引失效；保存及被监听文件变动还会清除磁盘快照，关闭内存覆盖后恢复从磁盘加载。新的查询快照仍同步检查其模块图，没有按 AST 子树增量更新语义模型。

导入路径字面量及导入别名声明同样能跳转到被导入文件的第 1 行。`textDocument/documentLink` 在去除引号的原始路径文本上提供解析好的可点击超链接，使得编辑器能够对整个路径添加下划线并支持点击打开。重复的链接、悬停和定义请求共享同一份缓存索引。目标复用模块加载器的规范化模块身份，包括相对路径、省略的 `.vela` 扩展名、解码后的转义符、Unicode 文件名及未保存的模块内存覆盖。普通字符串和未解析的导入不生成链接目标。默认标准库对象使用内置的内部声明源码以供类型检查和悬停提示，不生成磁盘跳转目标。

`textDocument/hover` 返回 Markdown 格式的 Vela 函数/类型签名及相邻的 `///` 文档注释，并标明光标下名称的精确高亮区间。它覆盖推导出的局部/全局变量类型、参数、函数、字段、方法、类、接口、枚举、类型别名及内置 API。源码类型引用在泛型特化展开别名和模板之前完成索引。导入符号的文档来源于类型检查时加载的相同内存快照。未识别名称、注释、普通字面量文本及空白字符不提供悬停。VS Code 客户端会自动同步未保存的文本，丢弃已取消或过期的回复，并渲染不含不受信任超链接与 HTML 标签的纯净 Markdown。

内置 API 文档采用英文编写；用户自定义的 `///` 注释完整保留其原始语言文本。悬停格式化严格对标 TypeScript 6.0.3 的 `getQuickInfoAtPosition` 标准：枚举与接口名保留名义声明头与文档，枚举成员显示限定名与数值，类型别名展示包含泛型参数的完整定义。方法与属性包含其所属类型，参数带有显式的角色标签。函数类型数组与可空函数类型保留清晰的外层括号分组。Vela 还在类悬停信息中额外展示构造函数参数及默认值。

[VS Code 扩展](../../editors/vscode/README.md) 包含 TextMate 语法高亮规则及零第三方依赖的 stdio 语言客户端。`vl editor package` 在 `out/editor` 下打包生成 VSIX 插件文件。`vl test debug tooling` 运行真实进程间的协议与工具端到端测试。可选的 Node 客户端测试通过 `node --test editors/vscode/extension_unittest.cjs` 运行；Node 运行时由 VS Code 在运行期间自带提供，不属于编译器本身的构建依赖。`vl editor test --code PATH` 可进一步拉起真实的 VS Code 扩展宿主执行自动化测试；该测试要求系统已安装 VS Code（在 Windows 上使用 `bin/code.cmd`），运行在完全隔离的临时配置目录中，且不依赖任何 npm 第三方包。

[终端调试器](debugger.md) 通过 `vela debug FILE` 启动，基于虚拟机的显式指令观察者运行，与运行时诊断共享源码映射表。

[持久化 REPL](repl.md) 通过 `vela repl` 启动，在多轮提交之间持久保留变量声明与数值，且不重新回放先前的输出。
