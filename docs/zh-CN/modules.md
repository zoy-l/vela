# 模块系统

[English](../en/modules.md) | [**简体中文**](modules.md)

每个源文件都拥有独立的顶层作用域。函数、类、枚举、接口、类型别名以及模块级 `let`/`const` 绑定对本文件私有，除非显式标记为 `export`。类成员默认公开，`private` 将访问限制在声明类内部，与该类本身是否导出彼此独立。

```typescript
// counters.vela
let current: int = 40;
export const step: int = 1;
export func next(): int {
  current = current + step;
  return current;
}
```

```typescript
// main.vela
import 'counters' as counter;
func main(): int {
  counter.next();
  return counter.next();
}
```

不带 `as` 的导入会将依赖模块导出的符号引入当前模块的顶层作用域中。带 `as` 的导入则必须使用前缀限定访问，例如 `counter.next()`。类、枚举类型、泛型特化以及类型别名同样支持带前缀的限定访问。导入名称冲突或与顶层声明冲突时将生成诊断报错；建议使用前缀区分不同导入。局部变量和参数可以遮蔽（shadow）已导入的名称或导入前缀。

导入不会发生隐式的二次导出（re-export）。依赖项无法使用入口模块的私有符号，导入某个模块也不会自动暴露该模块内部导入的其它依赖。导入前缀属于编译期绑定，并非运行时对象或值。语言中不提供 `namespace` 声明块语法。

源文件基于其规范化绝对路径通过工作队列仅加载一次。循环导入可以在不递归执行模块顶层语句的情况下完成函数声明之间的链接。模块绑定与类型名称在泛型特化前完成解析；函数调用和字段偏移使用已解析的原生目标与布局元数据，运行时不进行任何模块名称查找。

模块级全局变量复用程序内被保根的惰性初始化器槽位。它们按需初始化，并在同一个已编译程序的多次执行或副本间持久存在。新的编译过程会获得独立的状态。导出的可变 `let` 变量允许通过导入进行修改赋值，而对 `const` 赋值则属于编译期错误。`const` 仅阻止重新绑定，不阻止被引用对象内部状态的变更。初始化器使用其定义模块的作用域，不可捕获调用方或其它初始化器 lambda 的局部变量。类型推导沿全局依赖拓扑进行；循环推导必须显式提供类型标注，若在运行时实际惰性初始化期间发生循环依赖，将报告 `CyclicInitialization` 异常。

`CompileModules` 与 `CheckModules` 接口接收命名的 `SourceInput` 条目与入口路径。相对导入仅在提供的输入集合中解析，不会静默读取磁盘文件。`CheckFile` 支持为未保存的编辑器缓冲区传入内存覆盖内容，同时完整保留基于文件系统的依赖图。

编译入口点使用源文件路径。导入路径相对于当前导入文件进行解析。不带扩展名的标识符（例如 `import 'math';`）直接解析为 `math.vela`；显式书写扩展名同样有效。解析过程不会探测同名无后缀文件或 `index.vela` 目录入口。模块加载器、编译缓存、编辑器跳转与导入链接均共享相同的路径解析逻辑。标准对象（如 `Math` 和 `Error`）无需导入即可全局使用；不再支持 `std:` 形式的导入前缀。

`import 'sdk:test';` 从发行版嵌入的不可变源码加载[测试库](testing.md)。SDK 模块沿用普通模块的导出、私有性和前缀规则，磁盘编译、内存编译、原生目标代码缓存与语言服务共享 `sdk:test` 身份；内存输入不能覆盖 SDK。未知 `sdk:` 模块直接报错，不作为文件路径解析。`builtin:` 仍仅用于标准环境内部声明。
