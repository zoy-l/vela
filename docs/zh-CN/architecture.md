# Vela 语言架构

[English](../en/architecture.md) | [**简体中文**](architecture.md)

Vela 是一个面向原生宿主应用的静态类型脚本语言。寄存器字节码 VM、原生 AOT 和开发 JIT 共享带类型的中间表示（Typed IR）。开发模式已支持运行时脚本加载、保留状态的 Hot Reload 与重建脚本 Isolate 的 Reload；功能、性能和平台验收范围见 [JIT 与热重载契约](hot_reload.md)。共享运行时拥有值、GC、异步和宿主集成。

## 源码语言模型

源码采用 C 风格的代码块、分号与运算符，配合后置类型标注。顶层函数声明使用 `func name(parameter: Type): Return`；类方法省略 `func` 前缀，类字段声明为 `name: Type`。局部变量使用 `let` 或 `const` 声明，强制要求提供初始值，并允许从中推导精准的静态类型。函数参数、返回值类型及类字段必须提供显式类型标注。`const` 仅阻止重新赋值绑定，对象的字段变更或数组元素的修改依然完全允许。字符串上下文会自动格式化基本类型与 null；其它类型边界保持严格的静态受查。语言中不设立已淘汰的前缀声明语法。函数类型仅包含参数类型，例如 `(int, int) => int`；强类型箭头函数支持词法作用域捕获，并支持对捕获的可变 `let` 变量进行跨闭包共享修改。[P1 契约规范](core_language.md) 详尽规定了闭包、对象构造、接口、泛型、模式匹配及有序集合。

控制流包含允许空标签共享分支、禁止非空分支穿透的 switch 语句。显式的可空类型使用 `T?`，配合流敏感的非空类型细化检查。作用域规则、声明顺序及源码诊断信息详见[基础语言契约](language_basics.md)。

初始类对象模型有意设计得比 C++ 更轻量纯粹：

- `class` 声明名义类型的对象内存布局，包含静态已知的字段与方法；
- 类支持单继承、显式 `super` 构造串联、`override` 方法重写和多接口运行时动态分派；
- 类实例化表达式不使用 `new` 关键字；
- 命名构造实参在编译期直接解析绑定至公开实例字段或显式构造函数的形参 ID；
- 枚举成员必须显式指明其枚举名限定（`Brightness.light`），包括在构造函数实参、变量声明、返回值、赋值及数组元素中；
- 字段与方法均为静态声明，因此运行时的成员访问在热路径上绝非低效的字符串查找。

代码示例：

```text
enum Brightness {
    light,
    dark,
}

class CupertinoThemeData {
    brightness: Brightness;
}

class ActionSheetExample {
}

class CupertinoApp {
    theme: CupertinoThemeData;
    home: ActionSheetExample;
}

func buildApp(): CupertinoApp {
    return CupertinoApp(
        theme: CupertinoThemeData(brightness: Brightness.light),
        home: ActionSheetExample(),
    );
}
```

其表层语法类似于数据构造器，但构造依然具备精准的运行时契约。首期运行时表示采用 Isolate 持有的不透明堆对象引用及类布局描述符。后续的 `struct` 特性可以在不改变构造语法的前提下引入内联值语义。

## 编译器编译管线

```text
源代码
  -> 词法分析与语法分析（Lexer & Parser）
  -> 名称解析与静态类型检查（Name Resolution & Type Checking）
  -> 带类型的控制流中间表示（Typed IR）
  -> IR 中间表示优化（IR Optimization）
      ├─ VM 寄存器分配 -> 定长寄存器字节码 -> Vela VM
      └─ 共享 LLVM lowering -> AOT 目标文件 / 可重载 JIT
```

Typed IR 是字节码、原生 AOT 与 JIT 后端共享的核心语义边界。字节码是独立的执行期表示，专为高效解码和可预测的寄存器访问优化；字节码本身并不用作编译器的通用优化图。

[原生 AOT 设计](aot.md)规定 LLVM 后端、原生执行与 GC/异步契约，以及无需用户单独安装 Clang/LLVM 的工具链发行方案；已实现范围和发行验收状态以该文档为准。AOT 在公共 IR 优化后分流，不经过 VM 寄存器分配或字节码编码。

虚拟机的引导实现直接消费运行时的 GC 保根契约：每个栈帧的寄存器切片在整个函数执行期间注册为 GC 根区间。寄存器槽位保持连续存储，内存分配指令在触发 GC 时无需移动或重新安置调用栈中的值。

当前编译器管线已将受查的整数表达式、局部变量、函数调用、字段访问、赋值、枚举序号、固定布局类构造及结构化分支/循环通过 Typed IR 编译为字节码。`vela run` 通过执行无参 `main` 入口函数串联起整条通路。

字符串与强类型数组复用相同的 IR 与字节码通路。数组元素类型及其维度在字面量、字段、参数、返回值、索引访问及赋值中保持严格一致。上下文为推导空数组字面量提供类型信息；不进行任何隐式元素类型转换。数组具备引用语义及紧凑的原生连续存储。数组长度可通过强类型的变更 API 动态伸缩，同时引用的别名保持相同的对象身份；详见[动态可增长数组](arrays.md)。关于字节码编码限制，详见[编译器实现细节](../../compiler/README.md)。

语义检查通过统一约束求解确定泛型实参，按需生成并检查具体特化声明；显式与推断调用共享规范化的特化身份。已解析的类型完整保留结构化元素/签名/实参关系与调用目标；Lowering 阶段不会通过解析类型名称后缀来反推数组元素类型，也不会再次推导泛型实参。接口选择器、字段偏移与参数绑定在执行前全部静态就绪。校验通过的类布局表保持不可变，并由程序内的所有函数共享。

编译器在词法、语法解析、类型检查、IR 指令直至字节码区间全程保留源码位置信息。这使得错误诊断和调试器映射独立于 VM 指令编码本身。

类型检查还会准确记录每条语句是否能够 fallthrough、break 或 continue。非 void 函数绝不能自然穿透其闭合花括号；死循环路径无需 return。不可达语句直接作为编译报错拦截。布尔字面量、`!`、`&&` 与 `||` 会细化分支可达性；其它复杂条件则做保守判定，不进行激进的变量值跨块传播。Lowering 阶段利用这些事实安放 void return，并剔除不可达的分支跳转、循环递增及回跳边。即使条件结果已知，条件表达式内部的副作用依然予以保留。

## 虚拟机执行契约

首期字节码格式借鉴了 Luau 解释器在无需手写汇编的前提下实现极速执行的核心特性：

- 常规情况下采用单条固定宽度的 32 位指令字；
- 8 位操作码与紧凑的寄存器操作数，配合显式的辅助字支持超宽常量与元数据；
- 每个调用栈帧内具有连续的寄存器槽位；
- 静态检查后采用针对特定类型的快速算术与比较指令；
- 针对静态解析调用的直接函数 ID；
- 针对类访问的直接字段 ID 或固定布局偏移量；
- 普通整数、浮点数、布尔值或句柄的移动不发生任何堆内存分配；
- 常量池与调试元数据存储在热执行指令流之外。

解释器使用经过优化的 switch 分派。computed-goto/direct-threaded 分派已评估，当前实现保留 switch；测量边界见[VM 存储与分派](vm_storage.md)。

调用宿主原生函数走显式注册的函数表。每个注册条目拥有稳定的函数 ID、静态签名和强类型适配器。VM call 指令通过 ID 直接选取适配器；绝不构造泛型的 `Value*` 数组，也不在每次调用时做低效的字符串查找。原生后端可以将相同的强类型调用直接 Lowering 为宿主原生 ABI 调用。

## 共享 IR 优化边界

共享 Typed IR 优化器实现以下优化：

1. 基本块内的复制传播与冗余 move 消除；
2. 基本块内的整数、布尔值和 null 常量传播与折叠，以及已知分支简化；
3. 跳转串接与无用途跳转消除；
4. 死值、不可达基本块和无用途异常处理器消除。

直接调用目标和字段偏移由前端与 lowering 解析。原生后端还接入 LLVM 优化及[Class 逃逸分析](escape_analysis.md)。共享 IR 优化不能删除用户可见的失败、副作用或生命周期操作；无法证明可优化时保留原指令。

## 内存与对象管理边界

单个 Isolate 独占其托管堆与已注册的宿主引用。VM 与封闭 AOT 的类实例采用固定布局；可重载模式保留对象地址并使用可替换字段存储，其布局演化和生命周期见[热重载契约](hot_reload.md#6-对象布局与状态演化)。运行时不将 C++ 对象布局直接暴露给脚本。

运行时底层采用精确、非移动式、增量标记清除收集器，具备 Isolate 局部的高速分配路径。每个类布局清晰记录其包含引用的字段，使得标记阶段可直接扫描这些字段而无需动态元数据查找。VM 栈帧槽位、全局变量及宿主句柄必须注册为显式的根区间。对象标记期间字段的写入必须经过写屏障，灰色工作队列采用侵入式链表设计，确保垃圾回收本身不分配临时工作内存。

小对象分配采用大小分级（size-class）的空闲链表。VM 寄存器分离存储 8 字节载荷和 1 字节类型标签，类实例字段使用 `Value` 槽位；数组在类型专属的连续缓冲区中直接存储原生基本类型值或裸指针。小型数组利用内联槽位存储；大数组或扩容数组使用独立核算的外部底层缓冲区，同时 GC 对象本身保持其原始地址不变。数组布局标识其元素是否为引用类型；标记阶段仅扫描实际存活的前缀部分，引用类型写入自动触发写屏障。不可变字符串将对象头与字符字节合并在单次分配中，参与统一垃圾回收，并作为叶子节点标记。字符串拼接一次性分配结果并直接复制双方字节，在总字节数上保持线性 O(n) 开销。类字符串字段与原生字符串指针数组均能得到精准追踪。

已编译函数共享一个固定大小、被保根的原生字符串常量池。其持有者在分配字面量前注册该常量池，并在最后一个持有者销毁时注销其根。`vm::Program` 拥有不可变且经过校验的函数存储，程序拷贝共享该存储。`vm::FunctionHandle` 持有程序（包含代码与保根常量）。裸 `vm::Function` 视图是借用的加载输入：`Program::Load` 先复制它们，随后校验所持有的快照。执行过程不再重复校验程序结构。类布局由 Isolate 统一持有，Isolate 的生命周期必须长于所有程序、句柄与根区间。程序销毁与根操作均在 Isolate 所属线程中执行。虚拟机执行结果是借用的值：宿主在进行下一次分配或 GC 前必须先对返回的对象或字符串进行保根。关于寄存器分配与编码上限，详见 [VM 执行契约](vm_execution.md)。

在收集器进入清除阶段前会对根集合进行重新扫描，因为 VM 寄存器的内容在增量单步之间可能会发生改变。根注册与引用写入同样在清除阶段保护新老引用。收集器在单个 Isolate 内是严格单线程工作的；宿主跨线程访问必须经过 Isolate 拥有的保根边界后方可安全持有脚本对象。字符串采用合法的 UTF-8 编码，具备码点长度、索引及切片边界，并提供独立的字节长度。字符串插值、显式转换、join 及 GC 管理的构建器统一走相同的受查编译器与 VM 通路。API 规范、开销及保根细节详见[字符串设计规范](strings.md)。

分代垃圾回收仍作为 Release 基准测试阶段的优化决策项保留。它完全可以在当前对象、根和写屏障契约之后追加实现，而无需改变源码级的生命周期语义。分代回收与 Arena 区域分配属于后续的底层性能优化，而非引入第二套对象所有权模型。

REPL 各次提交共享可增长的 GC 全局槽对象。外部 Program 句柄为其保根，续延通过可达的 Future 引用图追踪槽对象，因此早先提交的写入对后续提交可见，不可达的挂起任务及其全局值也能一起回收。

async 调用在 await 前使用普通 VM 帧，挂起后只保存活动寄存器值，在后续执行片段恢复。Future 状态、timer 队列和 GC 由 Isolate 线程独占；宿主线程经原子 MPSC 消息队列发布完成消息，完成占位与取消使用原子操作，通过信号量休眠和唤醒所属线程。普通 Future、Completer 和 Program 句柄必须在 Isolate 销毁前释放；原生生产者持有的 `FutureCompletionEndpoint` 可以晚于 Isolate 销毁，调度器关闭后迟到完成返回 `Closed`。详见[异步契约](async_tasks.md)。

## 性能实测规范

虚拟机的每项优化均在 Release 构建下通过可重复的高负载基准进行严密评估：

- 整数与浮点数密集计算循环；
- 函数调用与返回开销；
- 连续数组遍历；
- 类字段读写；
- 静态绑定的宿主原生函数调用；
- 批量实体状态更新。

每次测量均系统记录编译耗时、首次执行耗时、稳态执行耗时、常驻物理内存峰值、字节码体积以及指令执行总数（若可获取）。原生 C++ 实现作为基准对照线；只有在工作负载与可观察语义完全可比的前提下，与 Luau 的对比才具有实际参考意义。
