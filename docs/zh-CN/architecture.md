# Vela 语言架构

[English](../en/architecture.md) | [**简体中文**](architecture.md)

Vela 是一个面向原生宿主应用的静态类型脚本语言。原生 AOT 与 JIT 共享带类型的中间表示（Typed IR）及原生代码生成。开发模式已支持运行时脚本加载、保留状态的 Hot Reload 与重建脚本 Isolate 的 Reload；功能、性能和平台验收范围见 [JIT 与热重载契约](hot_reload.md)。共享运行时拥有值、GC、异步和宿主集成。

## 源码语言模型

源码采用 C 风格的代码块、分号与运算符，配合后置类型标注。顶层函数声明使用 `func name(parameter: Type): Return`；类方法省略 `func` 前缀，类字段声明为 `name: Type`。局部变量使用 `let` 或 `const` 声明，强制要求提供初始值，并允许从中推导精准的静态类型。函数参数、返回值类型及类字段必须提供显式类型标注。`const` 仅阻止重新赋值绑定，对象的字段变更或数组元素的修改依然完全允许。字符串上下文会自动格式化基本类型与 null；其它类型边界保持严格的静态受查。语言中不设立已淘汰的前缀声明语法。函数类型仅包含参数类型，例如 `(int, int) => int`；强类型箭头函数支持词法作用域捕获，并支持对捕获的可变 `let` 变量进行跨闭包共享修改。[P1 契约规范](core_language.md) 详尽规定了闭包、对象构造、接口、泛型、模式匹配及有序集合。

控制流包含允许空标签共享分支、禁止非空分支穿透的 switch 语句。显式的可空类型使用 `T?`，配合流敏感的非空类型细化检查。作用域规则、声明顺序及源码诊断信息详见[基础语言契约](language_basics.md)。

初始类对象模型有意设计得比 C++ 更轻量纯粹：

- `class` 声明名义类型的对象内存布局，包含静态已知的字段与方法；
- 类支持单继承、显式 `super` 构造串联、`override` 方法重写和多接口运行时动态分派；
- 类实例化表达式不使用 `new` 关键字；
- 命名构造实参在编译期直接解析绑定至公开实例字段或显式构造函数的形参 ID；
- 枚举成员必须显式指明其枚举名限定（`Brightness.light`），包括在构造函数实参、变量声明、返回值、赋值及数组元素中；
- 字段与方法均为静态声明，因此运行时的成员访问在热路径上绝非低效的字符串查找。

代码示例：

```text
enum Brightness {
    light,
    dark,
}

class CupertinoThemeData {
    brightness: Brightness;
}

class ActionSheetExample {
}

class CupertinoApp {
    theme: CupertinoThemeData;
    home: ActionSheetExample;
}

func buildApp(): CupertinoApp {
    return CupertinoApp(
        theme: CupertinoThemeData(brightness: Brightness.light),
        home: ActionSheetExample(),
    );
}
```

其表层语法类似于数据构造器，但构造依然具备精准的运行时契约。首期运行时表示采用 Isolate 持有的不透明堆对象引用及类布局描述符。后续的 `struct` 特性可以在不改变构造语法的前提下引入内联值语义。

## 编译管线

```text
源码 -> 词法/语法分析 -> 名称解析与类型检查
     -> Typed IR -> 共享 IR 优化 -> 原生 LLVM lowering
     -> JIT 链接与实例化，或 AOT 产物发布
```

前端通过共享约束求解泛型实参，再具体化并检查声明；显式调用与推断调用共享规范特化身份。
已解析类型保留元素、签名和泛型实参的结构关系，lowering 不通过拆解类型名称恢复这些信息。

前端记录 fallthrough、break 和 continue 控制流事实。非 void 函数不能自然到达闭合花括号，
无限循环路径无需 return；不可达语句报错。布尔字面量和逻辑运算细化可达性，
lowering 在移除不可达跳转与返回时仍保留条件副作用。

Typed IR 保留源码位置、已解析调用、字段身份、异常边和运行时类型描述。
共享优化包括基本块复制与常量传播、跳转串接、死值和不可达块消除。
不能证明可删除的可观察失败与副作用仍予以保留。
LLVM 优化与[逃逸分析](escape_analysis.md)在这一语义边界之后执行。

## 原生执行

`run`、源码测试和独立调试器使用封闭 JIT 快照；`dev` 与 REPL 使用可重载原生会话。
AOT 通过同一生成器输出目标文件、静态库或可执行文件。
具体边界见[执行契约](native_execution.md)、[AOT](aot.md)与[热重载](hot_reload.md)。

Baseline 与 optimized JIT 保持相同语言语义。可重载优化层为活动栈帧保留恢复信息与基线入口。
LLVM 优化独立于 JIT 层级配置。

宿主函数在注册时建立不可变签名，并在实例化时检查。生成代码使用带类型宿主 ABI；
动态调用在进入目标前完成必要参数与类型检查。C++ 宿主触发 GC 时，
原生声明仍作为逻辑栈帧可见。Isolate 拥有运行时状态，JIT 映像的共享所有者拥有已链接代码。

## 内存与对象边界

每个 Isolate 独占堆、元数据、调度器和宿主绑定。封闭原生实例使用固定类布局；
可重载对象保留地址，通过受查发布演化字段存储。两种模式都不把 C++ 对象布局暴露为脚本对象。

GC 精确、非移动且增量执行。托管值位于显式登记的影子根、全局状态、保留激活记录与宿主句柄中。
引用字段和数组布局决定追踪对象；写入遵守屏障。
进入 sweep 前重访根，因为活动代码可能在增量步骤之间修改它们。小对象使用大小类空闲链表。

公开 `Value` 是 16 字节带标签值。带类型原生局部值可使用未装箱机器表示；
数组紧凑存储原生基本类型或引用。数组扩容替换后备缓冲区，同时保留 GC 对象身份。
字符串为合法 UTF-8，按码点索引并单独提供字节长度；不可变内容和可变 builder 缓冲区都计入堆用量。

`NativeInstance` 为常量和程序状态保根。闭包、异步激活和开发句柄保留所需版本；
不可达状态与代码可以一起退休。返回值借用堆，须在后续分配前保根。
详见[嵌入](native_embedding.md)与[垃圾回收](garbage_collection.md)。

async 调用执行到返回、错误或 await。挂起将活跃状态保存在堆激活记录中，再经调度器恢复。
Future 状态与 GC 由 Isolate 线程拥有。宿主生产者经 MPSC 队列提交不可变完成消息；
完成端点可晚于关闭存活，并返回 `Closed` 而不访问已退休运行时存储。
普通实例、Future 和根句柄必须早于所属 Isolate 释放。

## 性能证据

在 Release 下分别测量编译、首次执行和稳态执行，使用等价负载并检查每次结果。
代码与原生帧计划、GC 活跃/已提交字节和进程常驻内存分别报告；
编译器帧计划不等于实测物理栈大小。

基准对照 JIT、两个可重载层级、AOT 及合适的 C++ 或 LuaJIT 负载。
只有后端、机器、工具链、重复次数和测量边界一致时，历史测量才可比较。
确切保存规则与命令见[基准说明](../../benchmarks/README.md)。
