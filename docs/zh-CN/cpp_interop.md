# C++ 宿主类型与双向互操作设计

> 状态：I1–I6 已实现，macOS arm64 验收完成。本文定义公共契约、实现边界和验收条件；使用方式见
> [原生嵌入](native_embedding.md)。

Vela 为 C++ 宿主提供统一的脚本类型表达、类型化句柄和双向调用 API。宿主可以创建、接收、
操作和返回脚本值，也可以保存脚本对象与回调，在原调用结束后继续使用。类型检查、对象身份、
GC、异常、异步和热重载均接入现有运行时契约。

公共 API 区分逻辑类型与持有期限：`Array<T>`、`Function<R(Args...)>` 等描述脚本类型，
`Local<T>` 提供作用域内引用，`Persistent<T>` 提供跨调用强引用。基础标量使用 C++ 固定宽度
类型。JIT 宿主、AOT C++ 导出包装和 C++ 类绑定生成器消费同一套类型与值操作。

## 1. 目标用法与交付边界

`<vela/host.h>` 是公共入口。以下示例中，`NativeContext` 和
`NativeFunction::Bind` 继续承担宿主调用上下文和注册职责。

```cpp
#include <cstdint>
#include <expected>
#include <utility>

#include <vela/host.h>
#include "runtime/native/native_context.h"
#include "runtime/native/native_function.h"

using Integers = vela::Array<std::int64_t>;
using Transform = vela::Function<std::int64_t(std::int64_t)>;

vela::Result<void> Apply(vela::runtime::NativeContext& context,
                         vela::Local<Integers> values,
                         vela::Local<Transform> transform) noexcept {
  auto& scope = context.handles();
  auto first = values.Get(scope, 0);
  if (!first) {
    return std::unexpected(std::move(first.error()));
  }
  auto next = transform.Call(scope, *first);
  if (!next) {
    return std::unexpected(std::move(next.error()));
  }
  return values.Set(scope, 0, *next);
}

vela::Result<vela::Persistent<Transform>> Keep(
    vela::Local<Transform> transform) noexcept {
  return transform.Persist();
}
```

宿主按现有方式注册 `NativeFunction::Bind<Apply>("apply")`。脚本声明与调用为：

```vela
external func apply(values: int[], transform: (int) => int): void;

func main(): int {
  const values = [41];
  apply(values, value => value + 1);
  return values[0];
}
```

`values` 在两端表示同一个数组；成功调用后脚本读到 `42`。空数组产生索引错误，回调抛出的
异常沿同一错误通道返回。`Keep` 展示宿主内部保存回调的操作，不作为脚本绑定签名：跨调用
存储使用 `Persistent<T>`，脚本函数的参数与返回值使用局部句柄。

本设计交付以下能力：

- 标量、可空值、动态值、字符串、数组、集合、脚本类与接口、枚举、函数和异步值的类型映射。
- 现有公开内建引用类型的类型化持有、传递和公开操作，包括字节存储、正则对象等。
- 脚本调用 C++、C++ 调用脚本、回调重入、跨调用保存和显式释放。
- 手写绑定、生成的宿主类绑定、JIT 入口、AOT 导出及发行包的一致支持。
- 类型描述、GC 根、错误载荷、代码版本和关闭流程的完整生命周期。

本设计不引入 C++ 对象内存与脚本对象字段的布局共享、跨 Isolate 共享托管对象、任意 C++
对象图自动追踪、任意捕获 lambda 或 `std::function` 自动转为脚本闭包，也不引入 C++ 模板
运行时实例化。已有绑定函数仍可按语言规则形成函数值。STL 容器与脚本容器之间如需复制，
通过明确的复制操作完成；其自动映射不属于本设计。

低层 `ExecuteNativeFunction` / `ExecuteNativeCallable` 的结果仍借用堆。公共类型化入口在返回前
将成功值交付目标作用域，并将异常载荷保存到 `Error`；内部低层调用者显式持有 `HostRoot`。

## 3. 分层与模块职责

```text
C++ 手写宿主 / 生成的 C++ 包装
             │
公共类型、Local / Persistent、类型化值操作
             │
共享宿主边界：类型解析、codec、根交接、错误转换
             │
现有 Isolate / Heap / NativeExecution / 调度器

C ABI 的不透明句柄 ──> 同一宿主边界实现
JIT / AOT 生成代码 ──> 现有内部原生 ABI 与宿主适配入口
```

`include/vela` 提供公共声明与必要模板，`runtime/heap` 管理根存储，`runtime/isolate`
解析本地类型身份并登记外部资源，`runtime/native` 承担宿主转换与调用。字符串、容器、异步等
值操作仍由现有对应模块实现。运行时不读取 Clang AST，不依赖 frontend、IR 或 LLVM。

frontend 继续负责语言类型规则，IR 和共享原生生成负责传递完整类型、调用及 GC 效果。
`compiler/bindgen` 是 C++ 类型描述的生产者；脚本公共类型与导出包装由受查模块图和原生
导出流程产生。不得从类型名字符串、C++ RTTI 名称或当前对象内容反推静态类型。

公共 C ABI 仍使用固定宽度数据、不透明指针和显式状态。C++ 模板、`std::expected`、智能指针
及 STL 对象不成为 C ABI 的二进制字段。内部标量调用保留现有类型化入口，不强制绕行公开
通用值接口。此设计不新增执行后端或另一套 GC。

## 4. 逻辑类型与 C++ 类型映射

### 4.1 类型描述与值表示

以下公共类型位于 `vela` 命名空间。托管类型名是供模板与句柄使用的逻辑类型描述，不允许
独立构造出脱离 Isolate 的脚本对象。

| 脚本类型 | 逻辑类型描述 | C++ 调用边界上的值 |
| --- | --- | --- |
| `void` | `void` | 无结果，仅用于返回位置及合法的异步载荷位置 |
| `bool`、`int`、`double` | `bool`、`std::int64_t`、`double` | 对应标量值 |
| `string` | `String` | `Local<String>` |
| `T[]` | `Array<T>` | `Local<Array<T>>` |
| `Map<K, V>`、`Set<T>` | `Map<K, V>`、`Set<T>` | 对应局部句柄 |
| 脚本 class / interface | `Object<Tag>` | `Local<Object<Tag>>` |
| 脚本 enum | `Enum<Tag>` | 类型化局部句柄，边界编解码沿用现有枚举表示 |
| 已绑定 C++ 类 | `Host<T>` | `Local<Host<T>>`；原生方法接收者仍可使用受查的 `T&` |
| `(A, B) => R` | `Function<R(A, B)>` | 对应函数局部句柄 |
| `Future<T>`、`Completer<T>` | `Future<T>`、`Completer<T>` | 对应局部句柄 |
| `CancellationToken`、`Timer` | 同名逻辑类型 | 对应局部句柄 |
| `MutableString`、`ByteArray`、`ByteData` | 同名逻辑类型 | 对应局部句柄 |
| `RegExp`、`RegExpMatch` | 同名逻辑类型 | 对应局部句柄 |
| `dynamic` | `Value` | `Local<Value>`，可以保存标量、null 或引用 |
| `T?` | `Nullable<T>` | `std::optional` 包装 T 对应的边界值 |

泛型实参使用逻辑类型，不嵌套句柄。例如 `Array<String>` 和
`Function<String(std::int64_t)>` 分别描述字符串数组和返回字符串的函数；实际读取或调用
返回 `Local<String>`。`Array<Local<String>>` 不是合法类型表达。

`Nullable<String>` 对应 `std::optional<Local<String>>`，`Nullable<std::int64_t>` 对应
`std::optional<std::int64_t>`。可空性按语言规则展平，空句柄不充当脚本 null。`Local<Value>`
中的 null 是一个有效脚本值。`vela::Value` 与内部 `vela::runtime::Value` 的职责分别是公共
动态类型描述和运行时标签值，公共 API 不暴露后者的原始构造能力。

`std::string_view` 参数和 `std::string` 结果可以继续作为明确的字符串借用与复制转换，
由同一字符串 codec 实现。它们与保留脚本字符串身份的 `Local<String>` 具有不同的用途。
不增加隐式数值转换，也不把 `std::vector`、`std::map` 或 `std::function` 当作脚本对象。

### 4.2 名义身份与泛型

`Tag` 由脚本受查模块图生成，携带可解析的声明身份及公开契约。普通类、接口和枚举保持各自的
名义身份；类型别名透明。具体泛型应用由 frontend 的既有特化机制产生，宿主头文件只表达
已具体化的公开应用，不在运行时补做类型推导或特化。

生成物中的模块与声明标识在绑定到实例或开发会话时解析为本地 `DeclarationId` 与运行时
名义身份。不得把某次编译的表内索引或某个 Isolate 的指针固化进跨运行复用的头文件。
同名的不同声明不能互换，独立 Isolate 的值也不能因为使用相同 Tag 而互传。

创建或转换涉及脚本名义类型的值时，显式使用从实例/会话解析得到的 `Type<T>`。它绑定完整的
本地类型契约及必要的元数据所有者，不只是一个全局 Tag。纯内建类型可以直接在 Isolate 中
解析；含名义类型的数组、集合与函数签名沿用同一绑定。多个程序存在于同一 Isolate 时，
不能仅凭 `HandleScope` 和名字猜选其中一个声明。宿主导入的 codec 在实例化时取得该绑定。

宿主类仍以 `NativeClassTraits<T>` 和规范宿主键建立关系。C++ 类型身份只校验宿主注册的一致性，
不能替代脚本名义身份。借用 `T&`、可空 `T*` 及唯一/共享所有权交付继续遵循
[C++ 类绑定设计](native_class_bindings.md)；`Local<Host<T>>` 负责持有包装对象。

### 4.3 规范类型描述

`NativeType` 从扁平的种类记录升级为对规范类型描述节点的引用。描述需要覆盖种类、可空性、
名义引用、数组元素、集合键值、函数参数与结果，以及 Future/Completer 载荷。描述采用图引用，
名义递归通过声明引用结束，不递归展开类的全部字段。

复用并扩充现有 `layout::Type`、数组/集合/签名描述和 `CallSignature` 所属的共享契约。
C++ traits 与脚本编译是两个生产者，输出遵循同一结构定义；绑定注册持有不可变描述，实例化
将其解析为现有 `TypeConstraint`、布局和签名。序列化映像与运行时指针图仍分别承担
持久产物和 Isolate 本地状态的职责，不额外维护一张仅供宿主重复验证的运行时类型镜像。

已解析的 Type、导入签名及公共成员描述必须保留所需元数据的所有者，并接入现有元数据追踪。
可重载元数据不能因为一次解析就升级为永久 Isolate 缓存；最后一个使用者退出后应可回收。
封闭程序的布局缓存随映像所有者保活；所有者退出后，由存活对象与类型根继续保留实际可达的
元数据，空的名义类型容器也保留其元素契约。纯内建类型的解析遵循同一回收规则。
开发会话中的类型绑定保留稳定名义身份，构造和成员操作按当前合法发布解析；只有显式版本
能力保留捕获目标。类型资源纳入关闭阻塞，不把借用布局指针暴露为可长期保存的公共句柄。

宿主签名相等、值可赋值和显式受查转换是三个不同操作。注册/实例化比较完整外部声明，值进入
槽位时应用现有可赋值关系，动态转换执行现有类型检查。数组及 Map/Set 保持不变性，函数值与
Future 使用语言既有兼容规则；C++ 模板转换不自行定义协变或逆变。

规范描述参与生成器清单、宿主类契约摘要、原生映像验证和 JIT 缓存键。缓存必须包含实际影响
调用的嵌套类型，不能只哈希最外层 `Array`、`Function` 或 `Future`。

## 5. 句柄、根与借用期限

### 5.1 Local 与 HandleScope

`HandleScope` 属于一个 Isolate，并在所属线程创建、使用和销毁。`Local<T>` 引用作用域拥有或
明确覆盖的稳定根槽；复制 Local 不产生新对象或持久根，作用域退出后全部副本失效。
Local 不公开从原始 `Value`、堆地址或整数构造的接口。

宿主导入适配器在参数解码前建立一次调用期限，在结果交接完成后结束。首次解码句柄或调用
`context.handles()` 时才创建该次调用的 `HandleScope`；只使用标量的调用不初始化或登记根槽。
现有 `NativeContext` 仍属于 `NativeExecution`，其 `handles()` 访问当前宿主调用作用域。
嵌套调用独立入栈，不能把执行级 Context 的寿命误当作每个 Local 的寿命。宿主主动调用脚本时
显式创建作用域：

```cpp
vela::HandleScope scope(isolate);
// 在 scope 中创建值、读取持久句柄或调用脚本。
```

根槽采用稳定地址的批量存储，复用 `RootRange` 的登记与扫描。普通参数优先借用已有且覆盖
整个调用的根，禁止每解码一个托管参数就分配一个独立持久句柄。新增槽位或扩容可能失败，
由创建句柄的操作返回 OutOfMemory；作用域构造和析构本身不要求可失败的堆分配。

作用域的外部存储块与持久根存储纳入所属堆的原生存储记账，并在失败、退出和最后引用释放时
配对回收。预算检查可能推进 GC，因此建立这些存储之前也必须保根其来源值；临时 ABI
缓冲区继续使用现有 `NativeBuffer` 契约。

内部临时作用域的值必须先复制到目标外层作用域的根槽，再退出临时作用域。公共创建、读取和
调用接口接收目标 `HandleScope&`，结果直接交付到该作用域，避免隐式猜测返回值归属。
普通 C++ 辅助函数可使用调用方传入的作用域返回 Local，不得返回自己已经结束的作用域中的值。

C++ 类型系统不能静态证明所有作用域借用。过期 Local 的使用属于宿主编程错误，可在开发
构建中检查作用域有效性；不通过永久保根掩盖错误，也不承诺任意悬空 C++ 地址可安全恢复。

### 5.2 Persistent

`Local<T>::Persist()` 返回 `Result<Persistent<T>>`。成功时持久句柄持有稳定强根，原作用域
退出不影响该值。复制 Persistent 共享一个不可变根槽；移动转移句柄，最后一个所有者释放时
注销根。根槽里的引用不变，对象内容仍按脚本可变性规则更新。

`Persistent<T>::ToLocal(scope)` 在指定作用域中建立局部引用，并检查 Isolate 一致性。
该局部引用不依赖 Persistent 随后是否被重置。重置或移走后的空 Persistent 不能编码成脚本值；
脚本 null 始终通过明确的可空类型表达。

Persistent 是宿主存储类型，不成为 `NativeFunction::Bind` 的参数或结果类型。绑定中的持有
转换必须由宿主显式执行，避免调用签名暗中创建长期 GC 根。公共代码不再分别使用
旧 `RootedValue` 与 AOT `Handle<Tag>`；两者的稳定根存储已经收口为 `HostRoot`。

### 5.3 分配与交接顺序

每个跨边界返回都必须满足以下顺序：

1. 保根接收者、实参和仍需使用的托管中间值。
2. 在对象仍有根时准备目标槽位；必要的扩容或分配失败在此返回。
3. 将成功结果或异常载荷写入目标已登记槽位。
4. 交付结果后才释放来源临时根。

读取字段或元素时，可以先准备目标槽位再读取；若先得到裸值，必须使用内部临时根覆盖后续
槽位分配。移除元素尤其不能先断开容器引用，再为返回值申请根。

宿主返回托管值给脚本时，适配器保持调用作用域直到写入 ABI 输出；输出到脚本根槽的交接
区间不得触发 GC。C++ 主动调用脚本时，成功值和异常载荷必须在执行对象释放异常根之前完成
交接。所有分配与根操作计入现有 GC 效果分析，优化后的代码也必须保留该顺序。

### 5.4 归属、关闭和引用环

Isolate 必须晚于所属作用域、持久句柄、错误载荷和执行资源销毁。外部根纳入现有
`ReloadBlockers()` / `TryStop()` 契约，同一实际资源不重复计数。Hot Reload 可以保留句柄，
重建 Isolate 的 Reload 要求先释放外部引用，句柄不能转移到新运行中。

Persistent 保活脚本对象，不自动延长 Isolate 的寿命。持有根的 C++ 类也不因此变成可追踪
的 GC 对象。`Host` 包装仍是 GC 叶节点：若宿主对象保存回调，回调又捕获该包装，就可能形成
经外部根闭合的引用环。宿主须以显式关闭/解除订阅释放回调，不能依赖被该环阻止的析构函数
首次解除根。此设计不加入隐藏永久根或任意 C++ 对象图扫描。

## 6. 宿主绑定与 codec

`NativeFunction::Bind` 从完整 C++ 签名推导逻辑类型、上下文需求、参数解码是否可能失败，以及
结果的交接方式。`Local<T>` 和合法 `std::optional` 组合映射为对应脚本类型；原始托管指针、
Persistent、未知 STL 类型及未具体化的类型在生成或 C++ 编译期明确拒绝。

codec 分为描述、解码和编码三项职责。需要 Isolate、作用域或本地类型解析的解码接收上下文，
不能继续仅靠 `Decode(Value)` 构造一个无法判断归属的句柄。用户函数可以省略 `NativeContext&`，
但其 codec 需要上下文时，适配器仍必须取得上下文并建立作用域。

调用约定按整条适配路径的可失败性选择。只有参数转换、返回转换及调用本身满足直接调用契约，
才能使用直接入口；不能仅因结果是标量就让可能失败的托管参数解码进入无错误通道的入口。
精确标量签名继续使用原 C++ 函数指针，所有受查入口复用现有显式状态与输出约定。

实例化验证完整外部签名后才发布导入。参数类型、可空性、嵌套类型、返回类型以及类绑定的参数
名称都参与检查。可信调用内部利用这些保证，动态值进入、跨 Isolate 传递、宿主返回值和实际
可变存储写入仍在各自真实边界验证，不在每个 helper 中重复检查整个类型图。

宿主类模块的发布保持原子性；未使用成员也要满足完整契约。字符串便捷转换、`T&` 方法接收者
及唯一/共享宿主所有权都接入同一适配链，不另开一条只支持手写绑定的句柄调用路径。

## 7. 值操作与对象访问

### 7.1 字符串、数组和集合

String 的创建检查 UTF-8；读取文本可显式选择借用视图或复制。借用的字节视图不能晚于其所有者
根及 Isolate，不能把局部字符串视图保存在脱离根的宿主字段中。字符串长度与索引单位遵循
[字符串契约](strings.md)，UTF-8 字节数使用明确命名的接口。

Array 至少提供创建、长度、受查读取/写入、追加、移除和容量操作，Map/Set 提供既有集合操作。
均复用现有堆、数组与集合实现，保留以下可观察语义：

- 数组、Map 和 Set 的元素类型不变；空容器也必须有完整元素类型。
- 引用传递保留身份，浅复制与共享底层存储只在对应操作明确规定时发生。
- `Get` 等返回的托管元素在目标作用域中保根；写入经过既有类型检查和 GC 写屏障。
- 索引、容量、可空结果、Map 缺失键与 null 值、键相等性及插入顺序遵循现有语言规则。
- 分配失败和容器操作的失败原子性沿用既有操作契约，不为宿主接口另设弱化行为。

不把可增长数组公开为可长期保存的 `std::span`。批量借用如被提供，必须绑定被保根的所有者，
并限制在不会扩容、结构修改、重入或提交迁移的借用区间。字节视图沿用 ByteArray/ByteData 的
所有者关系；不把固定字节存储与 `int[]` 混用。回调算法复用现有结构修改检测。

### 7.2 脚本类、接口、枚举与公开成员

`Object<Tag>` 的创建通过公开构造入口执行默认值、初始化和构造函数，不允许宿主拼装未初始化
的字段块。接口句柄由受查转换获得，只暴露接口契约。枚举保留名义类型，不从任意整数伪造值。

生成的 C++ 成员包装携带声明身份及预期类型，调用现有成员解析与执行机制。字段 Get/Set、
getter/setter、普通方法调用和提取绑定方法分别保持语言语义。私有成员不可通过公共宿主 API
访问，只读属性写入明确失败。普通方法调用使用当前合法分派，提取出的函数值保留捕获目标。

动态访问从 `Local<Value>` 的实际运行时类型出发，执行受查的成员访问或类型转换。
[`MemberTable::ReadPublicField`](../../runtime/isolate/member_table.h) 仅用于诊断读取，
不会执行 getter；它不能直接充当新的普通属性访问接口。属性执行应复用生产成员调用路径。

成员描述和类型标记属于对应程序/会话的公开契约。成员解析不能依赖已销毁的原始 C++
`NativeInstance` 对象：所需程序状态通过对象已有的托管所有者或显式的类型/入口资源保活。
代码生成需保留宿主导出成员所需的元数据和目标，即使源码内部没有调用它们。

对象句柄保留稳定对象身份，不缓存永久有效的字段偏移或存储地址。可重载字段解析复用已有
声明身份、布局版本和缓存失效规则。所有成员访问遵循
[对象布局与状态演化](hot_reload.md#6-对象布局与状态演化)。

## 8. 函数、入口与重入

`Local<Function<R(Args...)>>::Call(scope, args...)` 返回 `Result` 包装的对应 C++ 边界值。
参数和结果若为引用，使用类型化句柄；`void` 返回 `Result<void>`。获取函数句柄时验证完整
函数类型，调用时处理实际边界仍需检查的值、执行状态和错误。

函数值具有固定的位置参数签名，沿用[函数值规则](core_language.md)。可选参数和内建可变参数
方法的适配由既有函数值构造规则完成，不凭空把 `Function<R(Args...)>` 扩展为命名实参或
C++ 可变参数协议。命名导出包装按实际声明生成其参数契约。

| 宿主能力 | 目标来源 | Hot Reload 行为 |
| --- | --- | --- |
| 类型化命名入口 `Entry<Signature>` | 公开模块和声明 | 每次调用选择当前发布版本 |
| `Local/Persistent<Function<Signature>>` | 脚本函数值、闭包或绑定方法 | 执行捕获的具体版本 |
| 显式捕获命名入口 | 对现有入口执行 Capture | 转为具有明确版本保活关系的类型化函数能力 |

命名入口包装现有 `NativeNamedEntry`，版本捕获复用 `NativeVersionEntry` 与函数值的现有
版本保活机制。封闭 JIT/AOT 没有后续发布，命名入口绑定其固定实例。查询命名入口只允许公开
导出；脚本主动交付给宿主的函数值按已有可调用能力执行，不借此开放任意内部声明的名称查找。

闭包、绑定接收者和程序环境通过现有托管边保活。宿主调用保留的回调时，从该回调保活的程序
状态通过 `NativeInstance::Borrow` 建立执行期间借用，接入 `NativeExecution` 和现有调用链。
函数句柄不得只保存裸函数地址或借用一个可能已销毁的 C++ `NativeInstance*`。

独立宿主调用以函数值所属执行域创建执行；在已有脚本执行中传入或调用其他函数值时，继续
检查 Isolate、代码身份或可重载分派域，不能把“同一 Isolate”当作跨程序任意混用的充分条件。
绑定方法必须保活包装接收者，不能只提取原生 `T*`。

脚本进入宿主后再次调用脚本，使用独立执行状态，保留外层根、逻辑调用轨迹和调用深度限制。
回调异常、停止和异步结果均按现有执行契约返回。宿主不应通过自动等待 Future 隐式推进整个
事件循环。命名入口缓存遵循发布版本校验，不能在热重载后继续使用过期解析结果。

## 9. Future、完成端点与线程

`Future<T>`、`Completer<T>` 的 T 是完整契约。已有调度器、Future 状态及 adoption 机制继续
负责执行；新类型化接口不复制异步状态机。创建、接收、返回、观察和等待都必须保持 T，
包括尚未完成时取得的 Future 以及嵌套 Future 的既有语言语义。

Future 完成载荷在发布给消费者前验证并建立正确的托管引用。失败沿现有异步诊断路径传播；
不通过包装成无类型 Future 绕过检查。等待或读取成功结果时，托管载荷写入调用方作用域。
观察者的取消、完成和关闭必须释放其捕获的宿主资源；受 GC 对象图追踪的内部任务不能保存
外部 Persistent 并形成自身保活环。

普通 Local、Persistent 和脚本值操作只能在 Isolate 所属线程执行。跨线程完成沿用
`FutureCompletionEndpoint` 的关闭与投递协议；类型化端点覆盖其完成类型。跨线程输入是
普通可传输数据时，在所属线程构造托管值；若使用既有允许的堆值投递路径，仍由其明确的
保根和接收契约覆盖整个投递期，不能把 Local 本身交给其他线程。

取消令牌的已有跨线程能力单独遵循其原契约，不推导为任意托管句柄可跨线程访问。关闭后完成
端点可以按现有机制存活并报告 Closed，但不再保活 Isolate。普通 Persistent 不具有该例外。

## 10. 结果与错误

公开 C++ 可失败操作使用 `Result<T> = std::expected<T, Error>`。无失败路径的标量读取和
句柄复制不额外包装 Result。Error 统一表达执行状态、拥有的诊断文本/已解析栈帧，以及可选的
已保根脚本异常载荷。内部 `ExecutionStatus` 和执行异常封套继续作为运行时控制通道。

| 失败位置 | 处理契约 |
| --- | --- |
| 不支持的 C++ 类型或不合法句柄签名 | bindgen 诊断或 C++ 编译期诊断 |
| 外部声明与宿主完整签名不匹配 | 实例化失败，禁止发布部分导入 |
| 跨 Isolate、动态转换或实际值类型错误 | 返回明确状态，执行前拒绝不合法输入 |
| 索引、容量或成员访问错误 | 使用对应既有运行时错误语义 |
| 脚本抛出异常 | 保留异常载荷与诊断，宿主可处理或原样传播 |
| 宿主业务失败 | 构造明确宿主错误，经共同边界进入现有脚本错误机制 |
| 执行停止 | 保持 ExecutionStopped，不能转换成普通可捕获异常 |
| 句柄、对象或结果保根分配失败 | OutOfMemory；报告该状态不再要求新的分配 |

宿主原样返回脚本调用的 Error 时，必须恢复原异常及其诊断，不能把它统一重写成 NativeFailure
或重新包装成丢失身份的字符串错误。错误对象保留托管载荷时也是外部根，释放和关闭规则与
Persistent 相同；只保留已复制文本和栈帧的诊断不依赖旧代码存活。

分配耗尽时允许没有异常对象或附加诊断文本，以现有状态码完整表示失败。调用已经发生的宿主
副作用和脚本副作用不承诺回滚；只有具体值操作自身规定的失败原子性需要保持。

宿主绑定和 AOT 包装共同使用 `vela::Error`，旧 `NativeError` 与独立 AOT 错误包装已删除。内部 helper 可保留
其实际所需的窄状态返回，但不得维护第二套面向宿主、语义不一致的异常表示。

## 11. 生成、AOT 与发行包

### 11.1 宿主声明生成

bindgen 从 Clang AST 识别受支持的公共模板与逻辑类型，生成规范描述和 Vela 声明。
类型别名先按真实 C++ 类型解析；不能依靠模板打印文本的字符串拆分识别嵌套类型。
`Local<Function<...>>` 等类型在手写绑定和生成绑定中具有同一契约。

生成器同时更新模型、清单序列化、公开契约摘要、依赖追踪、源码定位和双端输出。
某个公开参数无法表达时，报告具体成员及嵌套类型路径，不替换为 dynamic 或 `AnyTag`。
宿主类方法可以显式保存脚本回调，但生成器不自动扫描其 C++ 字段或生成闭包所有权策略。

### 11.2 脚本声明生成

脚本侧的公开类/接口/枚举标记、成员包装和类型化入口，从生产受查模块图生成。
复用现有原生导出流程的输入及类型事实，使 JIT 宿主也能取得同样的公共头文件；运行这些
头文件只依赖运行时，不能要求发行包用户携带编译器。

公开签名依赖的具体泛型应用必须包含在生成与编译依赖中。私有成员不输出；公开接口中无法
合法命名或导出的类型应在生成边界诊断。类型契约清单由同一生产者输出，不要求用户手写
另一份 class schema 或声明身份表。自动生成不执行模块初始化器或构造函数。

### 11.3 AOT 公共边界

AOT C 接口使用不透明作用域、局部引用与拥有根的持久句柄，底层存储复用共同根机制。
局部引用与持久句柄使用不同的 C 类型：局部引用随作用域释放，持久句柄显式释放。C 端的
作用域创建若需要分配，通过可失败工厂返回；C++ HandleScope 可以使用自身有界根记录。
任何 C ABI 成功结果与错误载荷都必须在返回前完成保根。

AOT C++ 包装生成精确类型。例如数组结果为 `Local<Array<T>>`，回调为具体 Function，用户类
为对应 `Object<Tag>`；需要调用方作用域的包装必须显式接收 scope。C ABI 提供指定目标作用域
的调用与读取接口，C++ 包装直接使用该路径，避免每个局部结果先分配一个持久句柄。显式
持久化、局部化和释放复用第 5 节的交接规则，失败时保持完整 RAII 清理。

所有静态已知类型都保留其完整契约，通用 Value 只用于实际 dynamic 等通用边界。删除旧导出
生成中将无法专门表达的类型统一变为 `Handle<AnyTag>` 的路径，不通过通用句柄维持两套 API。

原生映像、内部 ABI 或公共 ABI 的布局/调用约定发生变化时，更新对应版本、指纹和产物缓存，
要求重新生成并编译受影响产物。不得通过运行时猜测旧产物或自动降级维持可调用性。

公共头文件、必要运行时符号和生成元数据纳入 GN 目标及发行清单。发行包验收在独立 AOT C/C++
宿主中仅使用包内头文件、运行时库和生成物。JIT 宿主按现有源码构建方式链接编译器，并使用
同一公共值 API；本设计不新增 JIT 编译器库的发行模式。

## 13. 实施顺序与阶段完成条件

以下阶段存在依赖关系，全部完成才构成本设计交付。每阶段结束清理已被替代的路径，不以新增
头文件、首个绑定可运行或局部单测通过作为整体完成条件。

| 阶段 | 实现面 | 阶段完成条件 |
| --- | --- | --- |
| I1：完整类型契约 | 共享描述、宿主 traits、实例化解析、规范摘要、IR/映像与缓存 | 嵌套数组/集合、函数、Future、可空及名义类型的正确和错误签名均贯穿到实例化；无新增扁平匹配旁路 |
| I2：句柄与错误交接 | Local、作用域、Persistent、共同根存储、Error 和关闭资源 | 分配失败、作用域退出、跨作用域返回、错误载荷保根和跨 Isolate 拒绝均有真实调用验证 |
| I3：值与绑定 | 字符串、容器、对象/接口/枚举、字节与正则等内建类型，codec 与 bindgen | 本阶段各类型的创建或取得、读写、双向参数/结果及失败路径接通；脚本观察到相同身份和语义 |
| I4：函数与异步 | Function、Entry、回调重入、Future/Completer、完成端点 | 原调用退出并 GC 后可安全使用回调；载荷检查、异常传播、线程投递和关闭均完成 |
| I5：生成与多模式运行 | 脚本公共头文件、AOT C/C++、JIT、开发会话、REPL、发行包 | 同一宿主 API 覆盖全部模式；捕获版本与命名入口行为正确，独立 AOT 宿主无需编译器库依赖 |
| I6：统一迁移与验收 | 旧调用者清理、文档、回归、静态检查和 Release 基准 | 无冲突旧接口或通用类型回退；第 14 节场景全部验证，性能证据可复现 |

I3/I4 新增类型在进入阶段验收前，必须接通其生产者、注册、类型验证、适配入口和消费端；
I5 完成所有模式的统一覆盖。中间提交可保持明确的不支持诊断，不能以动态值或旧接口代替
未完成的静态契约并宣称阶段完成。

## 14. 验证与性能要求

### 14.1 行为验收

| 主题 | 必须覆盖的场景 |
| --- | --- |
| 类型 | 嵌套可空、空容器、同名不同声明、不同泛型实参、错误函数签名、错误 Future 载荷、动态受查转换 |
| 身份与可变性 | 同一数组往返、脚本/宿主双向修改、对象作为 Map/Set 键、宿主包装复用 |
| 局部根 | 强制 GC、作用域扩容、读取子对象、移除元素后返回、宿主返回后立即分配、嵌套作用域交接 |
| 持久根 | 原调用退出后存活，复制/移动/重置，最后引用释放后可回收，外部根计数配对 |
| 调用 | 捕获变量、绑定接收者、实例句柄销毁后仍存活的回调、跨执行域拒绝、重入及深度限制 |
| 错误 | 脚本异常原样传播，异常载荷跨 GC，宿主失败、停止、OutOfMemory，错误处理期间再次调用 |
| 对象 | 公开构造和初始化、private/只读拒绝、getter/setter 副作用、接口分派、枚举身份 |
| 异步 | pending/已完成 Future、成功/失败/adoption、观察者清理、跨线程完成与关闭竞态 |
| 热重载 | 当前命名入口、捕获旧版本、旧字段依赖、对象存储迁移、元数据和代码退休、Reload 外部阻塞 |
| 工具与分发 | 手写/生成绑定等价、完整摘要与缓存失效、独立 AOT C/C++ 宿主、公共头文件无编译器依赖 |

至少建立一条端到端场景：脚本把数组、对象和闭包交给宿主，宿主显式保留；原调用与初始实例
句柄结束后触发 GC，再修改对象并调用闭包；验证捕获、返回值及异常；最后释放句柄并验证根、
对象、元数据与代码资源能够退休。可重载版本另行覆盖当前入口与捕获版本的区别。

另一条端到端场景覆盖异步：宿主保存类型化完成能力，原调用退出后完成 Future，脚本读取
托管载荷；错误载荷、重复完成、关闭与投递中的资源都走真实生产链。测试应断言可观察行为
与生命周期，不镜像内部 helper 的实现。

验证遵循[开发流程](../../.agents/development_workflow.md)。实现中只运行能发现当前具体错误
的定向验证，完成边界运行相关完整回归、仓库静态检查和必要 Release 基准。纯文档交付只检查
内容、源码依据、链接、UTF-8/LF 和 diff，不运行无关构建。

### 14.2 性能与资源证据

句柄类型不改变现有标量直接调用和紧凑数组存储目标。局部参数传递不应按参数数量创建持久根
或独立堆分配；已建立的类型与签名事实不应在每次元素读取时重新遍历完整类型图。只有实际
动态边界和可变存储写入执行所需检查。

Release 基准分别测量：精确标量绑定、局部引用参数、字符串借用与复制、标量/引用数组访问、
回调调用与重入、持久根创建/释放、对象成员访问、Future 交付，以及 JIT/AOT 两端包装。
报告调用耗时、分配次数、外部根与句柄存储量，并区分冷类型解析和稳定调用成本。

比较对象是现有等价手写绑定或低层受查操作，工作量、优化配置和 GC 条件必须相同。出现额外
分配、重复保根或标量路径退化时，应定位并消除原因，不能以类型包装本身作为解释。
不预设未经测量的“零成本”或性能比例。测量方法、构建信息与结果按
[基准结果保留规则](../../.agents/benchmark_results.md)保存。

### 14.3 验收结果

macOS arm64 的验收覆盖 JIT、AOT、开发会话、REPL、手写与生成绑定，以及独立 C/C++ 宿主。
C++ 回归共 2502 项；工具链验收包括 476 个 AOT/JIT 语料对照，以及仅依赖发行包、删除源码后
继续执行的宿主场景。主要验证入口如下：

| 验收面 | 回归入口 |
| --- | --- |
| 局部根、持久根、重入和异常载荷 | [作用域](../../runtime/heap/handle_scope_unittest.cc)、[类型与调用](../../compiler/language/host_types_unittest.cc) |
| 对象、闭包及实例退出后的元数据和代码寿命 | [宿主对象](../../compiler/language/host_object_unittest.cc)、[可重载类型与入口](../../compiler/jit/host_type_unittest.cc) |
| Future 载荷、观察者及跨线程完成 | [运行时异步](../../runtime/native/host_async_unittest.cc)、[语言异步](../../compiler/language/host_async_unittest.cc) |
| 公共内建值、脚本头文件与双向生成 | [公共 API](../../include/vela/host_unittest.cc)、[头文件生成](../../compiler/native/host_header_unittest.cc)、[绑定工具](../../tools/bindgen_unittest.py) |
| AOT C/C++ 与独立发行包 | [原生宿主](../../tools/aot_unittest.py)、[发行包](../../tools/aot_distribution_unittest.py) |

Release 性能证据保存在[滚动摘要](../../benchmarks/results/rolling_summary.json)。本轮在 Apple
M1 Pro 上完成 37 项互操作、32 项标量调用和 40 项原生类绑定基准；每项重复 7 次，最短测量
0.2 秒，随机交错，共 763 个样本。摘要记录确切命令、工具链、源码状态、测量边界、中位数和
变异系数。15 项的变异系数超过 20%，小幅差异不足以据此判断提升或退化。

按每批 4096 次调用折算，带 `NativeContext` 的空调用、整数和浮点调用中位数从
13.4–13.8 ns/次降至 3.6–4.6 ns/次；字符串借用从 21.3 ns/次降至 12.9 ns/次。
标量、局部引用传递、对象访问、数组读取和字符串借用没有新增 Vela 记账分配。持久化每次
分配 1 次，Future 交付分配 2 次；重入场景每次创建函数值，分配 1 次、64 字节。全部互操作
场景在完整清理后恢复基线根数、关闭阻塞数与堆用量；这不等同于调用期间没有分配。

保留量检查复用 `CollectHeapBaseline` / `ReportHeap`：先结束已有增量周期，再按当前根启动
完整回收。旧基线仅调用 `Collect()`，因此摘要不直接比较两轮的互操作保留量计数；调用计时和
计时区间内的分配统计继续按相同工作量比较。外部根与关闭阻塞数在计时区间外采样，不代表调用
中的峰值。`scope_storage_bytes` 为 `sizeof(HandleScope)`，本机为 336 字节，不是测得的栈峰值。
分配计数覆盖 Vela Heap 及其记账的原生存储，不覆盖 `std::string`、元数据 STL 容器等进程
malloc 分配；本轮也未固定 macOS 线程亲和性。
