# 持久化 REPL

[English](../en/repl.md) | [**简体中文**](repl.md)


Vela 通过 `vela repl` 命令提供交互式命令行环境（REPL）。交互式会话维持一个活跃的
Isolate 实例与经过校验的程序状态；函数声明、全局变量值、闭包、类实例以及模块导入在多轮
提交之间持久保留，且绝不通过重复回放旧代码产生额外的副作用。

```text
> let value = 40;
> func add(value: int): int {
...   return value + 2;
... }
> add(value)
42
> value = value + 1;
> value
41
```

## 交互语义

- **严格静态类型**：REPL 遵循与已编译源码完全一致的严格静态类型、声明语法与重复声明报错规则。
- **增量提交执行**：每轮提交独立解析声明或语句/表达式。仅当前提交的新语句和表达式会被执行；先前已接纳的代码绝不重新执行。
- **表达式回显**：不以分号结尾的顶层表达式在执行后求值并打印一次非 void 结果；以分号结尾则抑制回显（遵循 Julia 交互式设计惯例）。void 表达式从不打印。
- **多行代码块输入**：未闭合的花括号、圆括号或方括号会提示继续输入续行（`... `）。遇到意外 EOF 且存在未闭合结构时输出语法诊断。
- **控制台内置命令**：`.help` 列出帮助命令，`.source` 打印已接收的输入历史，`.reset` 清空会话与 Isolate 状态，`.quit` 退出会话。内置命令属于控制台功能，不是语言关键字。
- **错误处理边界**：编译错误直接丢弃当前提交，不修改会话状态，也不分配持久 ID。运行时错误保留已通过的声明与已产生的副作用；进行中的惰性全局初始化器重置为未初始化状态，允许用户再次尝试。
- **源码溯源**：编译器诊断与运行时调用栈帧统一将交互提交标识为 `<repl:N>`，其行号相对于该轮提交的起始行。

## 稳定标识与运行时连续性

嵌入会话在首次接纳提交后固定原生 binding 注册集合。`ReplSession::Reset()` 返回结果：宿主外部根、Program、Future 或活动执行仍未释放时，返回资源诊断并保留当前会话。成功时关闭旧调度器与完成端点、释放旧脚本存储，再用同一份 binding 快照创建新 Isolate。控制台会报告被拒绝的 `.reset`，不会销毁仍被借用的 Isolate。

仅重新编译历史源码并拷贝裸全局变量是错误的：已有闭包实例保存了函数 ID 与选择器 ID，堆上的现有对象也持有类布局指针。会话通过以下机制保证跨提交的结构连续性：

1. **前端模块缓存**：成功导入的模块源码快照、规范化路径解析结果以及模块前缀在 `.reset` 之前持续保持固定。编辑被导入文件在重启或重置会话后生效。
2. **会话级持久 ID**：编译器为函数、全局变量槽位、接口及选择器分配独立于 AST 遍历顺序的持久 ID。函数体按其固定槽位写入，而非假定按顺序紧凑排列。
3. **Lambda 稳定标识**：匿名函数在泛型特化后，基于词法所有者与源码坐标获得稳定 ID。Lambda 目标使用显式索引映射，而非简单依赖连续布局。
4. **内存布局复用**：运行时类、数组与集合布局基于稳定的类型身份在会话内直接复用。新引入的接口方法在布局暴露前具体化选择器，确保先前创建的实例能顺利分派后续声明的接口方法。
5. **事务化提交流程**：编译器状态在工作副本中暂存，仅在字节码编码与程序校验完全成功后才原子提交。在虚拟机中，新全局槽位在释放旧存储之前先行分配并牢固保根；若编译或加载失败，新创建的元数据在逃逸至堆前完整回滚。

## 合成入口与源码来源

- **包装函数**：语句与表达式提交会被包装进一个合成函数（synthetic wrapper）。预处理后的 AST 加载流程将该根节点与已导入模块联合绑定；自动生成的标识符统一采用内部 `$` 前缀，杜绝与用户标识符冲突。
- **入口槽位复用**：旧的合成入口在执行完成后被标记淘汰，不再参与后续父体 Lowering，而其内部嵌套的 lambda 仍保留稳定的已编译 ID。所有非声明性提交复用预留的单一入口函数槽位，避免函数槽位无限制膨胀。
- **回显机制 Lowering**：无分号表达式在 Lowering 阶段被降级为：单次求值、使用标准运行时规则打印输出，并安全释放临时寄存器。

## 验证与正确性契约

REPL 的实现必须满足以下验证契约：
- 变量值、实例变更及初始化副作用在多轮提交间持久保留，且不产生任何历史输出回放。
- 闭包目标与可变捕获单元在新加入函数、全局变量及多次垃圾回收后依然可靠存活。
- 堆上的现有实例在跨轮提交后，完整保留其类身份、类型转换能力、接口一致性及集合成员资格。
- 编译错误能原子回滚暂存的元数据，而运行时错误能够保留先前的有效状态并允许重试失败操作。
