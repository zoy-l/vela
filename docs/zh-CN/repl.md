# 持久化 JIT REPL

[English](../en/repl.md) | [**简体中文**](repl.md)

`vela repl` 通过 `DevelopmentSession` 与 `DevelopmentRepl`，在一个活跃 Isolate 中
编译并执行原生交互提交。声明、全局变量、闭包、对象和导入跨提交保留，不回放已经执行的语句。

```text
> let value = 40;
> func add(value: int): int { return value + 2; }
> add(value)
42
> value = value + 1;
> value
41
```

## 交互行为

每次提交包含声明或语句/表达式，遵循普通静态类型与重复声明规则，只执行新增语句。
没有尾部分号的表达式打印一次非 void 结果；分号抑制打印。
未闭合分隔符触发续行提示，输入尚未完成时遇到 EOF 返回源码错误。

`.help` 列出命令，`.source` 打印已接纳源码，`.reset` 重建脚本状态，`.quit` 退出。
这些是控制台命令，不是语言关键字。编译错误拒绝候选；
发布成功后发生运行时错误，会保留已接纳声明和先前副作用，失败的惰性初始化可以重试。
交互源码诊断映射到 `<repl:N>`。

## 发布与身份

前端生成不可变源码候选，并维持稳定声明与特化身份。
共享原生后端编译候选函数，开发会话准备运行时状态，再在既有安全边界发布更新。
编译或准备失败时，当前运行版本保持不变。

已有闭包与对象保留其需要的代码和元数据。全局槽位及类型身份在成功提交间保持稳定。
合成语句入口从后续源码 lowering 中退休，捕获的嵌套函数继续保持可达；
重复提交不含定义的语句不会让持久函数表无限增长。

导入源码属于已接纳快照。独立控制台不监视文件；重置后重新导入使用新的交互会话。
嵌入开发会话的源码所有者通过显式 Load、Hot Reload 或 Reload 提供文件变更。
提交交互代码不会隐式接纳磁盘编辑。

## 重置与所有权

在加载宿主 `DevelopmentSession` 后构造 `DevelopmentRepl(session, path)`。
REPL 借用该会话，宿主绑定由会话的绑定快照固定。

`DevelopmentRepl::Reset(SourceUpdate)` 删除交互模块，并使用会话的 Reload 事务。
源码所有者提供更新；嵌入调用方可同时提交已刷新的项目文件。
外部根、原生实例/入口/候选、Future 或活动宿主访问可能阻止替换；
重置被拒绝时报告资源并保留原会话。

重置成功后关闭旧完成端点、退休旧脚本状态，并用绑定快照创建新 Isolate。
宿主销毁会话前必须释放自己的借用。排队工作、保留回调和旧代码遵循
[热重载生命周期契约](hot_reload.md)。

测试覆盖持久全局变量、可变捕获、泛型方法和接口、导入快照、错误、重置阻塞、GC 与代码退休。
