# Vela 字符串系统

[English](../en/strings.md) | [**简体中文**](strings.md)

## 编码与类型

`string` 是不可变且合法的 UTF-8 字节序列。源文件、运行时存储及控制台输出统一采用 UTF-8 编码。字符串中允许包含内嵌的 NUL 字节（`\0`），且不会因此截断字符串。字符串的长度、索引、切片边界和检索结果均以 Unicode 标量值（码点，code point）为单位进行计算，而非字节数或字素簇。语言中不设立独立的 `char` 类型。

对于字符串 `"A中😀e\u0301"`，其 `length` 为 5，而 `byteLength` 为 11。末尾的 `e` 与组合重音符号各自作为独立码点计数。Vela 不进行 Unicode 规范化归一化处理；相等性比较精确比对编码后的实际字节序列。随机码点索引需要从头扫描，因此在循环中反复对长字符串按索引寻址将呈现二次方时间复杂度 O(n²)。建议调用 `codePoints()` 在线性时间 O(n) 内生成原生的 `int[]` 数组，随后便可以 O(1) 常数时间按索引访问该数组。字素簇 API（`graphemes()`、`graphemeLength`、`graphemeSlice(start, end)`）遵循扩展字素簇规范；详见 [P1 Unicode 契约](core_language.md#unicode-code-points-and-graphemes)。

## 字面量、转义与插值

单引号与双引号字面量具有完全相同的 `string` 类型与字符串插值规则。代码格式化工具默认使用单引号。两种风格均支持 `\"`、`\'`、`\\`、`\n`、`\r`、`\t`、`\b`、`\f`、`\v`、`\0` 和 `\$`。`\xHH` 将标量 U+00HH 编码为合法的 UTF-8 字节（不会注入可能非法的裸字节）。Unicode 转义支持 `\uXXXX` 或带花括号的一到六位十六进制数 `\u{H...}`。固定宽度的 UTF-16 高半区代用项转义后必须紧跟固定宽度的低半区代用项转义，二者共同编码为一个 Unicode 标量值。孤立的代用项、花括号中的代用项数值、超出 U+10FFFF 的值、缺失十六进制位、未知转义符、非法源文件 UTF-8 字节、字面量中的未转义原生换行以及未闭合的字符串/插值均会产生编译报错。

```typescript
const name = 'Vela';
const greeting = 'Hello, ${name}! Count: ${42}';
const literal = '\${this is literal text}';
const emoji = '\u{1F600}';
```

`${expression}` 允许插值 `string`、`int`、`double`、`bool`、`null` 以及这些基本类型的可空变体。Null 会被格式化为 `"null"`。支持嵌套字符串与多层插值。每个插值表达式按源码书写顺序精确求值一次，且其计算结果在下一个表达式求值前完成保存。当加号 `+` 的至少一个操作数是字符串类型（包括可空字符串）时，采用完全相同的自动格式化规则。例如，`'count=' + 42` 生成 `'count=42'`。`+` 保持左结合性：`1 + 2 + '3'` 计算为 `'33'`；`'1' + 2 + 3` 计算为 `'123'`。对象和数组必须显式转换或提供表示；系统不提供自动的对象占位符或用户方法调用。赋值、函数调用实参、数值算术运算、相等性比较及条件分支严格保留原有的静态类型约束。解码为 `$` 的 Unicode 转义符不会触发字符串插值。模块导入路径支持解析转义符，但禁止使用插值和 NUL 字节。文件类型检查与编译流程共享同一个依赖加载器，确保带转义的路径和 Unicode 文件名解析结果完全一致。导入模块在依赖拓扑中仅解析一次，重复引入的文件只加载一份，并严格遵循模块导出规则。

`int.toString()`、`double.toString()` 和 `bool.toString()` 显式分配字符串。整数输出为十进制；布尔值输出为 `'true'` 或 `'false'`。双精度浮点数使用与控制台输出完全一致的最短往返 `std::to_chars` 格式化器，准确表达带符号零、正负无穷大与各类 NaN。格式化完全独立于宿主流语言环境（locale）及数字格式化标志。

## API 方法规范

| 表达式 | 返回类型 | 规范契约 |
| --- | --- | --- |
| `text.length` | `int` | Unicode 码点数量，时间复杂度 O(byte length) |
| `text.byteLength` | `int` | 编码字节数量，时间复杂度 O(1) |
| `text[index]` | `string` | 单个码点；扫描到该索引并分配 1–4 字节内容的子字符串 |
| `text.slice(start: int, end: int)` | `string` | 左闭右开码点范围切片；扫描切片边界一次并复制结果 |
| `text.indexOf(text: string)` | `int` | 首次匹配的码点偏移位置，未找到返回 -1；空模式在位置 0 处命中 |
| `text.includes(text: string)` | `bool` | 是否包含子串；任何文本均包含空模式 |
| `text.startsWith(prefix: string)` | `bool` | 是否以指定前缀开头，空前缀始终返回 true |
| `text.endsWith(suffix: string)` | `bool` | 是否以指定后缀结尾，空后缀始终返回 true |
| `left + right` | `string` | 至少一个操作数为字符串；将基本类型/null 操作数一次性格式化并拼接为最终字符串 |
| `parts.join(separator?: string)` | `string` | 分隔符默认为逗号；null 元素贡献空文本；支持基本类型数组（含可空元素）；空数组生成空字符串 |
| `String()` | `String` | 创建一个由 GC 管理的空可变字符串构建器（builder） |
| `builder.append(text: string)` | `void` | 将文本追加复制到其内部缓冲区中，采用几何扩容策略 |
| `builder.toString()` | `string` | 创建一个独立的不可变字符串快照 |

大写的 `String` 是用于构建的可变类型；全小写的 `string` 是不可变的 UTF-8 基本值类型。调用 `toString()` 可创建不可变的快照。

上述方法中的参数均为必填项。传参支持位置实参或命名实参，且即使命名实参颠倒了参数顺序，表达式也始终严格按源码书写顺序求值。索引必须满足 `0 <= index < length`；切片范围必须满足 `0 <= start <= end <= length`。超出范围将返回虚拟机可恢复的 `IndexOutOfBounds` 状态。语言不支持负数索引、自动截断纠正或隐式数值转换。字符串的索引访问结果和 `length` 属性不可被赋值修改。`String` 是保留的内置类名。语言不设立全局的 `join` 函数；用户代码可以自由声明同名符号。数组操作数在分隔符之前完成求值，各自仅求值一次。数组元素类型必须同构：`[1, 2].join(',')` 合法；`[name, 42, true]` 非法。混合类型建议直接使用插值 `'${name} / ${42} / ${true}'`，无需创建临时数组。

`indexOf` 和 `includes` 对多字节模式采用 KMP 算法，保证在重复前缀输入下仍具有线性 O(n) 搜索时间。短模式跳转表使用栈内存；超过 64 字节的模式将分配临时原生前缀跳转表并在分配失败时显式报错。前缀与后缀检查直接比对字节序列；UTF-8 的自同步特性确保这些字节比对严格落在合法的 Unicode 码点边界上。

## 编译、内存分配与垃圾回收

词法分析器输出解码后的字面量分段与表达式标记。语法分析器构建字符串插值 AST 节点；类型检查器验证每个片段与表达式并记录内置函数绑定。Typed IR 保留插值专用操作及静态选定的内置函数 ID，并将其直接带入定长寄存器字节码中。程序创建与加载边界会对内置函数 ID 与寄存器范围统一做单次有效性校验。运行时调用会返回明确区分的类型、越界或内存分配错误。

插值运算将各个片段保存在连续且被保根的栈帧槽位中。它剔除空的字面量片段，预先计算最终所需的总字节数，单次完成最终字符串的堆分配，并将各个分段直接复制入内。基本类型的格式化使用原生临时暂存区，绝不分配任何中间垃圾回收字符串。`parts.join(separator)` 借用数组原生存储并走相同的分配路径，分隔符所需空间预先计入溢出检查。两种运算均不构造任何中间拼接字符串。插值表达式内部自身执行的内存分配（例如显式的 `toString()` 调用）与最终字符串的合并分配彼此独立。

构建器（builder）是非移动式垃圾收集器中的叶子对象。其底层的原生缓冲区采用几何扩容策略，因此连续的追加操作整体具有 O(total bytes) 的拷贝复杂度。缓冲区容量同时计入 `allocated_bytes` 与 `committed_bytes`，直接影响 GC 触发阈值，并在构建器被清除（sweep）或其所属 Isolate 销毁时得到释放。生成快照会拷贝其字节数据；快照生成后与后续的追加操作均不会阻止旧缓冲区的回收。位于类字段和强类型/嵌套数组中的构建器复用现有的引用屏障与对象图追踪机制。

由 GC 堆支持的每个分配输入必须始终保持被保根状态，直至该次分配完成。虚拟机确保接收者、实参、插值片段、数组元素以及分隔符均从已注册的栈帧中保持可达。目标寄存器在分配完成后才被写入，即使裸字节码中目标寄存器与输入寄存器存在别名冲突也能安全执行。宿主环境必须在下一次内存分配或垃圾回收前对 VM 返回的值进行保根。底层堆字符串/构建器接口接收合法的 UTF-8 序列；来自外部不受信任的原生输入必须先通过 `InvalidUtf8Offset` 进行校验。当前源文件词法分析器是外部文本进入系统的安全校验边界。

## 大小写转换与规划中的匹配 API

`text.toLowerCase(): string` 与 `text.toUpperCase(): string` 实现 Unicode 18.0.0 默认完整大小写转换，包括展开映射及 Final_Sigma，不依赖 locale，也不做规范化。详见[字符串大小写转换](string_case.md)。Dart 风格 RegExp 与 RegExpMatch 提供 PCRE2 Unicode 匹配，位置使用 Vela 码点索引。详见[正则表达式](regexp.md)。
